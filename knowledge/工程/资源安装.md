### 韩服新增宠物与移植边界

<a id="kb-04-004-2"></a>

<!-- BEGIN 04-004-2 -->

名称必须按**GBK编码后的字节数**校验，而不是Unicode字符数：PET field2容量16（含NUL，最多15字节）；描述field16/17/18容量64，路径／BOO名称字段容量260，均须预留NUL。旧990表中32个泰迪／熊猫名称恰为16字节，可使原客户端启动加载全表时进入CRT参数失败分支，故是否装备该宠物无关。该旧故障的36行名称修正仍保留为可识别迁移基线；当前以统一中文译名及等级政策目标表为准。安装器只允许精确旧869／旧990／旧超长名称表及已审核中间表、逐行before／after摘要与field1/2/16差异匹配的迁移，不放宽一般冲突拒绝。完整构建脚本在生成输出前按当前配方核对PET摘要，拒绝从旧候选数据目录回填错误表。字段容量和错误分支由[本主题对应章节](资源安装.md#kb-08-059-1)维护；GUI、托管及客户端分别维护验收状态。

`prepare_korean_pets.py`以精确来源与目标摘要预检，只追加526个缺失散文件（其中162个PON／1399行由108转106），保留486个共用资源身份（包含BOO pack）。246个同名PON解码模型相等但序列化不同，保留CN文件；6张熊猫城镇／战斗／图标贴图内容确有差异，保留CN版本，不以韩服变体影响旧宠物。输入依赖包括1011个散文件；BOO记录100149的offset14位于字符串边界，跨字符串匹配按无效引用处理。候选引用与BOO执行链分别维护。

### 等待房间开始游戏：嵌套弹药依赖

第七入口超级 Boss 的嵌套依赖包括 `flying/pon/mis_ep22_dg01_m_196_02.pon`。兼容派生器从同家族 `mis_ep22_dg01_m_196.pon` 生成逐字节别名；该别名沿用源文件的图形、轨迹与状态数据。

MMO200结构中，`ep22_dg01_m_196_01.mmo`和`_03.mmo`各含三个弹道条目；偏移0x14E/0x196/0x1DE的六个64字节名称使用02 PON别名。72字节事件记录保留时间／坐标字段。12位异或规则、记录结构及预加载／文件读取地址见[本主题对应章节](资源安装.md#kb-08-059-1)。

资源别名注册表为缺失的`mis_ep22_dg01_m_196_02.pon`提供与同家族`mis_ep22_dg01_m_196.pon`（21508字节）完全一致的副本。它是**同家族自定义兼容性回退**，不是原始02文件恢复，也不能证明外观、轨迹或统计值匹配。别名保留源PON主效果、13帧、数值字节及标识符，不改写既有PON/MMO、六次发射事件、伤害／HP逻辑、冬季Boss生命周期、客户端指令或村庄道路。加载前检查别名与源文件内容一致性。

资源依赖检查覆盖SSTG -> 九种SMMO替代列表及BMO容器 -> MMO200 -> PON105 -> EFF/image/collision/sound，共558个文件节点、5264条引用边，在此命名域内没有未解析文件。替代列表仅用于资源盘点，不累计目标选择器。MMO200/PON105按字段解析；EFF2图像字段以NUL结尾，其他字符串提取不等于结构化消费证明。过时字符串、错误尾事件偏移或遗漏BMO的扫描不能证明额外资源缺失。该检查不是完整原生解析／渲染或游戏验收；超级Boss可见战斗、最终结算及返回／重新进入仍未验证。

### 前六关 Lumineos 副本：相同缺陷审核

条目1至6有独立资源检查，不能将条目7的结论直接外推。它们的原生`hd0_ep16..21_dg00_st01.sstg`路径已经存在，并选择了预期的ep16至21/dg0/st1适配器表。每个条目都包含九个嵌入的SMMO替代方案，其安装字节与安装副本匹配。提取的直接资源名称计数分别为82/94/78/78/80/82，在此有限的审计中没有缺失的直接名称或映像名称。这些是文件/路径/依赖性检查，而不是所有传递性/原生加载器的验收。第七入口的特殊查找规则不改变这六个元组。

适配器构造检查在难度0覆盖六个超级Boss条目：普通Boss -> CF8B/CF8C -> 门控stage1 CFEB/CFEC -> 对应超级Boss模式 -> 最终CF88，并检查普通HP、箱子、拾取及重复／状态周期门控。六个条目的资源模式数为2/2/3/2/1/2，不能统一为两个模式；受测范围内未发现相同阶段名缺失或查找缺陷。按组件累计四舍五入命中次数会越过共享模式HP0；适配器会拒绝已结束模式的后续报告，因此这种测试计数不能替代实际模式边界。构造验证不是六次客户端通关验收。

### 安装与恢复合同

当前发布以统一源码构建并按文件事务交付源码、程序、worker、资源、启动器和三份合同。安装合同包含旧安装与资源身份校验、逐文件备份、摘要保护和提交确认；数据库、配置及既有状态独立备份并核验保持；客户端排序兼容项与多开副本采用二进制补丁文档中的统一安装合同。schema初始化保留已完成引导、排行榜及角色进度，客户端兼容状态按当前配方校验。

恢复按文件事务的逆序核对摘要；元数据同步事务先于主部署恢复。摘要保护保留后续文件修改，程序恢复保留更新后的角色进度；数据备份按独立本地合同管理。

运行包更新采用显式文件清单、全量预检、目标进程退出检查、逐文件备份及摘要保护。提交同时维护托管程序集、worker、配方、启动器和三份清单的一致性；资源及人物状态按独立数据合同管理。恢复按已登记事务的逆序核对文件身份，保留更新后产生的游戏进度。客户端二进制及经验曲线的配套恢复步骤见`knowledge/指南/客户端二进制补丁.md`。

## 资源事务

转换、安装和验证采用相互独立的阶段，目标资源由清单精确限定。

`manifest/lumineos_resource_port.json` 固定每个输入、原客户端基线及转换输出的大小/哈希。`compatible_recipe_sha256s`登记可兼容的既有配方身份，所有版本共同执行逐文件基线、目标摘要、操作类型与保留清单校验。未知来源、未知覆盖目标、转换结果偏离、缺少共享依赖都会拒绝。源版本不同不能通过临时修改清单或全目录覆盖绕过，应重新审计。

L7 两阶段及 stage1 兼容别名的 BGM 继续使用 `sounds/23_ssky_game_bgm.ogg`，L8 两阶段保持 `35_ssky_game_bgm.ogg`。L7 当前资源闭包包含 662 个节点、1605 条引用，相较于前一公开资源配方更新263项；其中 97个MMO、42个PON转换、3个SSTG身份修正及121项复制资源；PON与SSTG数量各包含一个兼容别名。

安装前先关闭目标副本的游戏进程；读取适配器目录的adapter进程无需退出。安装器先校验全部目标，再保存备份与事务收据，逐文件通过同目录临时文件原子替换。普通异常自动回滚；进程中断留下的 `applying` 收据会阻止后续安装，需先显式恢复。重复安装会重新核对所有资源，而不只是查看标记文件。

仅对`upgrade_from_manifest_ids`登记的精确旧标记允许原位升级；升级前核对旧包全部资源，新事务逐项备份待更新资源和旧标记。安装输入匹配当前配方登记的基线或升级标记。未知旧包、内容后续修改或未完成事务均拒绝。成功输出包含相对于客户端根目录的事务收据。

回滚先全量验证备份及现有文件，只删除该事务新建且仍匹配安装哈希的文件；其他文件恢复原字节。遇到后续编辑会拒绝，不强行覆盖。备份和收据保留，不递归删除目录。

## 娱乐室状态资源

娱乐室初始化读取客户端根目录的 `animalstate.st`，长度为868字节（217个32位单元）。支持的内容SHA-256为 `2351E3C39A13A51625548CFC92D0081C92DB55DFB4B3079BE1845D7A18B9F96E`。初始化在打开资源后读取完整状态区，并进入小游戏场景。

资源补全步骤：

1. 准备合法取得且包含完整状态资源的客户端目录。
2. 执行下列命令，将资源验证、安装记录和本地副本归入独立覆盖目录：

```powershell
python -B scripts/prepare_entertainment_resources.py `
  --source-root '<完整客户端目录>' `
  --client-root '<运行客户端目录>' `
  --output-root '<独立覆盖目录>' --apply
```

3. 安装器验证长度与内容身份，以独占创建方式补齐文件，随后复核目标内容；已有相同内容保持幂等，已有不同内容进入保护分支。
4. 社交槽位首次建立时复制根目录状态文件；复用槽位时补齐缺失的状态文件，并保持已有配置和独立资源。
5. 本地记录包含文件名、长度、SHA-256及安装状态。回退新增资源时，仅移除记录为`install`且当前哈希仍匹配的`animalstate.st`；原有资源按本机保留副本恢复。社交槽位使用相同的文件身份校验。

## 4. 兼容及验证范围

资源转换需要Python及PyCryptodome；安装、校验、事务回滚使用Python标准库。启动与游戏运行由自包含托管工具负责。精确目录、输入／目标摘要、冲突检测、幂等和回滚构成资源安装契约。

当前验证范围包括格式、字段模型、文件身份、目录构造、安装事务及适配器执行。客户端验收范围为L8两阶段与三难度的显示、声音、碰撞、Boss、结算、续关、返城与多人，以及新增宠物三阶显示和各类攻击。`runtime_accepted`／`runtime_acceptance`保留独立的客户端验收状态。

英雄龙及部分9153–9156 PON保留追踪尾引用`y_ef_smoke_02_t_b.eff`；该依赖列为待确认资源。L7/L8安装器支持持久事务回滚；宠物安装器支持普通异常恢复，完整副本备份承担中断恢复。角色进度采用独立数据库持久化。

客户端EXE补丁的完整应用与回滚步骤统一见[客户端兼容说明](../指南/完整适配器与客户端兼容说明.md)。
