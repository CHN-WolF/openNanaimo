## 库存编辑与持久化载体

本地入口以“用户名／角色显示名”文本框为账号选择依据：已有用户名优先匹配账号，角色显示名解析到其所属账号。新名字从当前管理档生成独立快照，并同步六个管理页的选择。首次本地注册在一个事务中创建账号、角色和库存；再次进入保留数据库中后续产生的进度。GUI 在选档／保存前重读账号列表；数据库草稿首次注册为角色后，在同一窗口内升级为实际 `CharacterId`，同步六个选择器但不丢弃当前编辑内容。保存后端也重新解析缺失 `CharacterId` 的账号／角色名（用户名优先、角色名大小写不敏感），已有数据库角色不会继续写到草稿记录或旧JSON／DAT；显式克隆仍保持独立数据库草稿，不隐式覆盖来源角色。目录外卡片按源档记录完整保留，普通编辑继续采用只读保护。普通本地注册、纯新手注册与远程注册各自维护导入边界。

社交账号按主机 `adapter_data/game.db` 中的用户名复用账户，再由 `AccountId/CharacterId` 定位角色及背包。P1／P2／P3 是客户端启动槽位，不是存档键；相同用户名重新注册会保留已有角色，游戏内持久化不依赖 GUI 启动按钮执行 `Save-Profile`。普通离线资料编辑选择具体角色后写该 `CharacterId`；没有正式角色的资料使用名称编码区分的数据库草稿。协议容量与GUI可编辑目录分别定义；完整字段见[桥接布局](../基础/桥接布局.md)，库存目录与保护规则见下节。

### 库存编辑与持久化载体

<a id="kb-03-040-5"></a>

<!-- BEGIN 03-040-5 -->

GUI 全量目录由 `scripts/generate_inventory_card_catalog.py` 从现行 `ddakg._D4`、`EDdakgi._D19`、`Sddakg._D35` 的确定记录构建，保留既有420条普通卡文案；生成与测试逐一要求 `card_drop_cn.csv` 的每个卡号均可发放。SP／活动／VIP与幸运卡不能再被当成目录外只读数据；“全部添加”和“移除已知卡”使用同一560条目录。资源中有定义而未配置掉落的卡仍可人工发放，但不据此新增掉落地点、概率或自动赠送；发放幸运卡不等于已实现其抽奖使用。

离线保存只授权修改 GUI 目录内的卡片，不把 `CharacterCards` 按角色整表清空。目录外条目显示“未收录卡片（只读保留）”，不能在 GUI 增减；数据库原数量及 `UpdatedAt` 等元数据原位保留，数据库草稿／原生记录保留原代码及数量。提交省略这些条目（包括旧 GUI 清空列表）不授予删除权限；伪造新目录外代码、改变既有数量或重复提交同一代码均拒绝，数据库事务回滚。目录内删除仍然生效。“移除已知卡”只处理编辑目录，不能用保存绕过未知代码校验或向新账号复制不明权益。

土地权益仍归属独立的 `CharacterApartmentHouses` 与 `CharacterApartmentLandCards` 住宅／地址／租期事务，见[房屋归属](../业务/住宅/房屋归属.md)；库存编辑不生成、删除或改写这两张表，也不因旧编号重叠把一条 `12000001` 记录转换成住宅权益。

C#离线保存在`BEGIN IMMEDIATE`内核验目标账号／角色存在、名称编码一致和双方离线资格，校验五类库存及明确提交的技能字段，并按当前数据库行计算修改计划；未知卡片保护、宠物容量／宝石槽限制和库存授权保持不变。无实际变化返回`changed=false/backup=null`，不写角色／库存表也不生成备份；存在变化时，在首次编辑前用独立读连接完成一份完整SQLite备份，再在同一事务内提交改变的字段／行与可选固定称号。卡片只删已移除的目录内代码，家具只替换改变的槽位，其它行及`UpdatedAt`原位保留；技能逐等级、物品逐数量／宝石／阶段对比，不因为仅改HP而刷新全部库存。明确改变MaxHP/MP时沿用资源校正规则，未修改上限且未显式提交当前值时不补满当前HP/MP。称号写入保留资料快照版本／曲线升级和前沿清零规则，主资料、原生称号及数据库称号记录共享一次事务；任何SQL失败全部回滚，失败前的单份备份保留。克隆与草稿仍保存为数据库记录，固定称号也合并进草稿事务，不另调称号工具；并发注册／重名冲突拒绝重试，不能悄悄写入已不再生效的草稿。GUI管理写入以游戏适配器停止为前提，常驻离线工具不计作游戏服务。隔离生产工具与GUI管道检查见[会话工具与增量库存验证](验证状态.md#kb-09-001-1)，不等于原客户端运行验收。

已有角色的五部位装备、特效与当前宠物必须同时保存至持久 `Appearance` BLOB 和 `EquippedPetItemCode`，不能仅增加库存或写启动 INI。选中装备／宠物在合法目录及容量校验后补齐所有权；零值表示卸下，GUI 切换角色时也显式选中零值，不能沿用上一角色的装备或默认宠物。首次载入已有角色从数据库投影控件，“保存配置”和“保存所选档案”均采集当前装备选择。装备写入不改角色等级／经验、双树SP／任务进度、性别、Face、教程起源 `PetVariant`，也不将这些字段当作装备选择器；明确提交的技能等级及Z/X独立按本主题技能编辑事务处理，不能再把启动器技能编辑排除在数据库保存之外。

保留的 `CharacterItems` 行使用 upsert，不按全部目录先删除重建；保留宠物等级／经验／耐久及已有取得时间，升级材料勾选状态未变化时保留已进化阶段，更新宝石与明确编辑的数量／材料状态。切换当前宠物时，角色级等级／经验摘要从所选库存行同步，卸下时清零；未切换宠物的无关编辑不重写该摘要；被明确移除的目录内物品仍删除。目录外卡片和独立住宅表保护保持上述边界。

该保存链的既有验证记录覆盖隔离数据库和真实WinForms选择器，以及正式数据库的只读备份副本上的角色宠物／道具落盘、其他账号和任务／技能／地宫进度表不变；验证层级为持久化及控件行为。全量卡目录专项覆盖560卡的WinForms批量添加→保存→重读→批量删除、生产C#工具的SP／活动／VIP数量边界及克隆，以及未知卡／住宅／其他角色保留。上述范围不代表本次文档修订已重跑检查；版本归属见[验证状态](验证状态.md)。

## 地宫等级与资料导入边界

GUI 新建本地角色的炮弹型与肉弹型技能点均从0开始；本地账号初始赠送与原生角色缺省初始化使用同一规则。已有角色再次注册时保留两套技能树各自的持久 SP。

副本等级（称号等级）的权威持久值由角色资料账本维护，并通过已确认的 C355、CF71 与 CF88 载体同步；字段与显示链见[角色称号](../业务/角色/称号.md)，结算载体见[地宫计分与结算](../业务/地宫/计分与结算.md)。GUI 固定称号与跟随进度的优先级见[称号编辑规则](../业务/角色/称号.md)和当前 profile 导入实现。教程选项、卡片钥匙、宠物年龄和 Z/X 技能状态属于独立字段，导入时不得互相覆盖。尚未由源码和测试确认的旧配置别名保持未决，不写入当前协议契约。

## 社交模式运行边界

社交模式不创建新的协议模式，也不使用 Stand_Alone；它沿用 Network 登录、GS、房间和地宫链，将 adapter 与客户端配置到同一个明确局域网 IPv4。GUI 的 P1／P2／P3 按用户名注册账户后分别启动客户端；同一来源 IPv4 的注册按队列消费，其他机器从各自来源 IPv4 隔离接入。该启动便利层不扩大本主题既有的多人可见性或两机运行验收范围；绑定与 GUI 契约见[启动模式与GUI约定](#kb-09-017-1)，来源队列与账户归属见[基础／连接会话](../基础/连接会话.md)、[登录与 GS 入口](启动运行.md#kb-02-001-5)、[库存编辑与持久化载体](启动运行.md#kb-03-040-1)。

## 社交模式本机多开：客户端单实例边界（2026-09-29）

2026-09-29受测客户端为项目根目录的 `game.exe`（长度 `14198272`，SHA-256 `D511D81D172DCE14E108582E0429106170491D18A0781046B24CEDC6B56E2A54`）。该样本通过命名互斥体拒绝第二实例：`0x0043A5A2` 把 `0x00C2C0BC` 的 ASCII `NanaimoClient` 传入 `0x004030B2 -> 0x00AD2F50`；后者执行 `CreateMutexA(NULL, TRUE, name)`，随后 `GetLastError()==0xB7`（`ERROR_ALREADY_EXISTS`）即返回已存在。调用方在 `0x0043A5D9` 显示 `Already Game.exe Run` 并进入启动清理。该摘要标识历史受测样本，不是当前客户端的固定哈希要求。

2026-09-29的多开方案仅用于社交模式：`gui_launcher/start_social_client.ps1` 先验证名称、调用点和 wrapper 字节签名，再把原客户端复制到按“源 SHA-256／社交槽位”隔离的缓存，只把文件偏移 `0x0082AABC` 的13字节名称替换为 `NanaimoSocNNN`。原始客户端不修改；同一槽位重复启动仍受自身互斥体保护，不同槽位可共存；不匹配的客户端版本拒绝启动。2026-09-29 的原客户端验收在已有 PID `18448` 存活时启动槽位902 PID `14028`，10秒后同时存在两个 `game` 进程，随后只结束 PID `14028`。现行方案还校验图像共享读取位点，并将副本放在源客户端旁；完整约定见[社交槽位启动](#kb-09-031-1)及[客户端兼容](客户端兼容.md#df-11-002)。

## 启动模式与 GUI 契约

- **本地模式**：使用 Network 参数，adapter、资料注册与客户端目标均为 `127.0.0.1`。“进入 Nanaimo”以用户名／角色显示名文本框选定账号，向已运行的回环adapter提交账号注册，再启动独立客户端。新名字克隆当前管理档并同步全部管理页；首次注册原子导入，已有账号按数据库状态续档。档案复制与只读卡片规则由[库存编辑与持久化载体](启动运行.md#kb-03-040-1)维护。
- **社交模式**：自动检测或接受用户填写的特定局域网 IPv4，以该地址绑定登录／世界／资料注册监听并向客户端写入同一地址；不绑定 `0.0.0.0`。GUI 显示检测地址并保存最近使用地址。
- **普通适配器启动**：未修改的编辑状态直接复用已保存 INI；有修改时要求先显式保存，不再隐式提交完整库存。启动／停止、逐文件 SHA-256、端口检查与监听归属复核均在后台执行，保持完整运行包校验；停止已有服务不要求编辑状态匹配。
- **社交适配器启动**：社交模式“启动适配器”检查已保存的启动配置存在后，停止本项目已有 adapter／bridge 进程，拒绝复用被其他进程占用的固定端口，再以指定 IPv4 单例启动并验证监听归属。共享服务启动不调用本地角色 `Save-Profile`，不把GUI当前编辑档写入角色／库存表，不受本地纯新手复选框和背包目录校验影响；服务自身仍可初始化数据库及独立工作进程状态；社交账户由各参与入口单独注册。缺少配置时在停止现有服务之前报错。
- **启动诊断**：背包C#工具后端在Windows PowerShell 5.1下完整收集标准错误输出（stderr）与退出码，恢复调用方错误策略后报告完整异常。目录外卡片按[库存编辑规则](#kb-03-040-5)只读保留。

### 启动模式与 GUI 契约

<a id="kb-09-017-6"></a>

<!-- BEGIN 09-017-6 -->

- **参与入口**：P1／P2／P3各有用户名框和参与按钮，用户名定位主机数据库账号。新账号进入纯新手创建，已有角色续用原档，注册结果按来源IPv4入队；各槽位使用独立工作目录与运行时缓存。持久化验证覆盖账号重开和离线卡片保留。

- **目录查询**：“装饰家具查表”使用 `inventory_furniture.json` 及资源图标图集，覆盖781条目录记录，其中775条具有可用图标。图标由InteriorIcon资源解码；缺失项保留明确状态及目录信息。

- **后台任务与进度**：普通／社交适配器、客户端启动、档案选择与保存采用单个 detached PowerShell runspace；后台仅取得路径、值及脱离控件的档案快照，UI定时器更新阶段／耗时，完成回调在GUI线程执行。忙碌时禁用管理页、防重复提交，并拒绝关闭尚有任务的窗口；失败恢复界面状态。预览请求以200ms定时器合并，批量控件导入不逐次枚举进程。阶段计时写入`adapter_data/logs/launcher-timings.jsonl`，阶段时长是GUI轮询采样而非精密I/O剖析。
- **查询与目录复用**：`launcher_tools=2`提供`--tools inventory-server`，一个启动器会话按运行根目录共享本机命名管道工具进程，跨短寿命后台runspace复用。`profiles`独立查询身份；首次`snapshot/apply/clone`加载六类目录，后续请求复用字典。每次按六份JSON的路径、大小、创建／修改时间检查变化，整套校验后原子替换；缺失或解析失败触发请求保护。随机管道限制当前Windows用户，请求按同一数据库根顺序处理。GUI关闭、父进程退出或两分钟空闲时回收进程；程序／清单变化或工具退出后重新建立工具。已发送写请求的超时／断线通过回读确认提交状态。元数据缓存负责性能优化，密码学身份由发布哈希独立维护；旧`launcher_tools=1`采用一次性接口，固定称号合并事务要求能力值2。
- **增量与合并保存**：已有档案使用一次身份查询，后端按字段／库存行差异提交实际变化；备份按变更生成，资料与固定称号共同修改使用一份备份及同一数据库事务。只读卡片、宠物成长、非选择器Appearance字节、技能和住宅权益的边界由[库存编辑与离线保存](#kb-03-040-5)维护。数据库事务成功后写出启动INI／JSON，数据库与外部配置采用顺序提交的独立边界；独立`state grade/reset`工具保留独立备份契约，GUI使用合并入口。
- **共享兼容准备**：首次执行完整派生／应用／后校验后，报告列出的源／目标文件、客户端／工具／程序集／清单、资源标识和子弹配置以路径、大小、创建／修改时间及属性进行会话级失效检查；输入变化或缺失重新准备。韩服宠物与Lumineos可选资源保留启动前验证，子弹DIY启用时不使用共享准备缓存。该缓存不是密码学身份证明，旧报告缺少`session_inputs`时不复用；槽位副本仍独立执行源哈希、副本与隔离资源复核。

## 社交模式槽位客户端启动契约

- `gui_launcher/start_social_client.ps1` 是社交参与者的多开入口；本地模式继续直接启动未改写的 `$Client`，不得调用该 helper。
- GUI 在后台完成共享兼容性检查后，每个参与者仅调用一次多开入口；入口在同一槽位锁内完成准备和最后运行进程保护，再调用`BeforeLaunch`注册用户名，之后启动客户端并等待可见窗口（默认最多8秒）。准备失败不向适配器排入账号；注册后启动失败仍不能当作客户端接收成功。`PrepareOnly`保留为手工／测试准备入口，不是GUI二次调用路径。返回对象包含进程、窗口、工作目录、运行时目录和副本身份。
- 槽位副本与源客户端相邻，使用 `Game.openNanaimo-social-NNN.exe`；缓存根目录默认为静态资源根下 `.openNanaimo-social`，其内部按源 SHA-256 和槽位编号隔离 `work`、`runtime` 及元数据。
- 准备状态使用 `social-client.v5` 与 `social-worktree.v2`；文件、源根、缓存根、工作目录、配置哈希和图像解析器共享读补丁共同校验。可写配置与 `Working` 独立，静态资源采用目录映射；`APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP` 指向槽位目录。图像资源探测保留只读权限并允许并发读取，避免同机多开时将共享读取冲突误判为资源缺失。
- **客户端源哈希变化**：当前哈希槽位尚未生成但源目录旁已有副本时，在同一缓存根内查找该槽位的旧 v4/v5 登记。先校验根路径、工作区／配置、目标哈希及补丁范围，再在内存中仅撤销已登记的互斥体／共享读取改动，要求还原哈希精确等于旧源哈希。唯一合法匹配才把旧副本与登记文件保留到旧槽位 `source-update-backup-*`，按当前客户端生成新工作区与副本；旧工作区不删除。输出包含 `SourceRefreshed`、旧源哈希和备份路径。新准备失败回收本次新槽位并恢复旧副本，保留备份供诊断；显式清理旧源副本同样归档，不能递归清空来源目录或账号数据。

## 2. 本地与社交 Network 启动

两个 GUI 标签都使用 `network`／`-q` 协议路径，`Install-LaunchModeConfig` 从 `gui_launcher/launch_modes/gamestartoption.network.ini` 生成 `StateOption/gamestartoption.ini`，再把 `ServerIP` 写成当前目标 IPv4。

| GUI 模式 | 地址 | ClientArgs 尾参数 | adapter／注册 |
|---|---|---|---|
| 本地模式 | 固定 `127.0.0.1` | `6:7:1:127.0.0.1:` | adapter、11999注册和客户端均使用回环地址 |
| 社交模式 | 自动检测或手工填写的特定局域网 IPv4 | `6:7:1:<LAN IPv4>:` | 主机以该地址绑定；参与者向同一地址注册并进入 |

客户端路径固定为 `<OPEN_ROOT>/game.exe`。本地与社交模式均使用Network协议及明确IPv4绑定；Stand_Alone构造器用于独立协议研究。

纯新手档的开关和用户名位于普通用户名／角色显示名之上。启用后 GUI 禁用跳过教程与全地宫选项，独立 runtime profile 固定 `skip_tutorial=0`、`unlock_all_dungeons=0`。

## 4. 登录出生点与位置持久化

- 新角色首次进入沿用角色创建与新手引导流程。
- 完成引导后，角色的地图、村庄页面和最后合法坐标写入人物档案。
- 全新客户端进程在没有可恢复频道状态时使用安全启动页面；频道重新进入恢复保留的村庄页面和最后合法坐标。
- `FFFF/FFFF` 与 `03FF/03FF` 作为无效位置过滤；单轴 `9999` 仅用于地图边界交接，不覆盖持久坐标。
- 明确的合法入口坐标保持原值，下一页面的合法落点成为新的持久位置。
