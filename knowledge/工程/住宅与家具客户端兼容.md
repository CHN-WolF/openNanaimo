## 2. 家具边界：C393 快照与 Index getter 分离

C393 家具快照采用统一布局：**1012 字节 payload、1020 字节完整帧、`payload+0` 对象数、`payload+2` 写入 WORD 2000、`payload+4` 起最多 84 条 12 字节普通家具记录、未使用区域清零**。地板和墙壁由 C38E/C424 承载。C393 负责有界场景快照，本地 Index getter 负责家具点击路径。

启动器选择 `--furniture --native-state --dungeon-state --inventory-gift-display --land-purchase --apartment-exterior --dungeon7`：PE 布局和当前五字节精确匹配时应用家具 Index-getter redirect，同时派生资源；表情使用原生代码。站点不匹配时工具保持输入文件不变并报告校验失败。

### 2.1 C393精确布局

```text
完整帧长度  1020
payload长度  1012
frame+8      WORD count
frame+10     WORD info/final = 2000
frame+12     第1条12字节对象记录
最大记录数   84
```

客户端在 `frame+10 == 6000` 时再次发送 C392；`0`、`2000` 及其他非 6000 值结束分页。适配器以 `2000` 表示完整快照终态。记录循环按 `count` 消费，紧凑的 `12+12*count` 完整帧覆盖静态读取；固定 1020 字节与清零尾部提供容量边界。家具点击随后进入独立的受保护 Index getter。

### 2.2 客户端兼容边界

一键流程以当前 `game.exe` 为输入，在确认 PE 布局和目标五字节后应用家具站点重定向：

```text
VA 0x0041235F
E9 9C C3 1B 00 -> E9 7C CC 1B 00
```

五字节或 PE 布局不匹配时，工具保持文件不变。该重定向把受保护入口 `0x5CE700` 指向现有的直接 Index getter `0x5CEFE0`；表情协议边界由 C355 独立承载。

### 2.3 家具状态与布局

家具库存按实例关联选取状态、位置、层级和镜像，容量为84件。空房间及多家具布局共享固定C393快照；装修界面支持摆放、保存、取下和重新进入后的布局恢复。客户端家具点击使用 `0x41235F → 0x5CEFE0` 的直接Index入口，布局提交由C411承载。

### 2.4 表情翻页的适配器端协议边界

启动器保留 `VA 0x00837220..0x00837263` 的原生表情代码。`C354/8 -> C355/728` 通过 `+0x3C..+0x77` 及前置进度的低44位提供访问权限，同时保留独立的评级缓存：普通评级位于 `+0x88..+0xC3`，秘密评级位于 `+0xC4..+0xC7`，前沿评级位于 `+0xC8..+0xDE`。写入不越过 `+0xDF..+0xEF` 的17字节情侣姓名区域；`WORD+0xF0` 为戒指后缀。关系无效或不存在时，姓名为空、戒指值为零。

### 2.5 城镇空地购房入口

`--land-purchase` 将空地鼠标命中连接到原生购房确认窗口。窗口按当前街区读取费用，显示金币和推荐点余额，确认后提交所选地块。空地检测、窗口输入互斥、余额门槛、确认和取消均沿用原生界面逻辑。

| 站点 | 当前修改内容 |
|---|---|
| `0x00C396C0` | 房屋更新虚表指针由 `0x0040E912` 改为 `0x00513690` |
| `0x00513690..0x0051374F` | 192字节代码区：先调用原房屋更新，检查空地状态、背景输入许可和有效地块0..19；调用原命中检测 `0x005126A0`，通过工厂参数30创建内部类型25窗口，以购买模式1调用 `0x00401596`，注册窗口并清理输入；无效命中或分配失败退出 |
| `0x0053207E` | 保留 `85 C0 74 3E` 让出补丁；原生／已撤回的 `85 C0 74 43` 精确迁移为该补丁，无商店分支跳至 `0x005320C0` 而非 `0x005320C5` |

工厂参数30与31分别生成内部类型25和26，不能把参数值直接当窗口类型。旧入口补丁复用了续租窗口参数31，再设购买mode1；城镇 C37B 处理先查询参数30对应的类型25窗口，原生 `0x53206E → 0x534C5C` 本就会让出执行。当前入口使用正确类型，同时保留无商店分支让出补丁，让 `0x4F6350 → 0x4F6100` 原生余额消费者获得执行机会并完成就绪及队列释放。原生查询命中类型25窗口只是一个条件路径，不能推出所有运行状态都无需额外让出。

C37A/C37B余额交互、C36E/C36F购房交互以及金币／推荐点门槛沿用原生流程。当前兼容组合使用factory30／内部type25入口，并保留 `0x0053207E` 的 `85 C0 74 3E` 余额让出分支，兼顾窗口匹配与余额队列消费。

工具支持已登记旧wrapper的精确升级、原始／新版编码识别与幂等验证；未知编码触发安全拒绝。购房相关检查覆盖入口、类型映射、余额让出及迁移边界。

### 2.5.1 房屋推荐结果与弹框

`--apartment-recommendation` 按以下顺序完成两个精确站点的迁移：

1. 校验成功分支 `VA 0x005A0BC1` 的20字节原编码 `68 2C 62 C4 00 8B 15 68 F3 D6 00 52 E8 39 2F E7 FF 83 C4 08`。
2. 写入 `8B 0D D4 69 D8 00 83 81 C0 0F 00 00 01 83 91 C4 0F 00 00 00`，以当前公寓UI对象为目标，对推荐点QWORD执行低DWORD加1及高DWORD进位。
3. 校验重复推荐绘制上限 `VA 0x0058CE56` 的原编码 `83 7D F8 03`，再写入 `83 7D F8 02`，使弹框按资源定义绘制两行文本。
4. 对两个站点执行写后复核；重复运行识别相同新编码并保持幂等。`--apply` 将验证后的 `game.exe` 原子写入客户端目录，并把原文件按SHA-256保存到本机备份目录。

adapter以C397结果3提交成功，以结果2表示当日三次额度已用完，以结果1表示仍有额度时的重复或自荐。C397成功分支即时刷新推荐者当前UI；房主和其他访客在下一次正常进入／恢复公寓时由C38E读取最新持久推荐点。精确字节门控为受支持PE布局提供确定性迁移。

本次仓库提交发布补丁规则与GUI自动应用入口。GUI下一次启动时从使用者自己的 `game.exe` 派生兼容版本，完成备份、原子应用和写后复核。

### 2.6 街区住宅与屋外外观系统 patch

`--apartment-exterior` 提供屋外装修菜单、房屋外观与标语牌选取、原生外观商店、文字编辑、保存和街区展示。住宅期限为购买后14天；有效期、已有住宅与地块占用状态统一参与购房判定，期满后支持换购空闲地址。已购家具与外围装饰库存按角色持久保存。

客户端派生由C#运行工具执行，精确补丁配方编译在`Nanaimo.Adapter.dll`内；`scripts/prepare_client_compatibility.py`与`scripts/apartment_exterior_panel.py`用于构建期配方生成与开发一致性检查。完整 patch 覆盖以下内容：

| patch 范围 | 当前实现 |
|---|---|
| 屋外菜单入口 | `0x5DAB27 → 0x5DAD80`，保留室内命中优先级；屋外入口要求房主身份、菜单展开完成及有效街区地址。 |
| 图像与点击区域 | 菜单构造 `0x5DA300/0x5DA30A` 使用 `(13,186)`；原生图像尺寸98×22生成 `(13,186,111,208)` 点击矩形。 |
| 外围库存刷新 | `0x5D274D → 0x5D2A00` 清理并重建总表、外观表与标语牌表，`0x5D27A5 → 0x5D3F90` 逐行追加，保持新购项目和选取状态一致。 |
| 面板输入与背景 | 在当前公寓、房间和装修面板引用匹配时分配专用输入，协调公共HUD和顶部背景；保存、恢复原状、全部取消、关闭使用原生控件。 |
| 商店与预览 | 原生商店按钮、目录、购买与关闭流程接入装修面板；关闭商店后刷新外围库存及已保存设置。图片外观与动画外观分别使用对应资源接口。 |
| 外观与标语牌图片 | 房屋图片调用 `0x5DC1F2 → 0x4052BD`，读取记录+284；标语牌小图调用 `0x5DC585 → 0x404FFC`，读取记录+224，`0x5DC592` 经资源包7加载。 |
| 保存与完成提示 | C414的54字节载荷完整初始化，包含外观／标语牌穿脱状态及三行文字。待处理保存收到C415成功结果2000后刷新设置，并通过原生弹框显示“房屋外观已保存并应用”。响应按当前面板和待处理状态关联。 |
| 资源读取兼容站点 | `VA 0x00B4D05B`，受支持布局文件偏移`0x0074C45B`；将`E8 16 A9 FF FF`替换为`31 C0 90 90 90`，使公共`fread_s`的空流参数分支保留条件清零及`errno=22`后返回读取数0；其影响覆盖该公共函数的空流调用。公寓静态资源完整性由社交槽位准备器维护。 |
| 中文文本 | 屋外预览分类、币种、购买确认、适用范围、购买结果、应用结果及默认标语共25条文本使用有界GBK字符串；保留格式参数、分行分隔符、目录名称、价格与玩家标语。 |
| 对象生命周期 | 面板分配扩展至0xA4，保存商店按钮、商店对象和保存状态；关闭及离开房间时按所属关系释放对象并清理回调。 |
| 派生校验与升级 | 按精确站点校验菜单、库存、面板代码与文本，识别已登记的上一版局部编码，升级后保持重复应用幂等；写入前保存内容寻址备份，写入后逐项验证。 |

资源读取兼容站点的完整应用顺序：

1. 以使用者自备客户端为输入，解析PE节表并将 `VA 0x00B4D05B` 映射为文件偏移；受支持布局对应 `0x0074C45B`。
2. 校验五字节原编码 `E8 16 A9 FF FF`，仅对该编码执行迁移；已为 `31 C0 90 90 90` 时按幂等结果保留。其他编码须重新审核。
3. 写入 `31 C0 90 90 90`，复核该站点；`--apartment-exterior` 将该站点与屋外菜单、布局及面板一起纳入验证。
4. `--apply` 在写入前按原文件SHA-256保存完整备份，再原子替换已验证文件，并执行写后校验；回退使用对应内容身份的完整备份。
5. 社交槽位分别补齐 `Working/floor`、`Wall`、`Obj`、`Carpet`、`Frame` 静态子树；既有私有文件保持原内容，后续启动继续使用该槽位的独立副本。

屋外面板组件使用 `0x5CC600..0x5CD5FF` 代码区，登记21个指令／代码区站点及25个文本区间；菜单入口、构造位置和外围库存具有独立站点校验。启动器在家具装饰与地宫7派生中同时启用这一组件：

```powershell
.\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility `
  --source-root '<客户端根目录>' `
  --output-root '<派生目录>' `
  --furniture --native-state --dungeon-state --inventory-gift-display `
  --land-purchase --apartment-exterior --apartment-recommendation --dungeon7 --overwrite --apply
```

外围库存包含8种房屋外观及6种标语牌。标语牌支持三行文字，每行14个GBK字节；保存后的外观、标语牌和文字由住宅记录统一用于面板恢复与街区展示。详细使用规则见[单身公寓](../指南/单身公寓.md)。
