# 工程／启动运行／启动模式与服务

## 作用与范围

维护本地／社交 Network 地址、服务启动职责、参与注册与 GUI 后台任务。

依据 gui_launcher/nanaimo_launcher.ps1 与 client_connect.ps1；本地模式和社交模式共享 Network 协议路径。

启动失败须区分进程标准错误和托管日志。适配器通过 `--log-directory`将异常写入 `adapter_data/logs/adapter-error.log`，外层stderr可能为空；`Get-AdapterStartupFailureDetail`同时收集进程stderr、托管错误和原生尾部，并导出到后台runspace。退出码无法读取时明确标为unavailable，不把空stderr当作没有错误。`-ValidateOnly`只验证启动器配置和文件，不执行正常服务初始化；发版还须用实际本地配置启动并核对11005／11999／12050的监听归属。章节审核与嵌入包的配套规则见[章节安装与发布](../../业务/角色/任务/章节剧情移植进展.md#安装与发布)。

## 登录与 GS 入口

`本地模式`是 Network 启动并将客户端与适配器绑定到 `127.0.0.1`，不是 Stand_Alone。`社交模式`仍使用同一 Network 协议路径，只把适配器绑定地址和客户端发布地址改为明确的局域网 IPv4；Stand_Alone 继续作为独立研究模式。

## 社交模式运行边界

- 社交模式不创建新的协议模式，也不使用 Stand_Alone；它沿用 Network 登录、GS、房间和地宫链，将适配器与客户端配置到同一个明确局域网 IPv4。
- GUI的P1／P2／P3按用户名注册账户后分别启动客户端；2730启动器兼容登录按来源IPv4消费11999注册队列，同一来源按注册顺序匹配。2713账号／密码认证是另一条入口，不能将其认证票据解释为该队列。具体分发及角色名移交边界见[连接会话](../../基础/连接会话.md#kb-01-004)。
- 该启动便利层不扩大本主题既有的多人可见性或两机运行验收范围；绑定与 GUI 约定见[启动模式与GUI约定](#kb-09-017-1)，来源队列与账户归属见[基础／连接会话](../../基础/连接会话.md)、[登录与 GS 入口](#kb-02-001-5)、[库存编辑与持久化载体](账号与离线编辑.md#kb-03-040-1)。

## 启动模式与 GUI 约定

- **本地模式**：使用 Network 参数，适配器、资料注册与客户端目标均为 `127.0.0.1`。“进入 Nanaimo”以用户名／角色显示名文本框选定账号，向已运行的回环适配器提交账号注册，再启动独立客户端。新名字克隆当前管理档并同步全部管理页；首次注册原子导入，已有账号按数据库状态续档。档案复制与只读卡片规则由[库存编辑与持久化载体](账号与离线编辑.md#kb-03-040-1)维护。
- **社交模式**：自动检测或接受用户填写的特定局域网 IPv4，以该地址绑定登录／世界／资料注册监听并向客户端写入同一地址；不绑定 `0.0.0.0`。GUI 显示检测地址并保存最近使用地址。
- **普通适配器启动**：未修改的编辑状态直接复用已保存 INI；有修改时要求先显式保存，不再隐式提交完整库存。启动／停止、逐文件 SHA-256、端口检查与监听归属复核均在后台执行，保持完整运行包校验；停止已有服务不要求编辑状态匹配。
- **社交适配器启动**：社交模式“启动适配器”检查已保存的启动配置存在后，停止本项目已有适配器／原生桥接进程，拒绝复用被其他进程占用的固定端口，再以指定 IPv4 单例启动并验证监听归属。共享服务启动不调用本地角色 `Save-Profile`，不把GUI当前编辑档写入角色／库存表，不受本地纯新手复选框和背包目录校验影响；服务自身仍可初始化数据库及独立工作进程状态；社交账户由各参与入口单独注册。缺少配置时在停止现有服务之前报错。
- **启动诊断**：背包C#工具后端在Windows PowerShell 5.1下完整收集标准错误输出（stderr）与退出码，恢复调用方错误策略后报告完整异常。目录外卡片按[库存编辑规则](账号与离线编辑.md#kb-03-040-5)只读保留。

## 参与入口与后台任务约定

- **参与入口**：P1／P2／P3各有用户名框和参与按钮，用户名定位主机数据库账号。新账号进入纯新手创建，已有角色续用原档，注册结果按来源IPv4入队；各槽位使用独立工作目录与运行时缓存。持久化验证覆盖账号重开和离线卡片保留。
- **纯新手档**：控制行位于普通用户名／角色显示名之上；启用后固定 `skip_tutorial=0`、`unlock_all_dungeons=0`，不能跳过教程或开启全部地宫权限；复用普通 profile 启动的适配器时，会话级 C355 门控仍强制保持该限制。
- **目录查询**：“装饰家具查表”使用 `inventory_furniture.json` 及资源图标图集，覆盖781条目录记录（单位：该JSON的记录条数），其中775条具有可用图标。图标由InteriorIcon资源解码；缺失项保留明确状态及目录信息。该计数随目录文件更新而变化，未登记受测身份、日期与图标统计口径，不作为当前验收结果。

- **后台任务与进度**：普通／社交适配器、客户端启动、档案选择与保存采用单个与控件隔离的 PowerShell 运行空间（runspace）；后台仅取得路径、值及脱离控件的档案快照，UI定时器更新阶段／耗时，完成回调在GUI线程执行。忙碌时禁用管理页、防重复提交，并拒绝关闭尚有任务的窗口；失败恢复界面状态。预览请求以200ms定时器合并，批量控件导入不逐次枚举进程。阶段计时写入`adapter_data/logs/launcher-timings.jsonl`，阶段时长是GUI轮询采样而非精密I/O剖析。
- **查询与目录复用**：`launcher_tools=2`提供`--tools inventory-server`，一个启动器会话按运行根目录共享本机命名管道工具进程，跨短寿命后台运行空间复用。
  - 查询身份：`profiles`独立查询身份；首次`snapshot/apply/clone`加载六类目录，后续请求复用字典。
  - 失效检查：每次按六份JSON的路径、大小、创建／修改时间检查变化，整套校验后原子替换；缺失或解析失败触发请求保护。
  - 管道与并发：命名管道限制当前Windows用户，请求按同一数据库根顺序处理。
  - 回收与重建：GUI关闭、父进程退出或两分钟空闲时回收进程；程序／清单变化或工具退出后重新建立工具。
  - 写请求确认：已发送写请求的超时／断线通过回读确认提交状态。
  - 缓存边界：元数据缓存负责性能优化，密码学身份由发布哈希独立维护；旧`launcher_tools=1`采用一次性接口，固定称号合并事务要求能力值2。
- **增量与合并保存**：已有档案使用一次身份查询，后端按字段／库存行差异提交实际变化；全套提交、备份与只读保护规则由[离线库存授权与增量保存](账号与离线编辑.md#kb-03-040-5)统一维护。本节只维护启动侧边界：数据库事务成功后写出启动INI／JSON，数据库与外部配置采用顺序提交的独立边界；独立`state grade/reset`工具保留独立备份契约，GUI使用合并入口。
- **共享兼容准备**：首次执行完整派生／应用／后校验后，报告列出的源／目标文件、客户端／工具／程序集／清单、资源标识和子弹配置以路径、大小、创建／修改时间及属性进行会话级失效检查；输入变化或缺失重新准备。韩服宠物与Lumineos可选资源保留启动前验证，子弹DIY启用时不使用共享准备缓存。该缓存不是密码学身份证明，旧报告缺少`session_inputs`时不复用；槽位副本仍独立执行源哈希、副本与隔离资源复核。

## 本地与社交 Network 启动

两个 GUI 标签都使用 `network`／`-q` 协议路径，`Install-LaunchModeConfig` 从 `gui_launcher/launch_modes/gamestartoption.network.ini` 生成 `StateOption/gamestartoption.ini`，再把 `ServerIP` 写成当前目标 IPv4。

| GUI 模式 | 地址 | ClientArgs 尾参数 |适配器／注册 |
|---|---|---|---|
| 本地模式 | 固定 `127.0.0.1` | `6:7:1:127.0.0.1:` |适配器、11999注册和客户端均使用回环地址 |
| 社交模式 | 自动检测或手工填写的特定局域网 IPv4 | `6:7:1:<LAN IPv4>:` | 主机以该地址绑定；参与者向同一地址注册并进入 |

客户端路径固定为 `<OPEN_ROOT>/game.exe`。本地与社交模式均使用Network协议及明确IPv4绑定；Stand_Alone构造器用于独立协议研究。

纯新手档的开关和用户名位于普通用户名／角色显示名之上。启用后 GUI 禁用跳过教程与全地宫选项，独立 runtime profile 的固定值与强制门控见[纯新手档](#kb-09-017-6)。
