# 工程／知识维护

## 范围与适用条件

本页维护知识路由、事实归属、文档语言和迁移审计约定。全部文档统一从knowledge导航：基础、业务和工程主题维护事实，指南维护操作步骤和配置示例。

## 当前规则

基础层维护跨业务共用机制；业务层维护具体对象、状态、数值和事务；工程层维护启动、资源安装、客户端兼容、构建身份及验证入口；指南层维护启动、配置、安装、回退、构建与检查的操作顺序。文件名表达一个稳定对象，路径承担模块上下文；不使用全局编号，也不以发布日期或修复批次命名当前事实文件。

同一主题可以有事实页和指南，但具体规则只有一个主入口：事实页回答适用条件、状态、字段、数值及实现证据，指南回答如何操作，并链接事实主入口。指南中的必要命令、完整配置示例、安装及回退字节核验步骤保留在操作上下文。配置格式与兼容配方的定义归事实主题，示例中使用的具体数值不另成为规则来源。许可与分发说明作为指南中的独立说明页维护。

基础内部桥接只维护可信连接、帧、容器、版本与校验。业务字段的意义及消费地址维护在对应业务页；完整共享布局可链接到schema说明。基础持久化维护存储、原子写入、备份和迁移框架，业务迁移语义维护在各业务页。

## 状态与事务

修改事实时同步其实现证据和适用边界，再核对相关引用入口。新增主题先检查既有维护位置；只有对象、事务或验证边界可以独立解释和维护时再拆文件。对象、事务或验证条件独立时拆为同一主题目录下的子页，以索引表导航；不能只给聚合长页增加章节目录。旧主题文件可以保留轻量入口，事实仅在当前子页维护。较长且不可分的叶子提供章节导航。

叶子依次交代范围与适用条件、当前规则、状态与事务、协议字段及实现证据、兼容与未确认事项、验证入口；可以合并内容短且不可分的章节。源代码标识、opcode、字段名与原始资源名称保留原文，说明性正文和标题使用中文。首次出现的术语给出中文含义。

## 协议字段及实现证据

协议按连接、分发器／控制器、客户端状态、opcode和长度区分。偏移注明完整帧或载荷基准。客户端静态证据、适配器实现、项目策略及尚未确认行为分别表述。一次构造测试通过不能证明客户端画面或多人连续操作已验收。

## 兼容与未确认事项

当前规则只描述现行实现。历史策略、旧失败样本、迁移边界及未确认消费链保留明确标签；历史结果不构成当前事实或验收。缺少受测版本、日期、统计单位或报告的旧计数保留在[历史验证](历史验证/既有记录/索引.md)。正文修订通过 Git 提交历史追溯；未确认事项在对应主题维护。历史基线和迁移时片段摘要保持不变。

修复后的九篇正文按字符区间归档并逐片迁移；旧索引原文归档，51条专题检索词保留在[知识库索引](../索引.md)。基础、业务、工程和指南共同承载全部文档，直接使用新路径导航。地址、原始指令、数值、失败观察和代码示例保留，导航与维护归属随新结构更新。

- 迁移清单`manifest/knowledge_migration.json`记录原文区间、去向和两份摘要；`manifest/knowledge_baseline.json.gz`保留迁移基线全文。
- 原文路径仅用于标识归档内容，完整性检查从归档读取，不要求原文路径存在。
- 原文基线及迁移时摘要作为历史审计材料保存，不随正文修订覆盖；后续维护在提交说明中记录问题、依据和验证结果。
- 文件确需迁移时更新路由，保留原始来源区间与历史摘要。
- 审查问题、依据和修复逐项登记于 `manifest/knowledge_review.json`，需要维护者决定的许可范围单列未解决状态。

- 原docs的18份文档使用独立的`manifest/document_fusion_baseline.json.gz`保存全文，`manifest/document_fusion.json`登记原文字符区间、路径路由和片段去向。
- 每个 `FUSION` 片段在当前主题只出现一次；独立职责需要拆分片段时，按历史归档的原文标题边界分割连续字符区间，原父记录与历史摘要保留在 `fragment_splits`，子片段须完整覆盖父区间且只有一个当前去向。新子片段的摘要基准明确登记为历史归档切片，不能用修订正文重写历史摘要；完整覆盖检查与严格内容比较共同证明融合时的信息保全。
- 严格比较只忽略已登记的文档路径和本地Markdown链接目的地调整，用于对照融合时的历史正文。
- 日常修订可以依据源码和证据纠正正文、示例与引用，保留稳定锚点、迁移标记和原始证据，通过提交历史记录修改；默认模式检查完整覆盖、路由与链接，并报告已编辑片段。
- 正文修正后严格比较出现差异属于预期结果，不能通过覆盖历史摘要、修改归档或放宽比较使其重新通过。
- 基线档案只用于审计，阅读入口指向当前主题。

## 验证入口

从仓库根目录运行：

```powershell
python -B scripts/verify_knowledge.py
python -B scripts/verify_knowledge.py --self-test
python -B scripts/verify_document_fusion.py
python -B scripts/verify_document_fusion.py --self-test
python -B scripts/verify_package.py --source-only
```

融合初次验收分别使用`verify_knowledge.py --strict`与`verify_document_fusion.py --strict`核对迁移时正文。后续正常编辑使用上述默认检查；严格模式只用于对照历史基线，已登记正文修订会使其报告差异。新增文件同步模块索引、导出候选及相应检查，候选刷新方式见[文件清单与导出工具](../指南/文件清单与导出工具.md)。

## 术语约定

| 说明性术语 | 原标识保留条件 |
|---|---|
| 适配器、工作进程、补丁、首领 | 代码标识、命令开关、文件／资源名及历史检索词保持原拼写 |
| 载荷、完整帧 | 字段名仍保留 `payload` 等原标识；偏移必须说明基准与字节单位 |
| 状态布局版本、经验曲线版本、战斗代次 | 分别说明含义，版本数相同不视为同一版本体系 |

逐项审查登记包括原位置、当前入口、问题、证据、修复方式和状态；`needs_owner_decision` 表示需要维护者确定适用范围，不能作为已经消除的冲突。
