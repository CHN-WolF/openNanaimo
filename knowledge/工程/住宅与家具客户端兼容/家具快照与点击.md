## 家具边界：C393 快照与 Index 取值函数（Index getter）分离

C393 家具快照采用统一布局，字节数与字段只在下方《C393精确布局》维护。地板和墙壁由 C38E/C424 承载。C393 负责有界场景快照，本地 Index 取值函数（Index getter）负责家具点击路径。

- 启动器选择 `--character-creation --furniture --native-state --dungeon-state --inventory-gift-display --land-purchase --apartment-exterior --apartment-recommendation --dungeon7`：PE 布局和当前五字节精确匹配时应用家具 Index 取值函数重定向（Index getter redirect），同时派生资源；表情使用原生代码。
- 站点不匹配时工具保持输入文件不变并报告校验失败。

### C393精确布局

```text
完整帧长度  1020
payload长度  1012
frame+8  / payload+0  WORD count（对象数）
frame+10 / payload+2  WORD info/final = 2000
frame+12 / payload+4  第1条12字节普通家具记录
最大记录数   84（每条记录12字节）
未使用区域   清零
```

客户端在 `frame+10 == 6000` 时再次发送 C392；`0`、`2000` 及其他非 6000 值结束分页。适配器以 `2000` 表示完整快照终态。记录循环按 `count` 消费，紧凑的 `12+12*count` 完整帧覆盖静态读取；《C393精确布局》登记的固定完整帧长度与清零尾部提供容量边界。家具点击随后进入独立的受保护 Index getter。

### 客户端兼容边界

一键流程以当前 `game.exe` 为输入，在确认 PE 布局和目标五字节后应用家具站点重定向：

```text
VA 0x0041235F
E9 9C C3 1B 00 -> E9 7C CC 1B 00
```

五字节或 PE 布局不匹配时，工具保持文件不变。该重定向把受保护入口 `0x5CE700` 指向现有的直接 Index 取值函数 `0x5CEFE0`；表情协议边界由 C355 独立承载。

### 家具状态与布局

家具库存按实例关联选取状态、位置、层级和镜像，容量为84件。空房间及多家具布局共享固定C393快照；装修界面支持摆放、保存、取下和重新进入后的布局恢复。客户端家具点击使用 `0x41235F → 0x5CEFE0` 的直接 Index 取值函数入口，布局提交由C411承载。

### 表情翻页的适配器端协议边界

- 启动器保留 `VA 0x00837220..0x00837263` 的原生表情代码。
- `C354/8 -> C355/728` 的长度均指完整帧；本节 C355 偏移也相对完整帧，通过 `frame+0x3C..+0x77` 及前置进度的低44位提供访问权限，同时保留独立的评级缓存：普通评级位于 `+0x88..+0xC3`，秘密评级位于 `+0xC4..+0xC7`，前沿评级位于 `+0xC8..+0xDE`。
- 写入不越过 `+0xDF..+0xEF` 的17字节情侣姓名区域；`WORD+0xF0` 为戒指后缀。
- 关系无效或不存在时，姓名为空、戒指值为零。
