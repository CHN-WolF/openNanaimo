## L7/L8 资源与配套程序

本节统一维护资源新增、替换、兼容别名、小地图位点和配套运行数据的安装与恢复步骤。安装范围按以下清单逐文件限定。

| 所需文件 | 内容与用途 |
|---|---|
| `resource-packs/nanaimo-korean-resource-kit.zip`、同名`.sha256` | 完整增量资源包与包体校验值 |
| 包内`kit-manifest.json`、`resource-inventory.tsv` | 全量路径、操作类别、大小、输入和目标SHA-256 |
| `manifest/lumineos_resource_port.json` | 1328项L7/L8资源身份、转换方式、基线及升级资格 |
| 包内`l7-l8-bundle/manifest.json`及`payload/` | 已转换的1328项输出及共享资源校验项 |
| `manifest/l7_combat.json`、`manifest/lumineos_combat.json` | L7／L8战斗目录、槽位和生成产物身份 |
| `adapter_runtime/`及三份发布清单 | 配套托管程序、原生桥接（bridge）、`资源/数据/dungeon_combat_catalog.bin`及源码／运行／发布身份 |
| `game.exe`及匹配基础客户端 | 兼容派生输入与共享资源基线 |

L7引用闭包包含662个节点、1605条引用，相较于前一公开资源配方更新263项：97个MMO300→200、42个PON108→106、3个SSTG逻辑身份修正及121项复制资源。PON与SSTG数量各包含一个stage1兼容别名；复制资源覆盖引用的效果、图像、碰撞和音效。L7两阶段身份为`0/100/6/{0,1}`，L8为`0/100/7/{0,1}`；L8保留两阶段各九槽。

- 主要目录为`flying/mmo/`、`flying/pon/`、`flying/map/`、`effs/game/shootinggamebasic/`、`images/game_images/shootinggamebasic/`和`sounds/`。
- 村庄包`Village_map_image/Village_map_image.pack`合并page18/page19及道路，加载／预览图位于`images/interface_images/shootingsky_inter_image/`。
- 完整文件名和各自操作以包内TSV为准。
- L7采用`sounds/23_ssky_game_bgm.ogg`，L8采用`sounds/35_ssky_game_bgm.ogg`。

### 安装

1. 退出目标游戏客户端和派生副本；配套程序更新同时要求适配器与原生桥接处于退出状态。保存当前客户端、资源标记及运行清单，角色数据库和启动配置按各自事务保留。
2. 在工程根目录校验并解压资源包到全新目录：

```powershell
$Client = '<client-root>'
$Archive = (Resolve-Path 'resource-packs/nanaimo-korean-resource-kit.zip').Path
$Expected = ((Get-Content -LiteralPath ($Archive + '.sha256') -Raw).Trim() -split '\s+')[0]
if ((Get-FileHash -LiteralPath $Archive -Algorithm SHA256).Hash -ne $Expected) { throw '资源包摘要冲突' }
python -B scripts/package_korean_resource_kit.py verify --archive $Archive
if ($LASTEXITCODE -ne 0) { throw '资源包校验失败' }
$Kit = '<fresh-kit-directory>'
Expand-Archive -LiteralPath $Archive -DestinationPath $Kit
```

3. 资源安装器按全部基线、目标摘要和已登记旧标记预检；通过后保存原文件、旧标记和事务收据，并逐文件原子安装：

```powershell
python -B scripts/port_lumineos_resources.py apply --bundle "$Kit/l7-l8-bundle" --client $Client
if ($LASTEXITCODE -ne 0) { throw '资源安装失败，按事务收据处理' }
python -B scripts/port_lumineos_resources.py verify --client $Client
if ($LASTEXITCODE -ne 0) { throw '安装资源校验失败' }
```

4. 发布配套程序时使用成套运行目录，统一校验DCC7、HP、BOSS、碰撞、计分、目标和掉落目录。整合部署入口`deploy_lumineos_release.py`默认预检，`--apply`执行资源、配套代码及小地图位点事务；它可作为上一步资源单独安装的整合替代入口：

```powershell
python -B scripts/deploy_lumineos_release.py --client $Client --bundle "$Kit/l7-l8-bundle"
if ($LASTEXITCODE -ne 0) { throw '整合部署预检失败' }
python -B scripts/deploy_lumineos_release.py --client $Client --bundle "$Kit/l7-l8-bundle" --apply
if ($LASTEXITCODE -ne 0) { throw '整合部署失败，保留事务收据' }
```

5. 小地图完整函数`0x009000D0..0x00900156`匹配登记签名后，在VA `0x00900131`将原`7C`或L7版`80`迁移为`84`，使固定关闭位移为`0xB84`，L7/L8继续使用原生前置条件。该目标以1328项资源完整校验为前提；基础L7兼容布局使用`80`／`0xB80`。同次全套客户端兼容按[安装、验证与恢复](../../指南/客户端二进制补丁/统一安装与恢复.md#df-12-011)生成、应用及校验，竞技五个位点按[结果页补丁统一流程](../客户端兼容/竞技结果与复赛.md#结果页补丁统一流程)处理。
6. 验证`openNanaimo-l7-l8-resources.json`、资源全量摘要、兼容报告及三份发布清单，再通过启动器重新派生社交副本。重复安装校验幂等及stage1别名一致性。角色进度继续使用独立数据库。

### 恢复

1. 退出对应客户端；恢复配套程序时同时退出适配器及原生桥接。核对当前文件与收据登记的安装后摘要，并校验备份摘要。
2. 整合部署使用`python -B scripts/deploy_lumineos_release.py --client $Client --rollback '<deployment-receipt>'`，由代码收据关联资源事务。
3. 单独资源事务使用`python -B scripts/port_lumineos_resources.py rollback --client $Client --receipt '<resource-receipt>'`。替换文件恢复原字节；本次新增且仍匹配安装摘要的文件按收据删除；旧资源标记随事务恢复。遇到后续编辑时保留现场并报告冲突。
4. 客户端EXE优先恢复该次完整备份；定点恢复以完整函数签名为门禁，将`0x00900131`还原为该次原值`7C`、`80`或`84`。竞技位点按[竞技场结果页配方](../客户端兼容/竞技结果与复赛.md#df-12-012)逆序恢复。最后重新校验资源、程序、配方和派生副本的一致性。

资源包同时包含英雄龙与追加宠物配方、转换工具及`source-kr/`输入，PET按868→869→990合并。该模块的完整基线、所需资源、安装命令及恢复约定见[韩服资源说明](../../指南/韩服L7-L8与宠物资源说明.md#5-随仓库资源包与安装步骤)；宠物表和散文件按其独立配方备份与校验。
