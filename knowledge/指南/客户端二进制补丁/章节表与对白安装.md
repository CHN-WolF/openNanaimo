## 前置与准备

1. 正常退出目标客户端与运行程序，备份匹配程序、overlay、运行清单、配置、数据库、资源收据和原文件。
2. 准备合法取得的资源、匹配基线及已审核章节目录；编译与37项立绘准备见[章节资源](章节候选资源.md)，四村前置见[安装与恢复](修道僧四村对白安装/安装与恢复.md)。
3. 使用同版脚本、兼容配方与程序集。已装章节的目标先按原事务所有者恢复受支持基线，再派生；审批与玩家进度按匹配事务保留。
4. 独立生成QT、QS，合为仅含上述四文件的表安装包。两份报告的共同输入身份、实际客户端及运行QT须逐项匹配。

```powershell
python -B scripts/story_qt_patch.py build --client '<baseline-client>' --catalog '<catalog-directory>/catalog.json' --localization manifest/story_localization.json --chapters 1-16 --allow-unreviewed --output '<qt-output>'
python -B scripts/story_qs_patch.py build --client '<baseline-client>' --catalog '<catalog-directory>/catalog.json' --localization manifest/story_localization.json --chapters 1-16 --allow-unreviewed --output '<qs-output>'
```

`--allow-unreviewed`生成显式候选输入，实际功能与奖励授权独立管理；合包时交叉核对任务、文本及脚本ID。

## 安装顺序

1. 安装章节立绘，保存新增／复用文件收据：

```powershell
python -B scripts/install_story_portraits.py apply --bundle '<portrait-bundle>' --client '<client-root>' --allow-inactive-preview
python -B scripts/install_story_portraits.py verify --client '<client-root>'
```

2. 先plan核对全部目标，再以窗口事务安装表与托管程序，并同步配置、运行清单及父QS身份：

```powershell
python -B scripts/story_window_accept.py plan --client '<client-root>' --bundle '<four-file-table-bundle>' --build '<matching-runtime>'
python -B scripts/story_window_accept.py apply --client '<client-root>' --bundle '<four-file-table-bundle>' --build '<matching-runtime>'
```

保存返回stamp。该事务记录五项托管程序、表事务、原配置、运行清单和父收据；其余运行依赖按完整清单配套。运行QS随配套运行包交付，再与根目录QS核对。

3. 使用同版适配器预检、应用并核对资源：

```powershell
.\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root '<client-root>' --output-root '<fresh-overlay>' --dungeon-state --dungeon7 --monk-dialogue --dry-run
.\adapter_runtime\Nanaimo.Adapter.exe --tools compatibility --source-root '<client-root>' --output-root '<fresh-overlay>' --dungeon-state --dungeon7 --monk-dialogue --apply
.\adapter_runtime\Nanaimo.Adapter.exe --tools verify-resources --kind lumineos --client-root '<client-root>'
.\adapter_runtime\Nanaimo.Adapter.exe --tools verify-resources --kind monk-dialogue --client-root '<client-root>'
```

4. 已有英雄龙、追加宠物层分别使用 `--kind hero`、`--kind korean`核对。验证四个程序区域、37项立绘、37项场景资源、1,154项战斗资源、两端表、运行清单及启动器。
5. 奖励审核绑定当前包摘要、章节ID、奖励三元组、期限和审核标识；既有授权按原范围复核。可见验收按[验证状态](../../工程/验证状态/章节剧情与跨村门槛.md)登记。

## 父资源身份同步

单独完成表事务后，以完整收据同步L7/L8父QS身份：

```powershell
python -B scripts/story_window_accept.py repair-lumineos --client '<client-root>' --receipt '<story-table-receipt>'
```

工具验证原父回执自摘要、完整安装事务、全部目标文件及原QS备份；持有资源锁后更新大小、摘要和父清单自摘要，再联合校验全部已安装资源层。失败按摘要保护恢复原父回执。

## 恢复顺序

1. 正常退出客户端与运行程序，核对目标after摘要及匹配备份。
2. 窗口事务采用 `story_window_accept.py revert --client '<client-root>' --stamp '<apply-stamp>'`；程序、配置、运行清单、父资源和表由该所有者共同恢复。
3. 独立父事务采用 `port_lumineos_resources.py rollback --client '<client-root>' --receipt '<ledger-receipt>'`，随后 `install_story_tables.py rollback --client '<client-root>' --receipt '<table-receipt>'`。
4. 二进制按[统一恢复](统一安装与恢复.md#4-恢复)恢复完整程序备份并配套恢复程序集／配方。立绘用 `install_story_portraits.py rollback`及其收据；四村场景、计分板和战斗资源按各自事务逆序恢复。
5. 新增文件由所有者在摘要匹配时清理，替换项恢复备份，复用项保留；重验程序位点、运行清单、父资源及全部叠加层后启动。
