## 安装、验证与恢复

### 1. 预检与生成

1. 退出目标客户端，确定源文件、独立输出目录和配套程序版本。记录源文件大小与SHA-256；经验曲线切换同时建立匹配的数据备份。
2. 解析PE节表，将[客户端兼容](../工程/客户端兼容/索引.md)列出的VA映射到有文件内容的偏移，检查位点范围及代码区重叠。各位点须匹配精确原值、登记旧版或当前值；冲突终止生成。
3. 结果发布函数接受原96字节`CC`及`encodings(legacy=True)`定义的单控制器版本，统一迁移到mode0／1版本。其它新增位点按各自原值／当前值匹配；已有兼容项由完整配方统一维护。
4. 以独立目录派生客户端：

```powershell
python -B scripts/prepare_client_compatibility.py --source-root "<client-root>" --output-root "<overlay-root>" --dungeon-state --dry-run
python -B scripts/prepare_client_compatibility.py --source-root "<client-root>" --output-root "<overlay-root>" --dungeon-state
```

该组同时处理既有地宫状态兼容项。需要全套资源与客户端兼容时使用`--all`；其资源约定见《完整适配器与客户端兼容说明》。派生工具按配方写入代码区和入口，保持文件长度及配方范围外字节。

### 2. 配方与安装一致性

1. 配方更新后执行`python -B scripts/generate_managed_compatibility_recipe.py`生成`managed-host/Resources/client-compatibility.json`，按《构建与验证》重新构建运行程序。
2. 托管内嵌配方、Python配方及启动器位点目录逐项一致。对派生文件重新核对全部位点，并重复应用检查字节幂等。
3. 安装由兼容工具的`--apply`或启动器兼容入口执行。目标文件保持退出状态；安装按内容摘要建立本机备份，记录原／新文件身份，逐文件确认后替换。
4. 排序配方包含`dungeon_result_score_order_entry`（6字节）与`dungeon_result_score_order_compare`（154字节）两项，均由`sorting_sites()`生成精确原值／目标值。比较区使用32位无符号总分，按角色UID稳定处理同分，剩余区域以NOP填充。逐项确认原生交换`0x00762371`、保持`0x0076240D`及就绪门控的分支目标；这160字节范围内实际更新137字节。
5. 社交多开派生副本通过当前启动器的源文件更新迁移（source rollover）同步源文件身份、兼容配方和槽位注册摘要；每个副本分别核对上述排序位点及完整兼容报告。
6. 安装后验证目标PE全部位点、文件长度、兼容报告和启动器检查。托管程序、工作进程、启动器及发布清单同步使用同一配套版本。

### 3. 专项校验

应用后执行以下配方与隔离执行检查：

```powershell
python -B scripts/test_dungeon_experience_compat.py
python -B scripts/test_live_dungeon_experience.py
```

经验setter检查覆盖堆栈、返回值、已提交经验与独立分数槽；C60D检查覆盖本地UID匹配、远端角色更新，以及98／99／100／101／127／128／199／200级的人物与PET独立字段。适配器检查覆盖F10B v3、同级同步、跨级恢复、死亡和终局冻结、重复收据幂等及持续等级增长。两类检查分别对应客户端隔离指令执行和适配器生产状态机。

### 4. 恢复

1. 退出对应客户端；涉及程序或经验曲线恢复时，同时停止匹配适配器与工作进程并备份当前数据。
2. 从该次安装回执定位原文件，校验备份SHA-256及当前文件的登记身份。采用原子替换恢复对应客户端；定点恢复200级修改时由`restore()`核对当前字节并按逆序还原。
3. 客户端与内嵌配方共同恢复到匹配版本。跨CurveVersion恢复采用同批程序与数据快照；同曲线程序更新保持后续角色进度。
4. 对恢复结果重新执行位点、配方及清单检查，确认原／目标字节身份、资源版本和数据曲线一致后启动。

#### 恢复

1. 退出客户端和目标运行程序；按兼容回执恢复客户端副本与原始程序摘要。

3. 运行程序、战斗目录、发布清单和启动overlay按同一备份版本恢复；角色及独立挑战进度按数据库备份契约维护。资源事务使用`.openNanaimo-monk-challenges.json`，入口事务使用`.openNanaimo-monk-village-challenges.json`，各自保存原件、目标摘要和回退归属。

### 第一关兼容资源安装与核对

1. 准备合法取得的源资源目录、目标客户端目录和全新的输出目录，结束目标客户端进程；建立与当前运行程序匹配的安装备份。
2. 生成第一关资源包，工具执行源摘要、依赖、转换回读、中文编码与目标基线预检：

```powershell
python -B scripts/prepare_monk_resources.py build --source "<source-client>" --client "<client-root>" --output "<fresh-bundle>"
```

3. 以同一发布清单配套的运行程序与资源目录安装。安装器使用目录锁、逐文件备份、收据和原子写入，提交前后核对目标摘要：

```powershell
python -B scripts/prepare_monk_resources.py apply --bundle "<fresh-bundle>" --client "<client-root>"
python -B scripts/prepare_monk_resources.py verify --client "<client-root>"
```

4. 保存本次收据的相对路径，核对凭据、全部新增／派生文件和保留资源。重复应用同一包保持字节幂等，变更后的文件由冲突校验保护。

### 恢复

1. 结束目标客户端进程，选择本次安装返回的收据；工具校验目标、备份摘要、清单覆盖和事务归属。
2. 按收据逆序恢复既有文件，并移除本次创建且摘要匹配的文件：

```powershell
python -B scripts/prepare_monk_resources.py rollback --client "<client-root>" --receipt "<receipt-relative-path>"
```

3. 核对恢复收据与文件身份。运行程序按相应代码部署收据恢复，角色数据与独立通关记录继续采用数据库备份契约。

## 首领终局退场效果

`boss_terminal_effect_guard`随`--dungeon-state`应用，保护已完成退场动画的对象不再重复创建死亡效果。业务规则归[首领](../业务/地宫/首领/组件与零生命附件.md#kb-06-021)，本节维护修改、资源依赖、安装和恢复合同。

| 位点 | 精确原值 | 当前目标值 |
|---|---|---|
| VA `0x006CD78F`，13字节比较／分支窗口 | `83 B8 C0 03 00 00 02 0F 84 6A 01 00 00` | `83 B8 C0 03 00 00 02 0F 8D 6A 01 00 00` |
