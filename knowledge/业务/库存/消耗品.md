## 飞行物品定义和适配器策略

已知直接连接是 `13000009 -> 21000012 curse`，`13000017 -> 21000001 shield` 和 `13000019 -> 21000002 accelerator`。适配器将这些放在C430中，在六槽栏中允许C47D放置，并在C379/CF71/CF72中携带。在CF93上消耗一次后返回精确代码CF94。客户端定义类型为诅咒2，加速器6和盾牌9。

适配器兼容策略：盾牌按卡片文字规定的7000ms抑制 kind10 D010／HP伤害；诅咒使对普通目标／Boss的攻击变为150%，持续10000ms，这是对“防御-50%”效果采用的显式自定义策略；加速器依赖原生 type6 效果，持续25秒。已观察的 domain41 样本是 NaNa秀／装饰券，不允许放入战斗快捷栏；domain41代用治疗不属于该策略。

钱树21000020沿C379／快捷栏／CF93管理；激活以合法请求为边界，当前硬币金额与掉落概率见[业务／地宫／计分与结算](../地宫/计分与结算.md)。

## 游戏道具使用与结算

整容券按券代次与角色性别提供八种脸型：三种基础脸型及五种专属脸型。选择实例、扣券、外观保存和快捷栏索引更新在同一事务完成。游戏道具丢弃按稳定实例标识定位，以最新库存核对物品，特殊保护类别遵循原有丢弃规则。

扩容权益按合法日历时间及实际有效期呈现。有效权益保留至到期，已启用状态由对应客户端使用条件控制；成功使用扩容券时扣除一张，按目录天数更新有效期。相同请求的短时重传复用原结果。

### 复活糖静态调用链和边界

`MI._D22` 提供了客户端本地复活次数表：`48000001=5`, `48000002=10`, `48000003=30`, `48000004=1`, `48000005=5`, `48000006=11`, `48000007=32`；资源行不是 C430 的数量载体。完整的静态调用链是 C475 分配 -> C476 结果 -> C430 `(code,identity)` 实例 -> C46D 使用 -> C46E 成功。`sub_81D440` 删除了具体的标识，触发了 domain48 的 event35，通过 `sub_4011B3 -> sub_7090B0` (`this[5504]` (字节偏移 `+0x5600`)) 读取本地计数器，增加了资源值并通过 `sub_408A53 -> sub_54E430` (`this[5504]` (字节偏移 `+0x5600`)) 写入。

死亡须区分客户端World连接与内部worker事务：D010绝对生命值达到局部零；原客户端死亡对话框由`0x708900`构造CF95/8，经`0x6EAD40`发送放弃请求，公开响应CF96/8无负载；结果页重新挑战另发CF8B/12，资格规则归[业务／地宫／计分与结算](../地宫/计分与结算.md)。CF87是12字节的结果请求，CF88消耗一个12字节的头部加上0x34字节的记录。`sub_73F3A0`和`sub_73FF50`读取重试/结果UI的计数器。后续的载体闭合在`0x5310B2 -> sub_408A53`处证明了C355 `BYTE+0xF2`，并在`0x6F53B8 -> sub_41A2CB(value,0) -> sub_6E2F40 -> sub_408A53`处证明本地CF71 `BYTE+0xA8`写入管理器`+0x5600`。CF84 variant60在`0x6F5F33..0x6F5F53`通过`sub_4011B3`读取当前值、减1并写入`sub_41A2CB(value,1) -> sub_408A53`；`+0x10/+0x14`经`sub_40B14F -> sub_7091B0`写入actor完整金币余额`+0x7BD8/+0x7BDC`，随后控制恢复分支使用自己的固定放置常量。历史worker扣次构造族的`CF96 -> CF84 variant60 -> CF72`顺序只属于内部复活事务，不能套用于公开CF95放弃；CF83彩蛋选择在worker内部推进该事务，仅向客户端交付CF84及相应角色恢复。此处关闭字节／顺序与本地构建，不替代可见的客户端控制恢复。

#### 准备房卡片文本路径与本地兼容入口

准备房持久显示不是另一个manager直接getter。`sub_6E2F40` 在 `0x6E2F49..0x6E2F69` 用 `0x00C6AED8="%02d"` 写actor `+0x8124`；仅mode非2时，`0x6E2F75..0x6E2F7F -> sub_408A53` 更新manager `+0x5600`。独立 `sub_6E2F90` 在逻辑x575/y550经 `sub_40DA1C` 绘制actor缓存。正确manager及死亡/结算getter不证明准备房显示缓存当前有效。
