## 六槽快捷栏和消耗效果

静态已证实布局：

```text

C47D/144

  BYTE +0x22 移除数量

  BYTE +0x23 添加数量

  +0x24 按字节存储的待移除实例身份（容量8）

  +0x2C 按数量紧凑排列的添加记录（容量6）:

      code:u32, identity:u16, selected:u8, destination_slot:u8



C379/324

  +0xE4 + 12*n, n=0..5: code:u32, identity:u32, reserved:u32



CF71/184 本地成员

  +0x5C..+0x70: 六个战斗快捷栏代码

CF72/116 刷新本地角色

  +0x38..+0x4C: 六个战斗快捷栏代码



CF93/12

  WORD +8 目标槽位 0..5

CF94/24

  WORD +8 角色 UID; WORD +0x0A slot; DWORD +0x0C code

  WORD +0x10 HP 变化量; WORD +0x12 MP 变化量; WORD +0x14/+0x16 已初始化

```


`sub_819C90` 序列化从身份低位移除和添加到记录的最终字节中的目标槽位。未声明计数范围外的字节是客户端堆栈残留，被忽略。C379恢复六个库存/装备快捷栏对象，但战斗角色初始化单独消耗了CF71/CF72中的六个代码；仅C379不足以填充副本栏。

副本解锁是一个独立的载体。CF71案例53105读取`WORD +0x7A`在`0x6F51D8..0x6F51F1`；本地CF72案例53106读取`WORD +0x56`在`0x6F5AC6..0x6F5AD7`。两者都调用`sub_40CDFB -> sub_6DCCB0`，该函数写入战斗角色`+0x80EC`。当此字段为零时，`sub_6DCD10`销毁/隐藏槽位3-5，`sub_6DE170`省略它们的渲染，`sub_6DE350`拒绝它们的输入。因此六个非零物品代码本身不能解锁扩展副本栏。

原生快捷栏扩展券属于 domain44，代码 `44000012/44000013/44000014` 分别对应15/30/3天。使用协议为 C480/12 action4 与 C481/20；C481 成功响应携带准确券代码和绝对到期值。适配器按账号持久化到期值，通过 C379 `DWORD +0x12C` 恢复，并与当前值 `DWORD +0x140` 比较；只有权益有效时才为本地成员写入战斗 gate1。权益禁用或过期时写入 gate0，即便稀疏槽位3-5的内容仍保存在存档中。

C47D、C379、CF71 与 CF72 使用同一快捷栏代码。槽位启用状态由 CF71 `+0x7A` 与 CF72 `+0x56` 同步承载；已配置槽位写入对应启用值。

CF94的case53140从`0x6F1D9F`开始。类别14分支通过`WORD +8`选择角色，应用`WORD +0x0A`指定的槽位，并在`0x6F1FC5`读取`WORD +0x10`的HP变化量、在`0x6F20E4`读取`WORD +0x12`的MP变化量。类别21分支在`0x6F1E3C..0x6F1E78`解析物品定义，从`0x6F21FB`根据定义的`WORD +0x1FC`分派效果；原生飞行效果由确切的类别21代码选择，不能用类别14代码代替。适配器对类别21返回的HP/MP变化量均为零。

当前库存事务必须满足以下约束：

- C47D按实例标识定位，原子执行移除／添加并校验数量；目标槽位可稀疏指定，支持移动／取消选择；无效数量、长度、标识或重复添加均在提交前拒绝。

- 快捷栏持久化唯一键是 `(CharacterId, Slot)` 与 `(CharacterId, InventoryIndex)`；同代码的多个实例可同时占据不同槽位。初始化过程把 `(CharacterId, ItemCode)` 唯一键结构迁移到当前结构，并保留合法行。

- C379/C430/C46D/C47D 共享稳定的会话实例身份。完整 managed adapter 维护“会话实例身份 → DB 紧凑序号”映射；删除实例时保留其余实例身份，每次连接按当前库存建立映射。CF71/CF72 向本地成员发布战斗物品代码和扩展权限。

- 完整 adapter 的 C379 必须在完整帧 +0xE4 + 12*slot 写入 (code:u32, C430 identity:u32, reserved:u32)。仅在 C430 设置 selected 位而让 C379 六行保持零，会造成 C47D 保存成功但关闭、重开背包后快捷栏看似消失；当前 C47D 成功刷新与 C378 恢复均从同一持久快捷栏生成 C379。

- CF93将WORD+8槽位解析为**该槽位本身的**持久化`(code,identity)`，扣除一次使用前校验库存／效果，发送指定角色对象／槽位／代码的CF94；成功和拒绝均在同一处理事务内发送C379。

- 适配器自定义策略 A：使用的槽位清空。已放入快捷栏的同类实例保留各自槽位，未放入的仍留在背包；不选择其他同类实例代扣、不自动补位，也不改变槽位指向。

- 校验保证一个实例标识最多映射到一个槽位，并持久化清除重复项。`quickbar_item_handle_excluding(code,slot)`优先选择**未被其他槽位占用**的标识（`release/components/quickbar/quickbar_runtime.inc`）；旧译“选择由其他槽位持有的身份”方向相反。若没有可用标识，源码仍会回退到不排除已占用实例的辅助函数，因此所有同类实例均已放置时可能产生临时重复封包；下一次校验会清除重复项，不能宣称所有路径都不会产生临时重复。

- CF94不包含剩余库存数量字段。类别14携带HP/MP变化量；类别21携带其原生确切代码，HP/MP变化量为零。

六槽同代码验证覆盖槽位0..5与身份16/15/11/9/10/14的独立映射。各次使用消耗对应身份并发布一次C379，六次使用后快捷栏清空；背包剩余身份19独立保留。槽位与库存实例分别维护。

多物品验证覆盖重启后恢复三个实例、CF93槽位0/1/2与CF94角色21归属、库存2→1，以及Z/X CF9B0/1对应52000011/52000007等级5。扩展槽4/5使用权限1；14000221恢复MP110，14000022恢复HP1600；耗尽后清理槽位。客户端效果按物品、路线与等级分别验收。

## 地宫用药后的固定快捷绑定

准备房背包读取与装备、宠物、道具变更使用同一持久库存。原生地宫启用且在线会话、角色和工作进程快照有效时，读取前提交地宫当前状态与金币／NaNa双余额；变更成功后将装备、选中宠物、道具实例及快捷栏同步到保留的地宫工作进程，并恢复已提交的通关标记、评级与情侣权益，更新后续差量提交的基线。C379统一按会话库存实例投影，反复开关背包保持同一绑定；C47D装备提交和C44F宠物配件／成长变更共用场景安全刷新边界，按当前持久库存更新C379与C44C；城镇按角色身份更新外观，准备房采用库存载体同步。准备房食物按C43D/C43E/C43F完成单次扣除和恢复，通用使用沿C46D/C46E提交，后续地宫快照保留该扣除结果。

快捷键0～5固定对应各自的道具实例，不按同代码重新配对，也不把后面的键前移或补进已用空的键。原生快照以 `224+8*slot` 保存代码、`228+8*slot` 保存 handle；`4000+4*handle` 是可带空洞的存活实例表。消费后仅按确切存活 handle 转换为压缩后的背包索引，固定 slot 不变；不存在或重复的 handle 不猜配。实际按键2请求 `CF93 slot1` 消耗其自身 handle3，slot1清空；已空slot0保持空，slot2/3/4/5继续绑定handle4/7/6/5，5瓶余药只对应4个已绑定键也合法。

快捷栏 checkpoint 以固定 slot 保存确切实例绑定，并在单个事务中完成序号迁移，保证唯一键稳定。CF93/CF94 的 HP/MP 增量在 checkpoint 前写入快照，并按基础值加选中宠物宝石的有效上限钳制（生命周期契约见[业务／宠物／索引](../宠物/索引.md)）。30 项专项与数据库 journal 恢复验证通过。

### 快捷栏资料刷新布局与排行榜选择器

CF72的apply0不保护已激活效果。六槽构造器`0x006DCF50`在`0x006DD183/0x006DD19A`逐项清零六槽`actor+0x7DD8/+0x7DDC`的type／active，在`0x006DD1CB/0x006DD1E2`清零五组`actor+0x7EB8/+0x7EBC`，步长均32；另在`0x006DD1F5/0x006DD205`清零`+0x7E98/+0x7E9C`。保护getter`0x006E0C10`先检查这两组非零active且type1，再遍历`actor+0x7F7C`链表节点的type／active及`+0x18`next。当前构造器不清该链表。普通CF72/116、apply0仍清数组保护，独立链表保护可保留；这不能单独证明视觉type9的GI21000001实机失效。资源同步行为归[业务／宠物／索引](../宠物/索引.md)，验证范围为静态字段及隔离指令执行。

CF72的两个六槽构造调用点为`0x006F5B1E/0x006F5B68`；64字节包装函数位于`0x006E3100`，先调用`0x006DCF50`，保存EAX，再由`0x006658E0`获取`[0x00D72CE8]`管理器（初始化门控`[0x00D72CE4]`），直接读取BYTE+3与DWORD+0x10F0（原生getter分别为`0x00664F00`、`0x006692C0`）。仅模式为零且状态为4时调用紧凑布局`0x006DCD10`，其它组合保留构造器的尺寸、位置及槽位；沿用同一角色、六参数与`ret 0x18`。原生初始化`0x0066CAC0`在`0x0066CDA3 → 0x00419BBE`、`0x0066CDAA → 0x0040A2D1`查询同一模式，`0x0066CDB4`仅零分支通向`0x0066CF6D → 0x00412490 → 0x006DCD10`。零分支`0x0066CED7..0x0066CEE0`通过`0x00416054 → 0x006692E0`写入状态4，随后才应用布局。`0x006692E0`更新管理器+0x10F0，必要时将原状态0／3／4／6保存至+0x10EC。模式与已进入战斗状态共同限定紧凑布局的应用条件。

缩放链为`0x00419425 → 0x007D1460 → 图标+0x204的vtable+0x30 → 0x0041B4A5 → 0x00AB4AD0`，后者向渲染对象+0x34／+0x38写入绝对浮点缩放；vtable+0x1C经`0x004103B1 → 0x00AB3120`更新矩形。构造器`0x007C6B40`通过`0x007C8430`建立图标资源，渲染构造`0x00AB2C90`的初始缩放为1.0。完整位置规则归[本主题对应章节](快捷栏.md#kb-03-036)，精确字节与迁移归客户端兼容文档；验证层级为静态指令及隔离执行。
