# 业务／DIY／子弹／接入与资源链

## 范围与适用条件

本页维护 DIY 子弹的策略选择、编号身份、资源依赖链与扩展步骤，适用于本仓库当前的篮球实例与七个别名副本。目录与本地配置见[目录与配置](配置与兼容策略.md)，验证层次与伤害归属见[分层验证](验证与伤害边界.md)。目录计数不构成逐项实机可用或完整轨迹的证明。

## 策略选择

| 策略 | 已有实例 | 接入动作 | 边界 |
|---|---|---|---|
| 复用现有 PON | GUI 的 2,995 个原资源目录项 | 选择目录项，保存 `resource`；客户端桥接预载后调用原生工厂与初始化链 | 目录计数不等于逐项实机可用；复杂多行轨迹须单独验收 |
| 通过独立别名复用 | 六个 ep02 弹幕与一个 ep09 乌鸦资源 | 安装器从客户端源 PON 复制独立别名；GUI 保存配置时转换原名 | 专用反射依赖精确别名、规定行数和运行时字段门控 |
| 保留运动参数、派生外观 | `nanaimo_basketball.pon/.eff/.im3` | 精确验证原炮弹 PON／EFF，替换依赖名与 alpha 曲线，写独立 IM3 | 当前篮球派生器固定绑定已审核输入；不能直接套在任意 PON／EFF 上 |

## 编号与身份

| 身份 | 篮球实例 | 用途与限制 |
|---|---|---|
| 文件名 | `nanaimo_basketball.pon` | INI 的选择键、预载入口和专用门控；使用文件名接入，不要求新分配数字 owner |
| PON `owner` | `1279` | 保留原炮弹来源标识；不是玩家 UID 或 NPC 运行时 UID |
| 行数与行索引 | 3 行，索引 0／1／2 | 保留 PON 结构；篮球反射门控要求准确为 3 行 |
| 原 PON 攻击候选 | `[1845,0,0]` | 保留资源数据；不是所有适配器路径下的最终命中伤害 |
| 资源内容身份 | 源与目标 SHA-256 | 安装器识别已审核输入、当前目标与特定旧版；详见[位点与安装](../../../工程/子弹DIY兼容/位点与安装.md) |

## 资源依赖链

| 资源 | 读取关系 | 篮球派生内容 |
|---|---|---|
| `flying/pon/*.pon` | PON 主 EFF 字段指向效果文件；运动仍由原生 PON／行处理承担 | 主 EFF 字符串位于 `+4..263`，以 XOR `0xAB` 编码，改指 `nanaimo_basketball.eff`；其他参数与攻击候选保持 |
| `effs/game/shootinggamebasic/*.eff` | EFF 指向 IM3 图片并维护 12 个动画轨道及时间边界 | 首图片名 `+28..283` 改指 `nanaimo_basketball.im3`；三行索引 7 的 alpha 曲线分别设为 255／0／0，delta 为 0 |
| `effs/game/shootinggamebasic/*.im3` | 原生效果按帧索引读图 | 16 个 48×48 单元竖排成 48×768；原 EFF 的选帧轨道循环使用 16 帧 |
| GUI 预览图／GIF | 启动器单独读取 | 篮球 GIF 每帧 80 ms；代表图像预览，不能代替完整轨迹、碰撞与效果依赖验证 |

## 扩展新的资源

1. 明确选择“复用已存在资源”或“派生独立资源”，记录源 PON／EFF／IM3 的身份、来源和所需依赖。完整复制依赖闭包后再改引用，避免让新文件与原怪物共用待修改的外观文件。
2. 分别登记文件名、owner、行数、攻击候选和内容 SHA-256。owner 的复用或冲突应结合资源来源与运行路径评估，不将数字相同当成玩家归属一致。
3. 在独立安装策略中登记已审核输入、目标身份与可迁移旧身份，执行源保留、未知同名内容拒绝覆盖和幂等检查。现有篮球安装器只安装篮球与七个兼容副本；它不会扫描并自动部署任意新增资源。
4. 补齐[目录与配置](配置与兼容策略.md)，按[分层验证](验证与伤害边界.md)执行。需要额外反射时，同时设计和审核运行时门控、配方与隔离测试，不能只改别名 JSON。
