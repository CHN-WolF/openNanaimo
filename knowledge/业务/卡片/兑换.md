## VIP经验卡的主动使用与持久化

翻番卡经主动使用形成有效权益。卡片账本为`CharacterCards`；C3ED的VIP元组由当前在线账户与角色的会话共同授权。一般10、自由20、黄金30分别表示三种钥匙选择。适配器扣费策略为：一般／黄金各扣一把，自由钥匙以合法且有效的到期时间授权；扣卡、扣钥匙及建立`CharacterExperienceCards(CharacterId,CardCode,Expires)`在同一SQLite事务提交。

同一张仍有效卡的重复请求只确认原权益，不二次扣卡或延时。数据库入口默认不允许更换，客户端6201已有结束旧卡、使用新卡的确认流程，协议入口明确允许新卡替换旧权益，但不叠加；失败恢复原权益和库存。数量归零删除卡片行，角色之间独立，数据库重开保留数量和到期状态；原客户端重新登录后的画面验收仍归[本主题对应章节](兑换.md#kb-09-004-1)。

商城可购买标记保持原目录契约，300%行仍不可购买。随机奖励幸运卡不属于经验权益入口；通用拒绝回0，不能冒充容量不足。C3EE后由客户端自行请求C3E7/50及C3E9，不补发跨控制器库存包。VIP列表分类字节为0，按VIP卡号映射数量及新增提示，不与同为category3的SP／活动卡混槽。

到期字段采用原生按小时编码，适配器把“使用时刻＋目录小时数”向上对齐到可表示整点，覆盖完整目录时长；判定与列表公布采用同一边界。倍率及结算规则归[业务／地宫／计分与结算](../地宫/计分与结算.md)，协议字段和钥匙链归[本主题对应章节](兑换.md#kb-08-003)，发布及验证范围归[本主题对应章节](兑换.md#kb-09-004-1)。

## 幸运卡开奖与奖励事务

幸运卡使用独立于type40经验权益的开奖分支，启用A～H八个奖池及`Sddakg._D35`对应的非零奖励记录。适配器将奖品值解释为严格递增到10000的累计区间，均匀抽取0..9999；I/J保留目录占位。验证覆盖八池全部非零奖品的加载与逐项派发。开放边界固定为实际载入且奖品区间完整的A～H（22000011～22000018）；I/J（22000019/22000020）不进入卡册可用数量、开奖或合成／开启请求。已有未开放卡库存不删除，但向客户端投影时隐藏，适配器对相应请求返回安全失败，避免进入客户端无奖池分支导致卡片页失效。

`OpenLuckyCardAsync`验证账户、角色、在线会话、持卡和神秘钥匙；选奖、扣一张卡、扣一把神秘钥匙、入库及`LuckyCardUseReceipts`凭据共享立即写事务。真正容量不足回100，保存`LuckyCardPendingDraws`但不扣卡／钥匙，腾格或数据库重开后仍发同一奖励；奖池版本或ticket/产物对应关系改变则拒绝并保留待审记录，不重抽。其它拒绝回0，成功900；不能再把不支持的请求直接回100造成6018容量误提示。

## 活动卡独立兑换与显式配置

活动卡兑换只接`C3FD/C3FE`，不复用`C3ED/type20`整页合成。每页十种卡各需至少一张，成功各扣一张；会话授权、所选单件／套装／Hans奖励提交、实例重排和`EventCardUseReceipts`在同一立即写事务完成。容量不足保存`EventCardPendingDraws`且不扣整套卡；更改该页奖池版本不能重抽旧待领奖励，已提交凭据在配置停用后仍可回原结果。请求关联窗口与幸运卡分开，限制相同。同族宠物按上文合并到一行：期限变体相加、永久变体覆盖为永久，抽到已永久持有的成品宠物才执行扣卡但不新增宠物、清除待领取记录的重复奖励结算，并回固定"已拥有该奖励"。三种奖项的完整字段约束及示例见[活动卡奖池配置](../../../docs/event-card-rewards.md)。

活动卡兑换采用显式奖池配置：从实际数据库目录读取`event-card-rewards.json`，配置有效且页面已启用时进入兑换事务；其余情况返回安全失败并保留卡片。配置为Version1、页1..10，奖项允许单件商品、Bundle整套商品或Hans金币三种形态；Quantity1仅适用于单件及Hans形态，Bundle不带Quantity。Weight为正整数，每页合计10000；完整字段限制以[活动卡奖池配置](../../../docs/event-card-rewards.md)为准。产物采用普通商品分支，C3FE的domain13与200各自保留原控制语义；自动化验证使用隔离奖池，仓库默认奖池须单独安装。

`EDdakgi._D19`的页1～4（50000001..40）描述秘密关卡勇士系列，页5（41..50）描述特制套装／钻石，页6（51..60）描述仿福娃宠物／套装／道具，页7～10为占位。现有活动卡开放掉落、拾取与卡册展示，集齐后由客户端启用领取按钮；兑换奖品编号、数量和概率以显式配置为准。响应使用受限固定提示；字符串安全边界、控制条件与刷新归[本主题对应章节](兑换.md#kb-08-006)，配置兑换验证归[本主题对应章节](兑换.md#kb-09-004-1)。

## VIP卡主动使用与经验权益字段

范围为World连接卡片页／合成控制器的VIP元组，不覆盖普通type10合成或type30 SP卡。点击链`0x855CA0 → 0x85AF50 → 0x41D4C1 → 0x859710`经`0x413BBF → 0x7BEC40`构造C3ED/28，调用`0xADA3E0`发送：WORD+8=40，DWORD+10=钥匙选择，WORD+14=0，DWORD+16=卡号，DWORD+20/+24=0。C3EA经`0x859840 → 0x85AAA0`写key对象+12，之后由`0x85AF50/0x85BA10`取用：10一般、20自由、30黄金、40神秘；不是暂停／续时／停止动作。`0x85AAA0`读取C3EA的BYTE+9一般数量、+10黄金、+11神秘及DWORD+12/+16自由钥匙到期／当前时间；自由钥匙有效时初始默认key状态1对应请求20。文本6201存在结束旧翻番卡并使用新卡的确认，不能一概拒绝换档；事务政策归[本主题对应章节](兑换.md#kb-03-003)。

父分派器`0x85A270`的case50158经`0x41E6AA → 0x8599D0`消费C3EE。VIP answer800读取DWORD+8结果、WORD+16额外百分比、DWORD+20按小时编码的到期值，再经`0x416AEA → 0x866360 → 0x4013D4 → 0x8821A0 → 0x41C0E4 → 0x8829C0`更新VIP信息，并请求C3E9；最低安全总长24。普通answer400的DWORD+12产物语义不能套到800。

完成后的`0x416171 → 0x866520`请求C3E7/12：WORD+8=50、BYTE+10=0、BYTE+11=页。`0x863790`消费C3E8/140并经`0x4110F9 → 0x881BD0`处理VIP页：BYTE+11为页，BYTE+12..21为十格数量，BYTE+32..41为新增标记；DWORD+72为到期、DWORD+76为当前时间，WORD+138为额外百分比。到期不大于当前时间时清掉百分比。`0x411694 → 0x882E30`按`(额外百分比+100)`显示倍率，并将DWORD到期拆为年／月／日／小时；最高读取字节139。

VIP使用链的静态校验覆盖13个函数、2274条指令及9143字节。权益事务归[本主题对应章节](兑换.md#kb-03-003)，计分与取整归[业务／地宫／计分与结算](../地宫/计分与结算.md)，发布及验证范围归[本主题对应章节](兑换.md#kb-09-004-1)。

## 幸运卡主动开奖及容量误提示

World卡片控制器点击链`0x855CA0 → 0x85BA10 → 0x851010 → 0x8512C0 → 0x7BEC40`构造C3ED/28：WORD+8=40，WORD+10=40神秘钥匙，DWORD+12=0，DWORD+16=幸运卡号。`0x8512C0`在约5秒开启动画等待后发送，该调用点没有初始化DWORD+20/+24，解析不得要求尾部为0；此例外不能推广到翻番卡的明确零尾部。

响应经`0x85A270 → 0x8599D0`：result900读取DWORD+12产物并构造C3EE/16；result800进入经验权益分支。result100及300进入提示类型4，由`0x8411C0`显示GS._D20文本6018“物品栏已满”。当前适配器将幸运卡开奖、经验权益授权及实际库存容量分别校验，策略归[本主题对应章节](兑换.md#kb-03-004-1)。

## 活动卡套卡门控与专用兑换响应

World连接活动卡控制器的C3E8/mode20由`0x863790`分派，`0x8627F0`读取十个数量槽，十种全部非零才启用领取按钮。`0x861180`动画更新经`0x40D9A4 → 0x867EA0`构造C3FD/12，DWORD+8为当前1起始页号，调用`0xADA3E0`发送；`v17==9`是动画计数条件，不是只需九种卡。C3ED/type20属于另一种整页兑换元组，不得挪用。

`0x863790 case50174`消费C3FE的DWORD+8结果／产物分支值、frame+12起字符串：包括0、200、domain13及其它分支。0和普通产物分支将字符串传入`0xB47637 → 0xB4AA94`格式化到24字节本地缓冲；适配器只发送**最多23字节**的固定提示，按客户端既有的GBK口径编码（页内文案可为中文，例如金币档回"200金币"），禁止控制字符、百分号、无法以GBK编码的字符与超长内容，余字节归零并显式NUL终止。当前payload28/full36是安全构造选择，按本适配器的安全构造合同定义；未配置回0，不借用200或domain13成功路径。处理后构造C3E7/20刷新当前页，不推其它控制器库存。

上述使用链的静态范围覆盖22个函数、19281字节。奖池、扣费和重试政策归[本主题对应章节](兑换.md#kb-03-005)，发布与验证层级归[本主题对应章节](兑换.md#kb-09-004-1)。

## 卡片整页组合、主动使用与发布范围

当前运行包集成幸运卡、翻番卡和活动卡主动使用。六十种活动卡`50000001..50000060`保持正rate／weight配置，掉落、拾取、主库及卡册独立于兑换配置。页7～10保留占位。集齐十种后客户端启用领取按钮；兑换按显式奖池配置授权，未配置页返回C3FE/result0与固定提示`Not configured`并保留卡片。功能规则分别见[VIP卡](兑换.md#kb-03-003)、[幸运卡](兑换.md#kb-03-004-1)与[活动卡](兑换.md#kb-03-005)，字段与控制条件分别见[VIP卡载体](兑换.md#kb-08-003)、[幸运卡载体](兑换.md#kb-08-005)与[活动卡载体](兑换.md#kb-08-006)。
