### 整页组合黄金粉卡

整页组合由卡片商店册页控制器的 `C3ED/type20` 处理，与普通配方type10、SP type30、VIP type40及活动卡`C3FD`分别维护。当前支持普通两册各前十页：token1～10对应第一册page1～10，token11～20对应第二册page1～10；每页二十种卡各消耗一张，分别产出`13000201..13000210`和`13000411..13000420`中的对应一张黄金粉卡。各册第11页为产物页；兑换授权范围为token1～20。六字段表及客户端显示链归[本主题对应章节](合成.md#kb-08-028)。

适配器采用完整一页确定性兑换对应卡的本地策略，保留金币、普通／黄金／神秘钥匙及自由钥匙权益。会话所属账户与角色同时授权，材料全量、单种255上限、扣二十张、产物入`CharacterCards`及`CardPageUnionReceipts`在一个立即写事务中完成。缺卡／产物已满时保留材料；SQL异常整体回滚；归零行删除。传输重试采用独立10秒／256项关联窗口及持久凭据，同一已提交请求返回原结果，重开保留凭据；新会话重新授权。

本元组成功回`C3EE/16`、DWORD+8=400，+12置零；客户端用提交前保存的页token查询产物，适配器按实际请求返回单帧响应。客户端将任意非400结果映射为金币补偿提示，显示金额取本地状态；适配器校验拒绝时保留金币余额。此提示与实际兑换事务分别维护。

### SP卡片的技能类型与点数规则

SP卡片 `12000001..12000010` 为炮弹型，`12000011..12000020` 为肉弹型。合成控制器的三个卡槽每槽承载一张被选中的卡片：`sub_85B030` 按实际放入的张数填写 C3ED 的 frame +0x10／+0x14／+0x18，未用槽位为 0，单张提交时 token 为卡号减 13000000，多张提交时 token 为 0。满足持有、钥匙及点数容量条件的 type30 合成按确定性事务逐槽扣卡，并把各槽面值 `+1..+10` 之和加入对应的 `SkillPoints` 或 `SkillPointsMeat`；一次提交仅受理同一册页（同族）。成功反馈使用 `C3EE DWORD+8=600`、`WORD+0x0C=本次点数增量`，驱动专用完成效果并同步可见 SP；同一传输请求重试使用零增量。普通道具合成继续使用结果400及产物代码。构造与事务检查覆盖两种族型的+1／+10、单张至三张槽位求和、余额上限、钥匙、重复提交和原子扣卡。

合成食谱中的 `210000xx` 不是 SP 卡或技能点；它们属于 `gi._D6` 的飞行道具／效果物品，应作为普通合成产物写入 `CharacterItems`，不能改变任一技能族的 SP 槽。

```text

  case50154/C3EA -> sub_40F15A -> sub_859840

    -> sub_4167B1 -> sub_85A8D0       引导步骤 取自 +8

    -> sub_4032B5 -> sub_85AAA0       +9/+0A/+0B 及日期元组



  case50158/C3EE -> sub_41E6AA -> sub_8599D0

```


`sub_83CA40` 对应的C3EE路径仅消耗`DWORD +8`，发送C3E7/C3E9，并使用卡对象`+0x528`作为结果待定。该元组不是通用的。在第二个控制器中，`sub_8599D0` answer400读取`DWORD +0x0C`，存储在`this+992`，设置完成`this+964=1`，并清除忙碌字节`this+961`。在材料/结果动画完成后，`sub_8564A0`创建结果对话框，并调用`sub_40ED13 -> sub_851910`带有该代码。`sub_851910`构建显示的奖励对象，并包括一个针对域15的PET特定分支。因此成功C3EE需要长度16和精确的输出在`+0x0C`。

“C3EE不携带输出／奖励ID”仅适用于 `sub_83CA40` 元组，不能作为通用协议结论。

`sub_86E2E0`渲染四种选择模式：模式0使用C3EA `+9`，模式1渲染自由钥匙期限，模式2使用`+0A`，模式3使用`+0B`。日期顺序保持`+0x0C=expiry`、`+0x10=current`；最小安全C3EA长度为20。

### 指导步骤锁闭合

`sub_845E20`构建C3FB/12。`sub_844D10`发送当前/更新WORD对，并设置指导控制器字节`this+0x23=1`。`sub_845180`接收C3FC，检查`WORD +8`，并总是清除`this+0x23`；C3FC/10足够。

收到 C3FB 时返回 C3FC，并保持合成控制器的 current/update 状态一致。C3FB/C3FC 交换与完整合成结果生命周期分别验证。

适配器持久化 `card_guide_state_<account>.dat`，响应请求驱动的C3FC，并为新 `skip_tutorial=1` 账户引导步骤3。

### 卡片合成与钥匙 / 配方与合成钥匙事务策略

<a id="kb-03-033-3"></a>

<!-- BEGIN 03-033-3 -->

C3ED构造函数`sub_7BEC40`的固定长度为28。当前调用的提交点`0x84DDA0/0x84E396/0x84E896`写入`WORD +8=10`和`DWORD +0x0C=token`；`WORD +0x0A`是未初始化的填充字段，不是钥匙选择字段。

type10普通配方由适配器按以下确定性策略选择钥匙；type20整页组合与type40分别采用各自事务规则：

1. 优先使用有效的自由钥匙权限；

2. 否则 `normal -> gold -> mystery`，C3EA中可见的三个计数槽位。

C3E8的第四槽位是独立的账户字段；自由钥匙权限不因合成而改变。计数持久保存在以`card_key_state_<account>.dat`为键的数据库记录。提交前校验配方令牌、各材料所需数量、奖励容量及钥匙可用性；奖励、卡片和钥匙账本作为一个逻辑事务提交，保存异常时恢复内存与持久账本。

### 响应完成与适用范围

第二控制器普通配方的成功响应为 C3EE/16：DWORD+8=400，精确输出位于 DWORD+0x0C；未初始化结果使用零值。C3E7/C3E9/C3FB 与可选 C3EF 响应保持请求驱动。输出载体由第二控制器静态链确定。

本地测试覆盖单／双／三材料配方、精确产物、初始化失败、回滚／持久保存、重复合成、宠物／宝石／类别21库存及重新连接。客户端结果对话框关闭和可见奖励入库仍需单独验证。引导／计数的局部检查通过不证明完整结果生命周期。
