### 商店购买、待领取物品领取与持久化

- C431/16适用于PET和普通商店物品类别：BYTE+8付款模式（已观察4，托管端允许0/2/3/4），BYTE+9物品类别，WORD+0x0A数量，DWORD+0x0C代码。
- C46F/16适用于支持的Cash家族；C3CD/68是头像购买。
- C432/C470成功仅**BYTE+8=10**；拒绝使用40，NaNa位于响应+0x58、Hans位于+0x60。
- C3CE/32的独立头像结果在+0x10写NaNa/Cash、+0x18写Hans。
- 头像目录`ava._D1`字段9是NaNa/Cash价格，购买事务只借记Cash并保持Hans不变。
- OpenNanaimo的目录映射、数据库扣款和C3CE回写现已统一到该顺序；聚焦构造以代码10010024、价格65验证Hans 9,999,999不变、Cash 9,999,999→9,999,934。
- 资源映射物品类别14/18购买进入账户项目账本；支持的C46F库存进入`owned_misc`和C474模式1。
- 未知物品、零价格、不可售商品、支付类别不符或保存失败均拒绝请求，不提交余额及库存变更；原客户端可见购买与重登余额仍需发布版试玩。

- 托管适配器的 PET `pi._D7` 字段13/14分别为金币Hans／Cash，普通宝石 `PA._D9` 字段19/20分别为Hans／Cash，特殊宝石 `SP._D34` 字段8为Cash，18000001／18000002分别为480／200。
- 目录价格列与请求支付模式共同确定结算钱包；余额不足、错误物品类别与非卖品返回拒绝结果，并保持钱包和库存事务一致。
- 家具 `inter._D3` 有4个头字段，每行20字段，代码0、名称1、类型2、期限5、Hans6、Cash7、图标13；C40B mode0使用Hans，mode4使用Cash。

### Hans 商品与整容券

- 托管适配器的普通商城目录按币种显式分类。
- C431 请求仍使用 `BYTE+8` 付款模式、`BYTE+9` 物品类别、`WORD+0x0A` 数量和 `DWORD+0x0C` 代码；实际客户端会使用模式 `0/2/3/4`，不能只接受模式4。
- `gi._D6` 中18个 Hans 定价的 物品类别14/domain21 商品从 `g_profile_coin_hans` 扣款，其余当前目录行从 `g_profile_nana_cash` 扣款。
- C432/C470 继续在 `+0x58` 携带 NaNa、`+0x60` 携带 Hans。
- 任何余额、库存实例、实例身份 或保存步骤失败都回滚同一事务。
- 本地专项测试覆盖两种币种只修改各自余额、数量溢出与保存失败回滚；原客户端逐商品可见购买仍需客户端运行验收。

- 整容券链路为 `C46F/C470 -> C475/C476 -> C430 -> C3D1 -> C3D2 -> C47F`。
- C3D1 的68字节 payload 在 `+60/+62/+64/+66`（完整帧 `+0x44/+0x46/+0x48/+0x4A`）携带尾部脸型选择字段。
- 托管适配器按 C430 槽定位并消耗准确 实例身份，只允许修改脸型：一代券 `45000001` 对应 `10100004..10100008`，二代券 `45000002` 对应 `10100009..10100013`。
- 成功后先持久化，再发送 C3D2/52 状态1000和 C47F 即时刷新；失败恢复外观、库存和 实例身份。
- 后续 C355/C368/C379 从同一持久外观读取。
- 静态字段布局和专项构造已闭合，客户端界面动画与重进可见效果仍需发布版试玩。

- C475/20用于将商城待领取物品转入库存，适用范围不限于PET：BYTE+8模式，BYTE+9操作，WORD+0x0A数量，DWORD+0x0C本地对象令牌，DWORD+0x10代码。
- 已观察到的模式1／操作4／数量1请求包括44000018/42000007/43000002/48000001。
- 类别15按宠物领取规则处理；受支持的其他类别使用物品账本，并保留同款礼包的独立实例。
- C476状态位于WORD+8，零表示失败；状态3/4分支读取WORD+0x0A的数量及DWORD+0x0C的代码。

### 游戏道具使用与结算

特殊道具购买接受目录定义的金币或NaNa结算。银戒43000001为100000金币，金币分手券43100001为50000金币；现金款使用各自NaNa价格。普通购买、特殊购买、账户购买及赠送均校验目录币种、单价与可售状态，失败交易保持余额与库存一致。

## 韩服离线经验与商城候选

本节限定于指定韩服客户端相对**当前本服安装**的静态差异，不修改本页现行购买、礼物、币种及数据库事务规则。样本、证据等级及其它候选由[韩服差异](../../../工程/韩服差异.md)统一路由；目录文本见[准确样本](../../../evidence/static/kr-feature-comparison-20261011/catalogs/candidate-samples.json)。

### 离线经验购买

韩服`GS._D20`文本`21100..21104`描述`몽유환`（工作译称“梦游丸”，不是已确认的官方中文译名）：离线至少3小时后再次登录可购买，购买即自动使用并保存／累积经验。当前本服这些文本ID缺失。韩服还存在带`[OFFLINE EXP]`调试标识的专用弹窗、购买按钮、请求构造及成功结果消费；已证明新增界面框架和部分消费链，**未证明本版本实际可用**。

KR工厂`0x6FED00`的case79在`0x700AE6`构造`0x7B7DC0`弹窗；CN工厂`0x7E8980`在`0x7E89B1`的上界为77，78／79进入默认分支。否定只限定这个工厂，不能扩大为本服没有一切离线经验能力。专用界面由`sub_7B8290`引用`003297_popup_shop_mongbg00.im3`／`003298_popup_shop_mongbg01.im3`；点击链`sub_7B87C0 -> sub_7B96C0`在`this+0x28==0`时发送购买请求。

| 韩服专用弹窗元组 | 静态构造／消费 | 已证明下界及限制 |
|---|---|---|
| 开窗`C37A -> C37B` | `0x7B81F3 -> 0x7B9660 -> 0x49FB80`构造full12，经`0x989820`发送；`0x7B9010`读响应full DWORD+8/+12/+16/+20 | 该响应直接消费至少24字节，不等于已闭合完整协议长度 |
| 购买`C46F -> C470` | `0x7B96D5 -> 0x7B0A20`构造full16；`0x7B96DD -> 0x7B9780`取`this+0x3DC`所指对象DWORD+0，`0x7B96E8`写full+0x0C，`0x7B96F7 -> 0x989820`发送 | 构造器只明确初始化WORD+4长度及WORD+6 opcode；此路径的+8..+11没有明确初始化，不能照搬为安全请求模板 |
| 购买成功`C470` | `0x7B9010`读取BYTE full+8==10；DWORD+0x58/+0x5C和+0x60/+0x64交`0x933050/0x933000`写钱包对 | 成功分支直接消费至少104字节；结果50另读BYTE+9，下界10字节 |
| 购买后的经验展示 | `0x7B922A -> 0x73AC50`取当前QWORD经验，`0x7B923C -> 0x7B9760`取选中对象QWORD+0x160，经add／adc后`0x7B924E -> 0x7BB040`写动画目标 | 证明本地累加展示，不证明奖励来源、真实到账或持久化 |

这些opcode复用了其它控制器已有号码；连接选择、当前弹窗／dispatcher和客户端状态不可省略。原始函数、xref及逐指令PE复核见[离线经验链](../../../evidence/static/kr-feature-comparison-20261011/binary/kr-offline-first.json)、[构造与消费](../../../evidence/static/kr-feature-comparison-20261011/binary/kr-mechanism-closure.json)和[最终验证](../../../evidence/static/kr-feature-comparison-20261011/binary/verification.json)。

构造器所调`0x7B8630`是空函数；限定扫描`0x7B7000..0x7B9800`只发现`this+0x3DC`的两处读取，没有闭合写入者、具体目录类型或可达开窗入口。实际物品代码仍未知。`14002486`在两端实际`gi._D6`都为伊露卡满HP／MP药，**不是离线经验道具**，不得因先前猜测硬接此ID。

“离线至少3小时”目前是目录文案层级；不能据此认定计时起点、离线收益公式、价格、可领次数或原服持久化策略。成功分支的本地经验展示也不是本轮实际购买或经验到账观察。不得将它解释为客户端关闭后仍自动挂机、自动发经验或本服现行的离线档案编辑功能；移植须先闭合定义来源、实际入口与资格校验，再按请求驱动维护经验事务。

### 复购赠礼与组合礼包

韩服新增`GS21007..21011`描述专用复购窗口赠礼、背包无空槽时赠礼失效／不发以及支付窗口最多25件。它是与普通购买／待领取列表不同的候选，赠品来源、消费门控与提交回包仍以静态调用证据为准；不能把文案中的无空槽丢赠礼改写成本服当前事务规则。

KR工厂case78在`0x700B59`构造`0x7B7AB0`，RTTI descriptor`0xB90640`、已闭合COL`0xB407B8`和vtable`0xAFBFB4`构成保留框架。关键回调`0x7B7D20/0x7B7D30`返回2／0，`0x7B7D40/0x7B7D10`为空；没有复购按钮、请求、响应或赠礼事务闭合。对文本键直接DWORD引用的空搜索结果不能排除间接消费，但也不能将该空框架升级为现成玩法。原始[复购链](../../../evidence/static/kr-feature-comparison-20261011/binary/kr-repurchase-closure.json)及[回调](../../../evidence/static/kr-feature-comparison-20261011/binary/kr-repurchase-final-callbacks.json)保留。

`PS._D26`韩服50行、本服43行，新增`55000044..55000050`。例如`55000048/55000049`的“经验Big3套装”文案包含3倍经验、复活`(30)`、秘密关卡自由进入7天，附赠11次喇叭及1张黄金合成券。括号30只保留原值，不擅自解释为天数；这是商品说明，不是可执行拆包配方，也不是新技能或新副本。现有同类经验卡、复活、合成和权限各自维护事务。

退款属于商城系统差异而非娱乐玩法。KR`0x731560`经`0x7319DF -> 0x7359D0`构造`C495/full20`：full+8为1，WORD+0x0A为槽位、BYTE+0x0C为类型、DWORD+0x10为代码，随后发送。KR`0x7156B0`在`0x7157A5`匹配`C496`，`0x715B6B/0x715B86`读DWORD full+8，直接消费下界12字节，成功／失败切UI40／41。`GS41002/41003`对应撤销购买结果提示。CN库存分发器`0x8005F0`的高opcode分支`0x8006D9`只匹配C481，没有C496；否定仅限这个库存分发器。

退款资格、扣回库存、退还比例及其它控制器仍未闭合；不能当成物品出售、无条件退货或法律期限结论。复购和退款均没有本轮运行验收，原始指令与身份见[二进制证据说明](../../../evidence/static/kr-feature-comparison-20261011/binary/evidence-note.md)。
