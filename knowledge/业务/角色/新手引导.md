## 主线新手引导与配置装备隔离

所有已建角色从持久化 `Appearance` 恢复登录外观；未完成教程时，仅对 `271A` 的 D6/D7 执行教程安全投影。`Characters.PureNewProfile` 与建角同事务保存，每次登录和频道刷新恢复。`C368`、`C36A` 与尼莫对话前后共享角色保存的外观，档案生命周期由账号和角色身份维护。

### 一村尼莫引导完成与建角推荐人

一村故事引导完成使用 `C599/88 -> C59A/36`。普通引导提交 `taskType=0, guideId=0..5`，终章提交 `taskType=7, guideId=6`；72字节尾区按不透明数据接受。adapter 在同一事务中更新 `CharacterStoryGuides`、发放一次性奖励并始终返回可消费的 `C59A`。尼莫 `guideId=0` 首次完成向普通游戏道具背包发放 `46000008`（100金币兑换凭证）1张；重复提交成功应答并保持单次领取。凭证使用事务扣除1张并增加100 Hans。

建角后的推荐人请求为 `2725/24`，固定16字节GBK姓名；响应为 `2726/28`，`DWORD +8` 结果10/20/30分别表示不存在（含原始请求中的空名或格式无效）、自己、成功，成功时 `+12` 写16字节规范角色名。adapter 在首次有效绑定的同一SQLite事务中给推荐人角色档案增加200推荐点，重复提交沿用已保存结果。每次请求返回一个完整结果；角色上下文由后续常规登录上下文请求取得。

推荐人结果10／20／30分别创建消息40／41／42；客户端兼容项将三类提示的确认结果接回登录继续流程，并在留空或填写自己姓名时清理本地提交等待旗、恢复填写状态。适配器负责单请求单结果、登录连接作用域、规范姓名和首次有效绑定200推荐点事务。

成功姓名使用16字节NUL结尾GBK字段，适配器校验编码、容量与控制字符；失败结果清零姓名尾区。结果构造、提示状态、等待旗恢复、幂等绑定和后续登录上下文已纳入专项回归。字段与状态调用链见[本主题对应章节](新手引导.md#kb-08-008-2)，完整二进制应用和恢复步骤见客户端兼容说明1.1.2节。

## 纯新手档持续游玩与地宫前置

纯新手档在创建角色后保留玩家选定的基础外观槽位；教程阶段只暂时屏蔽特效和宠物槽，教程完成或重新进入村庄时恢复已保存的完整外观。纯新手档用户名由启动器单独保存，填写已有用户名即可继续对应角色；历史生成的纯新手账号也支持以其已有角色名找回，已有角色不会被重新创建或覆盖。

纯新手档始终按原始进度逐个开放地宫，只有前一地宫链完成后才允许进入下一地宫；该模式不允许开启“全部地宫进入权限”，运行值固定为 `unlock_all_dungeons=0`。第五村继续保留既有进入兼容机制，但仍要求前置普通地宫全部满足。常规角色档是否使用便捷开放策略属于独立配置，不改变纯新手档约束。

## 韩服僧侣破关与跨村主线

韩服前四村出口各有一个`수도승`（修道僧）NPC。主线要求完成本村四个Episode任务，在Episode4／8／12／16的出口剧情结束后与僧侣对话，再完成独立飞行射击关卡取得下一村资格。任务表将僧侣目标列为对应章节最后一项；任务ID、目标ID和普通任务卷轴分别维护。精确NPC／任务／目标／脚本／资源映射及地址归[本主题对应章节](新手引导.md#kb-08-001)“韩服僧侣破关静态边界”。

脚本失败执行`COMPLETE step_clear=0`，成功执行`step_clear=1`，失败对白推荐留在挑战中重试以增加可连接／复活次数。QS6000建议至少16级、完成二次成长的宠物，属于玩法建议；准入字段按独立控制契约维护。重试上限、准确成功条件、组队资格及强制宠物门槛列为待确认边界。

CN版本使用独立NPC、动作脚本和关卡格式；当前跨村政策由既有主线与前置QWORD规则维护。韩服四个僧侣目标及C5A0入口列为独立的静态与离线资源模型，移植范围以当前适配器功能表为准。

## 新手教程门控

主教程的进入判定已定位到适配器控制的登录字段：

```text
271A byte +0x0E
  -> sub_4E3830
  -> 角色信息对象 byte +3
C352 成功
  -> sub_4DFAA0 本地 phase5
sub_4DF1E0 phase5
  byte +3 == 0  -> 全局 state12（主教程）
  byte +3 != 0  -> 全局 state1 （跳过教程）
```

Network 模式使用角色资料参数 `skip_tutorial` 控制教程入口。跳过路径仍由请求驱动：C351 只收到 C352，随后客户端直接发出 C354；适配器返回 C355，重新应用角色资料门控，再发送 EA61 scene0。此路径不发送教程 EA61，也不合成 C353。

直接进入游戏的状态链为 `C351 → C352 → C354 → C355 → EA61(scene0) → C367/C368`，按角色与页面状态逐步完成初始化。

## 拉明奥斯村庄前置进展

第五个村庄（hd4）有一个独立的64位前置条件字段在**C355全帧+0x80..0x87**。普通的前四个村庄进度和压缩的阶段显示字节不会替代它。它的局部移动谓词需要**每个前置对的两个位**；普通的CheckDungeon路径是分开的。零掩码条件下的客户端运行中，每一对在接收到的C355和只读的运行内存中都是零，这与报告的“挑战完关卡方可移动”边界相符。具体的分派器/写入器/谓词/消息/发送地址、页面映射和本地映射小部件异常属于08。

C355 final access normalization has two domains: `+0x3C..+0x77=0x0F`, and the low44 predecessor bits of `QWORD +0x80..+0x87` are set while bit44..63 are preserved. The score-board bytes `+0x88..+0xDE` are not normalized: ordinary `+0x88..+0xC3`, secret `+0xC4..+0xC7`, and frontier `+0xC8..+0xDE` retain persisted or zero values. `+0x78..+0x7F` and fields from `+0xDF` onward remain unchanged. C354 remains the request trigger.

构造检查覆盖普通副本表、前置 QWORD、打包阶段域、频道重连及 `+0xDF` 边界。该验证覆盖适配器端 C355 构造；物理入口、道路、action166、战斗资源与原客户端可见移动分别验收。
