## 副本等级与称号状态

副本等级独立于人物等级。客户端在`dword_D869D4 + 0x5C4`后存储这对值：副本等级为`WORD [pair+0]`，人物等级为`WORD [pair+2]`。权威的副本等级载体是271A `+0x0D`、C355 `+0x24`、CF71 `+0x49`、CF0E `+0x0B`、CF88记录 `+0x07`（第一条记录对应完整帧`+0x13`，步长为`0x34`）和CF8A记录 `+0x06`（步长为`0x38`）。C355 `+0x25`是独立的一次性对话／状态DWORD，不是称号等级。

称号／角色资料面板读取副本等级并格式化资源`1243 + grade`；其显式呈现开关覆盖了等级0到42。等级0显示“修炼中的初级收集者”。原生称号字符串从 `GS._D20` 解码取得：单独的开关选择文本ID2038至2058/2394至2412；等级23使用文本2396（打败头脑胶囊的收集者），等级24使用文本2397（打败马斯特洛克的收集者）。图像ID和文本ID不能互换。选定阶段也有一个客户端本地副本等级字段，但CF6C/CF77/CF87不传输它；因此，本地阶段选择无法提供持久的账户权限。适配器必须在结算时为每个角色提交副本等级，并通过后续的角色资料载体恢复相同值。确切的原始适配器边界顺序和奖励编号仍然未知。

原生兼容副本等级状态使用记录键 `dungeon_grade_state_v1_<name-hex>.dat` 和版本1载荷。当前 `sqlite_state.inc` 将文件API映射到SQLite的 `NativeState` 表，`.dat/.new/.bak` 是兼容记录名；不要求运行目录存在同名文件。载荷包含 `grade`、`frontier_valid` 和 `hd/episode/dungeon/difficulty/stage`，通过 `.new/.bak` 记录执行事务替换和备份恢复，并校验等级0到42。角色身份是精确配置的名称字节，以大写十六进制编码。

自动称号只由 `stage1` 超级 Boss 成功结算授予，普通 `stage0` 不更新称号，低／中／高三种难度共享同一地图里程碑。1～4村使用原始选择元组 `hd0/episode0..15/dungeon2/stage1`，依次授予 grade1..16（P1..P16）；5村保留通信身份 `hd0/episode100/dungeon0..7/stage1`，依次授予 grade17..24（R1..R8），资源查找时的 ep16..23 别名不参与称号身份。自动最高grade24；SQLite旧称号约束23→24在事务中完整保留旧行，未知字段／自定义索引或触发器拒绝自动迁移，重复初始化幂等。R8沿角色通关账本保存并在重登录时恢复，rating0失败不能授予。重复通关不重复升级，较高的非错误手动称号不降级。旧 `grade23 + ep15/dg2/stage0|1` 错误状态由 managed 持久通关记录重算；既有迁移样本中的 episode3/15 Super-Boss 通关历史恢复到 grade16/P16；该结果仅适用于该样本。纯C文件若只有 stage0 无法证明旧称号，先回到有界0并等待 managed 导入。

CF88记录 `+0x07` 与271A/C355/CF71使用同一称号账本。构造与持久化验证覆盖等级23、超级别名去重、v1存档兼容、等级保持及资料载体。等级23使用文本2396和对应GBK字符串；显示按登录及结算场景独立验收。结算细节见[业务／地宫／计分与结算](../地宫/计分与结算.md)，调用链见[城镇称号与角色等级](称号.md#kb-08-012-1)。

### 称号等级的持久化与显示

固定称号等级使用现有 `dungeon_grade_state_v1_<name-hex>.dat` 版本1账本：原子写入所选 `grade`、`frontier_valid=0` 和零化的边界元组；跟随进度时不改写账本。这不修改客户端，也不引入第二个称号字段。适配器通过271A `+0x0D`、C355 `+0x24`、CF71 `+0x49`和后续CF88结算状态恢复该等级。本地测试覆盖了前三个载体上的等级42，但未证明客户端渲染及重新登录后的可见状态。

称号等级取值为0..42。本地图像文件名使用1243+等级；本地化称号字符串通过410E1F/434710中的独立开关获取。1243..1285是图像编号，不是文本ID；2412是文本键，不是共享图标编号。`GS._D20` 已闭合 grade0..24 的中文文本：grade1..16 分别是机炮飞艇、大机械熊偶、斯巴特洛、单眼怪里奥、石鬼豪斯、立忠大将军、独角蓝鬼咒魁、不老的始皇帝、乔伊桑和蜈蚣王、疾风刺客法雷、不死神坛、坏熊梅尔文、海盗王丹尼、轰天炮台、三龟巨魔、派·罗斯；grade17..23 分别是瓦格拉诺、闇黑法老王、邪神马米加、迷之爱丽丝、冰龙邪王、大魔女明琪、头脑胶囊；grade24是马斯特洛克。GUI下拉框同步显示 P1..P16、R1..R8 及这些原生文本。grade25..42 的打包文本为空，grade40..42 的图像记录1283..1285也未出现在检查过的界面包中，因此GUI明确标为“原生文本为空”，末三档另标“无配套图标”，不猜测名称或回退。

### 城镇称号与角色等级

200级兼容将城镇称号设为6位（bit6..11）、等级设为8位（bit12..19），UID保持bit20..31、低6位保持原义；入口使用imm32比较200。托管初始构造、TownTitleProjection增量／广播、原生构造与客户端读取统一使用称号mask=0x3F<<6、等级mask=0xFF<<12，分别保留等级bit12及UID。边界与保位回归覆盖127／128／199／200／201和称号0～255归一化。精确原／新字节、独立代码区、冲突检查、迁移与恢复步骤统一归`knowledge/指南/客户端二进制补丁.md`。指令隔离验证覆盖200种城镇组合及入口1..255分支。下文CN原布局说明兼容前的字段编码。

`0x53E0C0` 消费城镇角色控制值：位6..12为地宫称号，位13..19为角色等级，位20..31为场景身份。角色构造经 `0x402432 -> 0x535530` 将称号传入参数 `a16`，经 `0x40B2B2 -> 0x504E40` 写入角色 `+0x31BC` 并选择 `1243 + 称号值` 的资源；`0x40AAF6 -> 0xA72530` 保存称号。独立的等级参数 `a18` 经 `0x40D373 -> 0x505D90` 写入角色 `+0x31BE`，经 `0x40FEE8 -> 0xA72570` 保存等级。适配器共享城镇构造同时写入两个独立字段，并保留构造模式及分配身份。

城镇压缩等级的位宽与地区版本必须分开：CN `C36A/112` 完整帧 `DWORD+0x3C` 在 `0x53E138..0x53E182` 解析为 `grade=(v>>6)&0x7F`、`level=(v>>13)&0x7F`、`scene_uid=(v>>20)&0xFFF`（等级右移 `0x53E15A`、掩码 `0x53E15D`）。KR对应 `ANS_TOWN_USER_INFO` 处理器 `0x4DEDF0` 在 `0x4DEE68..0x4DEEBC` 改为 `grade=(v>>6)&0x3F`、`level=(v>>12)&0xFF`，UID仍从bit20开始（等级右移 `0x4DEE94`、掩码 `0x4DEE97`）；即称号由7位减为6位，等级由7位扩为8位。已发布旧版本按CN的 `level<<13` 构造，99策略下安全；200级配套托管及原生城镇构造改为 `level<<12`，必须配套CN解析补丁。只放开应答方等级、仍用旧位域会使200被读为72，并可能污染UID最低位。100..127不触及此位宽边界；128..255至少需要配套修改解析与打包。现有称号0..42可装入6位，但不能据此省略其余消费者审计或移植整套KR包布局。以上结论限定于字段布局和隔离位域计算，三位等级界面采用独立验收状态。

### 结算和角色资料结果锚点

<a id="kb-08-049-7"></a>

<!-- BEGIN 08-049-7 -->

副本等级和玩家等级相邻但独立。`sub_41E0D8 -> sub_A72510` 读取副本等级 `WORD [*(manager+0x5C4)+0]`；`sub_40AAF6 -> sub_A72530` 写入它。玩家等级使用相应的 `+2` 获取/设置对。载体写入包括：271A case30 `+0x0D`；C355 `0x00530F90..0x00530F9B` 从 `+0x24`；CF71 case53105 `0x006F4FC0..0x006F4FCB` 从 `+0x49`；CF0E case53006 `0x006F8938..0x006F8943` 从 `+0x0B`；CF88 case53128 记录 `+0x07`；CF8A case53130 记录 `+0x06`。C355 `+0x25` 通过 `sub_40CA04 -> sub_54E410` 写入管理器 `+0x4F70`；其唯一的获取路径 `sub_402BD0 -> sub_540350` 显示/清除对话框52，因此它不是标题状态。

标题渲染在 `sub_82E4B0` 处结束：本地等级在 `0x0082E584` 读取，检查过的远程资料提供帧 `+0x29`，`sub_B475A2` 使用常量 `0xC9211C` `interface\%06d-qz_inter_lv_icon%d.im3` 格式化 IMAGE 记录 `1243+grade`；随后的 switch 覆盖等级0..42，使用TEXT键2038..2058/2394..2412。等级24图像1267是R8；文本2397是马斯特洛克。grade25..42的解码文本为空，记录1283..1285未包含在两个检查的界面包中。选定阶段的等级是独立DWORD `+0x1E534`；CF6C/CF77/CF87不传输它，因此持久奖励映射属于适配器。新闭环将1～4村 `ep0..15/dg2/st1` 映射grade1..16，将5村通信元组 `ep100/dg0..7/st1` 映射grade17..24；难度不参与。此前ep15/dg2/st0写grade23的运行样本现证明是奖励策略错误，不是合法里程碑。CF16行 `+0x20` 是角色等级，`+0x22` 是精确称号grade，两者不可分桶混写。

## 称号

- 登录、村庄、准备房、个人资料和结算界面统一读取角色持久化称号。
- 角色等级、宠物等级、通关评级和称号分别维护。
- 普通stage0通关保留当前称号；stage1超级Boss在任一难度通关后，1～4村16张地图依次授予P1～P16，5村8张地图依次授予R1～R8（第八图要求配套L8代码与资源），重复通关与较高称号保持稳定。
- 启动器的称号文本与图标使用各自的资源编号；下拉框已同步grade0～24原生中文文本，grade25～42明确标记原生文本为空。
