## 公寓／OzVill 入口调用链

公寓世界属于独立的 GS 场景边界。`C358/8 ENTER_OZVILL` 仅含包头。`C38D/28 REQ_MOVE_MINIROOM` 在 WORD+8 携带 `how_move`，在 +0x0A 携带 16 字节房主 ID；末尾两个声明字节未被已核实的构造函数初始化，必须忽略。`C38E` 成功条件为 BYTE+8=10，读取范围到 +0x6F，最短112字节；包括移动类型、房主／角色摆放数据、访问计数和两条固定 BoardNWall 记录。

公寓入口由C358及C38D请求驱动。单房主适配器从已配置角色资料构造C38E房主字段，房主身份与请求载荷分别校验。

房间对象加载是独立的 C392/C393 边界，见[单身公寓、家具库存与街区住宅](家具.md#kb-03-039-1)，不是主动发送 C424。相关本地构造结果不证明自有公寓角色可见进入、装修和远程访客角色的完整呈现。普通背包 C40A 路由另见[单身公寓、家具库存与街区住宅](家具.md#kb-03-039-1)。

### 单身公寓、家具库存与街区住宅

<a id="kb-03-039-3"></a>

<!-- BEGIN 03-039-3 -->

每日推荐采用本地玩法规则：UTC每日3次，同日同房主一次，每次成功为房主增加1点。C397承载结果码；C38E完整帧+64的QWORD保持为进入／恢复公寓时的房主推荐点载体。成功C397由客户端兼容入口递增当前公寓UI使用的推荐点QWORD；房主和其他访客在下一次原生C38E边界读取持久值。剩余次数为0时结果2优先；仍有额度时重复／自荐为1，成功为3。有地址房屋的完整帧+40／+44分别为到期时间和当前时间，使用同一UTC时区的十进制`YYYYMMDDHH`编码，房主与访客共用该房屋期限；无有效地址时两字段为0。街区购买按78个可购页面的目录分别校验金币与推荐点：金币为日价乘14（4200–14000），推荐点为30–300。本地消费规则在同一事务中扣除这两项费用并保存住宅；住宅有效期为购买后14天，UTC到期时间随购买记录持久保存；有效角色归属与 `(Town,Page,Slot)` 分别唯一。有效期内再次购买返回50，他人占用返回40。到期住宅退出街区和外观设置；购买空闲地址时原子释放相关过期占用并完成新购，家具及外围库存持续保留。旧住宅按原购买时间补齐期限。C36D/88只在对应页面呈现持久住宅：完整帧+24/+28为外观／招牌代码、+32为46字节文字、+78为房主UID、+80街区、+81槽、+82村庄、+83性别、+84占用状态100。C38D mode3使用当前街区中的房主UID进入对应公寓。

### 单身公寓、家具库存与街区住宅

<a id="kb-03-039-7"></a>

<!-- BEGIN 03-039-7 -->

住宅土地卡使用专属身份 `60000000`，由有效住宅的地址和租期生成卡片册土地页。购房、绑定、删除及到期以住宅事务为边界；历史有效住宅自动补齐土地绑定，地址、原购买时间和到期时间持续保留。SP卡 `12000001` 使用独立库存账本，住宅迁移、删除和到期保持其数量。手动删除在授权事务内读取并返回旧 `(Town,Page,Slot)`，删除住宅通过外键级联清除土地绑定，并保留免费公寓、室内家具布局和外围装饰库存。提交后向旧村庄／街区的在线玩家（跨频道、包含同页房主）排队C372原生重置；既有房间访客保持当前会话。新页面住宅快照读取数据库有效记录；旧街道UID的C38D mode3返回普通失败，mode1自有公寓／mode2按名字访问继续可用，重新购房恢复街道入室路由。显示字段、删除结果码与地块重置链见[公寓土地页与首次引导完成](房屋归属.md#kb-08-054-1)。当前验证等级为静态链闭合与适配器构造验证；运行验收覆盖弹框、卡片、售地牌即时刷新及跨频道可见性，租期到期刷新由独立生命周期管理。

### 公寓土地页与首次引导完成

`C3E7/12 → C3E8/140` 的mode30为土地页。`0x863790` 按完整帧BYTE+8分派、BYTE+9判断持有状态；`0x79C220 → 0x4170D0 → 0x846230 → 0x8469D0` 构造土地卡，读取BYTE+68／+69／+70／+71的频道索引、村庄、街区和槽位，以及DWORD+72／+76的到期／当前时间。日期为UTC十进制 `YYYYMMDDHH`；频道索引为当前频道减1。土地身份为 `60000000`，普通SP卡 `12000001` 使用自身册页。响应保留完整140字节及独立钥匙计数；住宅迁移和租期规则由[单身公寓、家具库存与街区住宅](房屋归属.md#kb-03-039-3)维护。土地删除由 `0x4F6F70` 构造 `C370/8`，`0x863790` 消费 `C371/12` 的DWORD+8：**1成功、0失败**。成功分支调用对话文本选择9/12，写控制器DWORD+11484（2871*4）=0、重建土地页空状态并继续；失败分支选择9/9并保持持有状态。

街区地块撤销使用 `C372/88`，不是空的 C36D。城镇分发 `0x531BD0` 的 case50034 在 `0x5320CA..0x5320DC` 调用 `0x41D7DC → 0x52CF00`；BYTE完整帧+82选择当前地块map里的槽，WORD+80=20在 `0x52D000..0x52D00B` 调用 `0x408BE8 → 0x511DB0`。该重置函数按地块类型将对象+88置1（普通可售地）或4，释放+36/+40/+44/+100/+380/+652等绘制／门／招牌对象，普通地块恢复 `Village_images\qz_village_house_sale` 资源，清房主显示文字并将旧房主UID（对象+108）置-1。移除分支读至帧+82，兄弟mode10分支读至+84；适配器保留88字节完整初始化载体，仅填WORD+80=20与BYTE+82=slot。该包不携带可用于客户端过滤的村庄／街区标识，适配器必须在旧地址的Town/Page与当前TownSceneActive作用域筛选玩家；响应C371先排队，后经既有广播通道发送C372。C36D消费者 `0x53DB60` 即便帧+84不是100也仍调用房屋状态2，故不能作为住宅删除载体。

当前验证等级为静态链闭合与适配器构造验证；运行验收范围包括土地页、街景和跨频道同步。

## 空地购房入口与窗口类型匹配

房屋更新入口为 `0x00C396C0 -> 0x0040E912 -> 0x00512410`。当前派生将虚表连接至 `0x00513690` 的192字节包装器，接入空地命中和mode1购房窗口；空地构造链为 `0x0052ACF0 -> 0x00513DC0 -> 0x0052BE80 -> 0x005119E0`。C36D更新已有地块，C38E处理所有权与街区状态。独立CHouseAgent_PopUp路径通过 `0x007C3926` 处理C36E，构造函数为 `0x0041254E -> 0x007C1A40`。

`sub_40DB6B -> sub_7E8980` 的工厂参数30在 `0x007E9626` 设置内部类型25；参数31在 `0x007E9699` 设置类型26。购房使用factory30／mode1，续租 `0x005DAAE0/0x005DAB7E` 使用factory31／mode2。C37B在 `0x0053205C` 查询参数30，经 `0x0041BC16 -> sub_7EBBF0 -> sub_41062C/sub_7EA900` 映射到类型25，再经 `sub_408F94 -> sub_7EC400` 查找活动窗口；命中时由 `0x0053206E` 返回 `0x00534C5C`。

当前购房组约定时保留 `0x0053207E` 的 `85 C0 74 3E` 余额让出分支，使相应分支跳至 `0x005320C0`，由 `0x4F6350 -> 0x4F6100` 消费余额、完成就绪并释放队列。原生／已登记旧编码 `85 C0 74 43` 精确迁移为3E，已有3E保持幂等；旧factory31购房包装器升级为factory30，未知站点触发安全拒绝。C37A/C37B及C36E/C36F保持原生余额和购房交互。

## 推荐与街区住宅

启动器的“数值与道具”页提供**公寓推荐点数**，默认 1000 点。首次应用初始化余额，修改配置后在下次启动生效；相同配置重复启动时保留游戏内消费及获得的点数。

- 每位角色每天拥有 **3 次推荐机会**，每日按 UTC 日期更新。
- 推荐对象为当前访问房间的其他房主，同一天每位房主接受同一角色一次推荐。
- 每次成功推荐为房主增加 **1 点推荐点数**，额度、去重记录和推荐点数持久保存；成功C396返回C397，启动器派生的客户端兼容入口在推荐者本地递增显示值。C38E保持进入／恢复公寓的状态边界，房主和其他访客在下一次正常进入／恢复公寓时读取持久值。
- 当当天推荐次数为0时，推荐请求统一显示“已用完3次推荐次数”；仍有额度时，同日重复推荐显示“不能重复推荐”。重复推荐弹框绘制资源定义的两行文本。
- 城镇空地的购买入口连接购房确认窗口，显示本街区所需金币、推荐点和当前余额；确认后提交对应地块的购买请求。窗口占用输入时保持单一确认流程。
- 购房按所属街区分别校验金币和推荐点：78 个可购页面的费用为 **4200–14000 金币、30–300 推荐点**。本地玩法在购买时扣除对应金币和推荐点，统一保存住宅归属；每次购买取得 **14 天街区住宅使用期**，每位角色在有效期内拥有一个地址，每个地址对应唯一房主。
- 已有有效住宅时，购买其他地块会提示已经拥有房屋，当前住宅到期后可再次购买；他人已占用的地块显示已售出提示。
- 到期时间按购买时刻持久保存，重新登录继续计算剩余时间。期满后可重新购买空闲地块；室内家具和已购买的外围装饰库存持续保留。现有住宅按原购买日期补齐 14 天期限。
- 家具按目录 `inter._D3` field5 的使用期限持有：发放、购买与领取写入真实到期时间，同一款式按目录天数在原有期限上叠加，旧的无期限行以本次发放起算；到期后该实例从家具背包、容量与装修实例校准中一并移出，摆放记录随实例消失。目录期限为 0 的家具保持永久。
- 住宅按实际所属村庄、街区和位置显示，跨场景、跨频道及重新登录均使用同一份归属记录。
- “我的公寓”提供个人室内空间；街区住宅提供对应的户外入口和外观展示。

## 土地卡片闭环

- 成功购买街区住宅时，在同一事务中创建住宅归属、扣除费用、发放一张土地卡片并绑定村庄、街区、地块和租期。
- 每个角色同时只保留一张有效土地卡片；卡片在卡片册土地分类中显示。
- 删除土地卡片在同一事务内取得旧地址并释放街区住宅／土地绑定；角色继续保留免费单身公寓、室内家具、外围库存及独立 SP 卡数量，不退还购房费用。
- `C370/8 → C371/12` 的原生结果是 **DWORD+8=1 成功、0 失败**。成功分支立即清除土地页持有状态，不依赖重开卡片册；重复、未授权删除返回失败，畸形长度请求不产生响应或修改。
- 成功提交后，适配器向正在原地址村庄／街区的在线玩家（包括其他频道）发送 `C372/88` 的原生地块重置事件：WORD+80=20、BYTE+82=槽位，其他载荷清零。该事件释放房屋、门及招牌并恢复售地状态；不能用空 `C36D` 代替。其他村庄、其他街区、离线或室内玩家不接收这条街景事件，也不强制切场景。
- 新页面快照只读取仍有效的住宅；已删除房主的旧 `C38D mode3` 街道 UID 返回普通失败并保留当前场景。`mode1` 自有公寓和 `mode2` 按名字访问继续可用；再次购房后恢复土地卡和街道入室路由。
- 住宅租期届满时，土地卡片和地址绑定一并失效；家具、外围装饰库存和免费单身公寓继续保留。
- 现有有效住宅会在数据库初始化时补齐土地卡片绑定，确保历史住宅与当前规则一致。
