# 城镇／NPC DIY：修道僧

本主题维护自定义NPC的位置、场景图像、名称、输入、对白、立绘和返回位置。地宫身份、战斗与进度归[地宫 DIY：修道僧破关](../../地宫/关卡与房间/修道僧破关.md)。客户端程序及资源的派生、安装和恢复统一归[四村对白安装](../../../指南/客户端二进制补丁/修道僧四村对白安装.md)。

## 位置与场景渲染

VIL记录使用`(village+1)*10000+page`定位。50×36格点的单元步幅为36字节，type1／WORD+14定义可走性。梧桐和萨恩位置的中心及四向12像素采样值均为0；场景派生保留前四村道路、碰撞、交通与格点数据。

修道僧置于VIL第1层，与城镇角色共同按世界Y排序。`0x9DBA60`按placement层号调用`0x40FB69 → 0x9DCA40`，后者经`0x417184 → 0x4D7B50`比较对象Y并插入绘制链。梧桐位置位于Y168栏杆前方，萨恩位置位于住宅碰撞区外。

四村场景EFF分别引用独立角色图像、共用阴影和中文名牌。排序根Y为中心Y+26；阴影、身体、名牌的EFF Y常量分别为0、-43、11，三者世界位置与命中中心保持一致。身体局部底边y=93，半高50，`-43-50+93=0`，与阴影中心共同落在排序根。场景对象更新链为`0xAB5FB0 → 0xAC1BC0`，角色脚底计算点为`0x4FCCC0`。地图与四个EFF构成同一安装事务。

## 名字的文字渲染

场景名牌使用生成后的IM3，中心锚点与46×24尺寸固定。中文“修道僧”采用13号宋体、白色字面、1像素深棕色描边`RGBA(90,24,0,255)`，中英文间距2像素。

英文MONK沿用`vill_npc_monkname.im3`的金色像素字形和描边。有效范围为x9..30、y12..18，裁取22×7后以最近邻转换为22×8；最终名牌按整数像素居中。中文和英文分别维护字形来源、轮廓和透明度，摘要由场景资源清单登记。

对白中的名字由引导框文字接口绘制，文本归`manifest/monk_localization.json`。场景名牌与对白名字具有各自的渲染入口，共享“修道僧”这一显示名称。

## 命中与输入

命中矩形为中心X±24、Y±48。村庄更新`0x527CCD`接入点击控制器；资格要求当前村庄／出口页面匹配、光标对象有效且背景输入可用。

`0x52AA50`把鼠标坐标写入村庄`+0x334`指向的光标对象。`0x52A751`在原`0x527C80`更新完成后复核命中，经`0x402770 → 0xAB35E0`设置手形1；门类光标编号为5。窗口按钮使用其原生光标。

输入快照由`0x41F861 → 0x52A520 → 0xAD04E0`更新。左键按下沿条件为`+0x21C=0x80`且`+0x22C!=0x80`，每次按下产生一次开窗动作。`0x415ED3 → 0x4EA7A0(0)`对应左键松开检测，适用于需要松开语义的独立控件。

## 对白分页与窗口生命周期

对白窗口分配0x400字节，在`+0x200`内嵌0x16C字节引导对象。`0x4163BF → 0xA12610`构造，`0xA12CC0(0,0)`载入底部引导框及下一页／结束按钮。正文每页四行，每行51字节，GBK内容上限48字节并以NUL结尾。

`0xA13C00`设置框体中心`400,300`、名字`60,474`、正文`61,507`、按钮`479,550`。按钮经`0x414353 → 0x7B2470`更新、`0x4169A0 → 0x7B2630`命中，返回5推进；Enter使用相同分页逻辑，Escape关闭。入口对白末页在来源校验通过后进入本村挑战，结果对白末页完成关闭。

窗口`WORD+0x34`使用1表示打开／翻页、2表示关闭。回收器`0x7EC5C0`在`0x7EC5F2..0x7EC5F7`消费虚表`+0x0C`返回值；当前回收函数`0x6E4600`仅对关闭状态返回1，随后经`0x7EC605 → 0x4123A0 → 0x7ECD70`摘链，`0x7EC644`调用析构。析构顺序为`0x41B6A8 → 0xA12790`释放引导对象资源，再由`0x4D7830`释放窗口。

普通窗口绘制点为`0x527852`，修道僧窗口采用独立的最终UI绘制点`0x5278F1`：反向遍历窗口链，对虚表匹配且状态为1的窗口绘制一次正文与立绘，然后经`0x41CB16`绘制光标。顺序为城镇及聊天／HUD、修道僧对白、光标。

## 立绘与动画

四村使用`effs/interface/NPC_62_0.eff`至`NPC_65_0.eff`。每项EFF2含三行，依赖对应的`NPC_N.im3`与`NPC_N_b.im3`；图像尺寸230×300、IM3 v2，格式分别为10和8。12项文件共同登记于场景资源清单。

`INIT_PORTRAIT=0x739080`接收ECX引导对象、EDX村庄0～3，分配0x144字节并经`0x41BE00 → 0xAB6910`构造`CPtcGrp`，由`guide+0xF4`持有。`0x404232 → 0xAB6B60`使用五参数`(path,0,400,300,0)`加载本村EFF，位置沿用`guide+0x12C/+0x130`。村庄与分配结果通过校验后才提交肖像槽。

原生`0xA12EC0`按`guide+0x118`与数量生成`interface\NPC_%d_%d.eff`。当前独立加载接口保持中文名字与村庄立绘的确定对应关系。每帧先调用肖像虚表`+0x10`一次，再更新框体，推进透明度和滑入轨道；`0xA13630`经`guide+0xF4+4*guide[0x14C/4]`的虚表`+0x14`绘制，当前索引为0。原生析构负责释放`guide+0xF4/+0xF8`。

## 来源坐标与返城

入关前从村庄`+0x3B0`本地角色读取坐标，以角色UID等于MyInfo UID、地图type1可走为条件冻结村庄、页面与位置。原生回村`0x53CE10`匹配冻结来源和挑战入口后恢复坐标，继续C365/C367/C368场景生命周期。

胜败对白消费当前角色、当前挑战代次的结果，并在回到原村庄／页面后获得一次显示资格。具体状态转换归[胜利与失败后续对白](../../地宫/关卡与房间/修道僧破关.md#胜利与失败后续对白)。

## 配套合同
