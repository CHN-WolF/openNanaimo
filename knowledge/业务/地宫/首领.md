## L8 Boss 血量来源与同阶段比较

L8保留韩服资源的HP字段，MMO300→CN200转换维持字段语义，按所选单槽执行一次百分比缩放。`ep23_ending_00.mmo`的正HP行为ordinal0／2、type2，各1,500,000；`ep23_bbm_00_00.mmo` ordinal12及`ep23_bbm_01_00.mmo` ordinal11均为type3，各2,000,000，三份MMO的完整字段／事件模型在韩服原文件和当前安装文件间一致。两份SSTG仅逻辑身份按既定映射更改，九槽HP百分比均保留韩服值255；两份BMO逐字节一致。按每组件`rawHP * percent // 100`一次缩放后，stage0为两个3,825,000组件、合计7,650,000；stage1两模式各5,100,000、通关累计10,200,000。stage1不是单模式10,200,000，不能与别关单模式混比；三难度／九槽相同，槽位是替代选项。

| L1、L2、L4 | 476,280 | 617,464 | 16.062／16.519 |

当前L7采用韩服战斗目录及255%倍率，stage0为3,060,000，stage1两模式合计4,289,329，三难度共18槽逐项一致。L8与L7按同阶段资源账本比较，分别为2.5／约2.378倍；部件生命周期与实际击杀时长按各自战斗规则评价。

L1–L8共144个Boss槽配置，L8的18个配置按正HP组件核对。stage0以7,650,000为初值，按权威伤害逐次扣减，D012/60的`+0x28`返回剩余HP；例如伤害1478−572=906后剩余7,649,094。241次有效更新累计伤害214,971时，剩余7,435,029，满足初值守恒。4项主机测试覆盖资源模型、目录及扣减关系；字段消费与缩放链由[本主题对应章节](首领.md#kb-08-041)维护，验证等级为资源一致性及本地HP构造。

### 接触伤害与零生命附件

Boss接触攻击目录与可击杀组件账本分别维护。零HP危险部件按自身精确攻击值结算玩家受伤，其生命、部件终结、Boss总生命与奖励状态保持各自生命周期。L7超级Boss的机械手、锁链及同类零生命附件继续依附所属Boss阶段；子弹连续命中保持附件存续，阶段与Boss完成沿既定退场边界处理。

资源分类保留正HP根附属部件、冬季本体、地宫3-3门框及独立退场对象的作用域。专项覆盖24,443个保留型零HP部件身份，包含L7超级Boss第一形态九槽共810个零HP身份；重复弹击与肉弹边界保持原有生命及终结状态。kind70玩家受伤保持整个Boss上下文一致。1,278个形态的正生命组件完成检查覆盖864次最终终结及414次中间阶段切换。接触数值与跨地宫覆盖归[业务／宠物／索引](../宠物/索引.md)，客户端场景验收归[本主题对应章节](首领.md#kb-09-020-11)。

### 地宫3-3零生命门框

hd0／episode2／dungeon2／stage0／mode0的九个槽，SMMO绑定`ep03_st03_e_gate_l.bmo`（槽0..5）或`_m.bmo`（槽6..8）。child0的`ep03_st03_e_gate.mmo`仅有ordinal0、type4、原始HP0；child1的`ep03_st03_e_gate_00_L/M.mmo`含两个正HP type3发射部件（ordinal0/1）及两个零HP附件；child2的`ep03_st03_e_gate_mon_23_L/M.mmo`有三个正HP type2召唤怪。资源名ep03对应通信episode2；门框采用零生命附件身份。

当前适配器策略仅对此精确元组抑制门框受击产生的独立D012终结，保持其HP及Boss总量不变。child1两个正HP部件都归零的同一次伤害请求中，先发D013/96清理child0门框，再沿既有路径清理child1并发D012；child2的生命、终结及奖励独立维护，最终结算由完整终结条件控制。门框清理按mode／battle ledger单次发送，新战斗重置；弹击D011及kind40接触共用该规则。冬季Boss保留规则、其它零HP目标及普通D00D账本分别按原有作用域维护。72条生产构造路径与验证范围见[本主题对应章节](首领.md#kb-09-020-11)。

### 通用组件账本

Boss 正生命组件账本限定在 `(battle epoch, mode, authored child, authored ordinal)`。每个组件拥有独立 `component_hp`；弹击与肉弹均以精确部位身份同步组件、child与当前mode生命，伤害钳制到命中组件剩余HP。首次归零产生一次组件终结，重复报告保持幂等。新mode与新战斗清理运行时部位绑定。普通 runtime UID 怪物、runtime/deform、crate 与 Boss 账本继续相互独立。

共享Boss账本的选图与阶段重置受当前房间成员资格约束。`boss_hp_sync_select_stage`初始化phase为PREPARED(1)、profile_kind为LOOKUP_MISS(7)，并清理HP与profile；D011/32仅在合法战斗阶段计算伤害，其余阶段返回BAD_PHASE(-2)。活跃房间门控在非成员请求进入上述重置前完成检查，保持现有Boss伤害账本。隔离范围归[业务／地宫／索引](索引.md)，验证层级归[本主题对应章节](首领.md#kb-09-020-11)。

火焰宝珠 `hd0/ep4/dg2/st0` 的本体与冰棱均计入当前mode总生命，每个有效命中即时发布总剩余量。各部件独立扣血、独立终结，普通生命更新使用中性部件选择值255；组件首次归零使用精确child／ordinal。该范围使用通用组件账本，覆盖九个资源槽及伤害截断、重复终结和最终结算。

同一子对象的平行分体 Boss 按独立组件生命结算，阶段剩余量等于全部存活组件生命之和。D012 +0x28 发布当前阶段总剩余量，客户端血条的零值判断与宽度统一读取该权威值。UI关卡1地宫1包含两个2000生命组件，总量4000；地宫1-2、1-3的三分体依次保留2/3、1/3和0的总生命比例。单次伤害以命中组件剩余量为上界，全部组件归零后完成阶段。局部首元组按既定首个存活组件规则解析，明确的后续序号保持精确寻址。

多模式 Boss 的内部 `c->hp` 是当前 mode 账本，`result.hp` 可保留当前加后续 mode 的总剩余量，但两者不能无条件当作终结时的客户端 recording。原客户端要求当前 mode 结束的 D012 `+0x28==0` 才授予完成许可，更新循环还再次要求 recording 为0才推进 mode；此前把未来6000留在这里导致组件爆炸后永不换阶段。wire `+0x28` 按当前 mode 账本发布（`mode_recording_hp`）；中间终结处该账本为0，编码器直接发布该值，聚合保留在 `hp`/`cumulative_damage`；states、奖励、排名和 HP/MP 回复增量全部为0，`awaiting_next_mode` 不提前结算。中间终结使用64字节并显式初始化排名尾部，覆盖其他 episode 的条件读取。一次请求只构造一次响应，不补推后续阶段数据。

跨 mode 总血条完全连续的旧承诺已撤回：阶段终结发送0后，下一 mode 初始化可能重置血条。正确换阶段与显示层连续总条是两个边界，后者需单独支持，不再用正 recording 绕开原生终结条件。当前失败 slot7 的构造、重复报告隔离和发送函数回归通过；修复后原客户端自动进入下一 mode 仍待验收。

当前资源审计覆盖1,278个mode，其中348个为多部位mode；弹击与精确接触分别覆盖2,642种完整击杀顺序，关卡4地宫1与超级Boss各路径另覆盖45,414种击杀排列。专项验证独立HP、组件／child／阶段终结、运行时绑定重置与重复报告幂等。普通三组件场景已有原客户端可见观察；其余 mode 保持对应构造验证范围。

## 肉弹与Boss接触边界及验证限制

Kind40接触使用精确mode/child/ordinal，同D011共享部位终结账本。当前模式完成后，携带下一连续模式、合法child和正生命ordinal的肉弹接触可直接推进模式并扣减命中部件生命；模式、部件与正伤害校验在账本变更前完成。伤害以上限钳制，最终结算按战斗周期去重。泛用外部组件伤害仍限定当前模式，肉弹保护周期由[业务／宠物／索引](../宠物/索引.md)维护。普通type4对象退场、组件D013、聚合最终D012和CF87/CF88保持独立边界。

构造验证覆盖角色选槽、191个Boss重放、别名、零子拓扑、身体／冰霜指令、ep7及状态周期；这些结果只适用于各自受测构造。单次运行中的CF88不能证明所有技能或release均已通过客户端验收。

血条兼容修改将绘制器 `0x742DC0` 的判零及宽度计算统一到对象 `+0x10C`，该字段由初始化和权威生命更新维护。阶段最大值保持对象 `+0x104` 的资源总量。当前与未来阶段分别建账，当前阶段归零按既定完成门控推进。三分体专项覆盖地宫1-2／1-3全部三种难度的过量伤害、精确组件终结与剩余量；局部指令检查覆盖本地估算为零、负值及过量值时的显示选择。

### 冬季持久体资源和回收闭合

## 超级 Boss 的 mode 推进门控

D012 `+0x28` 通过 `0x6EC979 ->0x401050 ->0x6BF200` 写入 Boss recording `+0x18`。包值为0才进入 `0x6ED62D ->0x6ED63C ->0x40B5DC ->0x680F30`，设置完成许可 `Boss+8=1`。组件退场／爆炸不替代 mode 推进：`0x6BE8C4..0x6BE8F7` 还要求许可、资源节点 `+0x208` 和 `Boss+0x18==0`；`0x6BE9D2` 要求计时严格超过2000ms，随后 `0x6BEA2B ->0x4093F9 ->0x6BE120` 递增 mode。中间终结的 states0 不进入成功结算。episode≥16 的零 recording 分支还可能在 `0x6EE121/0x6EE1A6` 读取 `+0x3C+slot`，故中间终结响应按64字节覆盖四个显式零排名。

46项x86条件验证覆盖recording及外层对象／动画门控。中间终结帧 `+0x28` 使用当前mode账本 `mode_recording_hp`，阶段边界为0；聚合HP与累计伤害保存在 `hp/cumulative_damage`，后续阶段由客户端请求推进。
