## 接触伤害与零生命附件

首领接触攻击目录与可击杀组件账本分别维护。零HP危险部件按自身精确攻击值结算玩家受伤，其生命、部件终结、首领总生命与奖励状态保持各自生命周期。L7超级首领的机械手、锁链及同类零生命附件继续依附所属首领阶段；子弹连续命中保持附件存续，阶段与首领完成沿既定退场边界处理。

- 资源分类保留正HP根附属部件、冬季本体、地宫3-3门框及独立退场对象的作用域。
- 专项覆盖24,443个保留型零HP部件身份，包含L7超级首领第一形态九槽共810个零HP身份；重复弹击与肉弹边界保持原有生命及终结状态。
- kind70玩家受伤保持整个首领上下文一致。
- 1,278个形态的正生命组件完成检查覆盖864次最终终结及414次中间阶段切换。
- 接触数值与跨地宫覆盖见[角色伤害和得分](../伤害与目标/入伤与协议.md#kb-04-013)，客户端场景验收归[验证状态](../../../工程/验证状态.md)。

## 地宫3-3零生命门框

- hd0／episode2／dungeon2／stage0／mode0的九个槽，SMMO绑定`ep03_st03_e_gate_l.bmo`（槽0..5）或`_m.bmo`（槽6..8）。
- child0的`ep03_st03_e_gate.mmo`仅有ordinal0、type4、原始HP0；child1的`ep03_st03_e_gate_00_L/M.mmo`含两个正HP type3发射部件（ordinal0/1）及两个零HP附件；child2的`ep03_st03_e_gate_mon_23_L/M.mmo`有三个正HP type2召唤怪。

- 资源名ep03对应通信episode2；门框采用零生命附件身份。

- 当前适配器策略仅对此精确元组抑制门框受击产生的独立D012终结，保持其HP及首领总量不变。
- child1两个正HP部件都归零的同一次伤害请求中，先发D013/96清理child0门框，再沿既有路径清理child1并发D012；child2的生命、终结及奖励独立维护，最终结算由完整终结条件控制。
- 门框清理按mode／battle ledger单次发送，新战斗重置；弹击D011及kind40接触共用该规则。
- 冬季首领保留规则、其它零HP目标及普通D00D账本分别按原有作用域维护。
- 72条生产构造路径与验证范围见[验证状态](../../../工程/验证状态.md)。

## 通用组件账本

### 组件生命与幂等

- 首领 正生命组件账本限定在 `(battle epoch, mode, authored child, authored ordinal)`。
- 每个组件拥有独立 `component_hp`；弹击与肉弹均以精确部位身份同步组件、child与当前mode生命，伤害钳制到命中组件剩余HP。
- 首次归零产生一次组件终结，重复报告保持幂等。
- 新mode与新战斗清理运行时部位绑定。
- 普通 runtime UID 怪物、runtime/deform、crate 与 首领 账本继续相互独立。

### 选图与房间资格

- 共享首领账本的选图与阶段重置受当前房间成员资格约束。
- `boss_hp_sync_select_stage`初始化phase为PREPARED(1)、profile_kind为LOOKUP_MISS(7)，并清理HP与profile；D011/32仅在合法战斗阶段计算伤害，其余阶段返回BAD_PHASE(-2)。
- 活跃房间门控在非成员请求进入上述重置前完成检查，保持现有首领伤害账本。
- 隔离范围归[业务／地宫／索引](../索引.md)，验证层级归[验证状态](../../../工程/验证状态.md)。

### 本体与冰棱

火焰宝珠 `hd0/ep4/dg2/st0` 的本体与冰棱均计入当前mode总生命，每个有效命中即时发布总剩余量。各部件独立扣血、独立终结，普通生命更新使用中性部件选择值255；组件首次归零使用精确child／ordinal。该范围使用通用组件账本，覆盖九个资源槽及伤害截断、重复终结和最终结算。

### 平行分体与阶段总量

- 同一子对象的平行分体 首领 按独立组件生命结算，阶段剩余量等于全部存活组件生命之和。
- D012 +0x28 发布当前阶段总剩余量，客户端血条的零值判断与宽度统一读取该权威值。
- UI关卡1地宫1包含两个2000生命组件，总量4000；地宫1-2、1-3的三分体依次保留2/3、1/3和0的总生命比例。
- 单次伤害以命中组件剩余量为上界，全部组件归零后完成阶段。
- 局部首元组按既定首个存活组件规则解析，明确的后续序号保持精确寻址。

### 当前mode与聚合生命

- 多模式 首领 的内部 `c->hp` 是当前 mode 账本，`result.hp` 可保留当前加后续 mode 的总剩余量，但两者不能无条件当作终结时的客户端 recording。
- 原客户端要求当前 mode 结束的 D012 `+0x28==0` 才授予完成许可，更新循环还再次要求 recording 为0才推进 mode；此前把未来6000留在这里导致组件爆炸后永不换阶段。
- wire `+0x28` 按当前 mode 账本发布（`mode_recording_hp`）；中间终结处该账本为0，编码器直接发布该值，聚合保留在 `hp`/`cumulative_damage`；states、奖励、排名和 HP/MP 回复增量全部为0，`awaiting_next_mode` 不提前结算。
- 中间终结使用64字节并显式初始化排名尾部（该条件覆盖规则优先于普通D012/60长度），覆盖其他 episode 的条件读取。
- 一次请求只构造一次响应，不补推后续阶段数据。

### 血条连续性限制

- 跨 mode 总血条完全连续的旧承诺已撤回：阶段终结发送0后，下一 mode 初始化可能重置血条。
- 正确换阶段与显示层连续总条是两个边界，后者需单独支持，不再用正 recording 绕开原生终结条件。
- 当前失败 slot7 的构造、重复报告隔离和发送函数回归通过；修复后原客户端自动进入下一 mode 仍待验收。

### 资源与构造覆盖

- 当前资源审计覆盖1,278个mode，其中348个为多部位mode；弹击与精确接触分别覆盖2,642种完整击杀顺序，关卡4地宫1与超级首领各路径另覆盖45,414种击杀排列。
- 专项验证独立HP、组件／child／阶段终结、运行时绑定重置与重复报告幂等。
- 普通三组件场景已有原客户端可见观察；其余 mode 保持对应构造验证范围。

## 终局整组回收的完成状态保护

Boss组件完成退场动画后进入终结状态。终局整组回收会再次遍历同一child的对象；旧保护只跳过中间状态，已完成动画的对象仍可能再次创建退场效果，导致最后一次终结出现重复爆破声。当前兼容策略将终局效果保护扩展到全部已完成退场状态：首次归零仍正常播放，已完成退场的对象不再重复创建效果。Boss生命、奖励、模式推进和组件回收规则保持独立。

一村地宫3-1的当前资源元组为`hd0/ep2/dg0/st0`，三喷火部件使用`ani_mon_um_03_02_L/M.mmo`；九个槽为替代选项，不合并。MMO共26行：正HP本体ordinal7／16／25分别绑定`fly_mon_mb_burst.wav`，其7／8／8个零HP type4附件通过`+0x198`关联各自本体并绑定`fly_mon_m_burst.wav`。一次精确本体退场可分别调用8／9／9个对象的效果路径；并非需要8／9／9次重复死亡回包。三个本体还各有三个非空退场效果槽，附件各一个。大魔王大门对应地宫3-3、`hd0/ep2/dg2/st0`：child0门框一行、child1两个正HP喷射部件和两个无声音附件、child2三个正HP目标，六个带声音对象均使用`fly_mon_mb_burst.wav`，各有独立生命周期。门框在两个喷射部件都终结后退场，策略和九槽构造检查见[地宫3-3零生命门框](协议与部件回收.md#kb-06-020)。大门没有三喷火资源那样23个关联音效附件，不能把两者的扇出量混用。

用户描述的“一村地宫3分别打爆正常、彻底终结特别吵”与该生命周期边界一致。三喷火本体分别拥有多个关联退场对象；每个本体单独终结时按资源关系播放一次，最后一个本体完成全场终结时会触发child级整组回收。补丁后，已完成退场的本体和附件不会在最后整组回收中再次播放，首次终结效果和资源表现保持不变。大魔王大门沿用相同的完成状态保护。

同类多对象Boss资源沿用相同的完成状态保护，首次部件终结与终局整组回收分别处理。
