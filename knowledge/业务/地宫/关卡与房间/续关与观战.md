## 组队续关与观战

阵亡成员保持接收房间更新的观战状态，主动道具、技能和拾取按死亡状态限制。最后一名参战者提交失败结果且全队生命归零时，同房已阵亡观察者同步进入失败结算；各角色结果按会话、战斗周期及结算周期单次发布。失败页面允许阵亡角色直接返回城镇，重新挑战仍使用原有显式授权。

- 下一地宫动作由当前房间的一位发起者授权。
- 同房同关卡组员共享该动作的确认，保留过渡期连接，并以各自战斗周期校验状态更新；并发继续保持一个房间动作，拒绝时恢复组员原授权。
- 每次有效续关同时更新所有活动成员的地宫、实际阶段、显示阶段和难度，重置上一场的加载屏障及最终开始确认。
- 队员的连接局部状态在后续请求前切换到新关卡准备阶段，队长取得关卡资料时为队员建立新的预加载周期；队员通过自己的资料请求或对应房间初始化完成加载。
- 当前成员的CF70资料刷新保留已下发的预载授权，成员退出、新入房与连接代次变化分别清理授权。
- 离场、断线及连接槽位重新分配按成员代次清理续关状态。
- 当前续关仅在本房存在已观察到CF99的有效连接时执行前置清理，而且只对标记成员发送CF6D，再向活动成员发送CF8C；正常存活续关及没有CF99的死亡重试均不重新触发首次入房。
- CF99掩码在连接复用、房间创建及离场边界清理，成员离线／离房不触发或接收前置清理，一个成员的CF99不能重置未标记队友。
- CF6D的成功状态为BYTE+8，独立BYTE+9按当前房间身份写房主1／队员0，DWORD+0x10使用当前房主UID，本地角色UID使用既有身份；托管成功门控只读BYTE+8，成员仅在房间续关授权下接收该初始化，队员发起时被标记的房主仍可收到+9=1。
- CF6D会额外发起首次入房P2P／成员资料流程，不得把它当作通用、无副作用的续关初始化。
- 本人主动CF70对应的本地CF71结束过渡离场保护。
- 新阶段中的阵亡成员按[死亡返回与重试资源策略](../战斗资源/快照与资源继承.md#kb-07-020)建立部分生命、保留剩余魔法并重置火力与死亡状态，资源冻结持续到对应加载初始化；保留控制器的CFEB／CFEC续关维持已建立的情侣用药身份。
- 掉落与评分的角色归属分别见[拾取资格](../掉落/领取与结果队列.md#kb-07-002)与[地宫计分](../计分与结算/击杀计分与评级.md#kb-07-009)。

## 连续挑战的初始化与战斗控制器生命周期

- 正常连续挑战使用CF8B mode2与CF8C结果重载链，重试／挑战超级首领使用mode1。
- CF6D对已收到CF99的成员定向发送并清理返城状态；其CFD1/CFD2与CF8C重载各自触发C587/CF70。
- 适配器在每次有效续关开始时为活动成员重置资料合并状态，为实际发送CF6D的成员启用一次性合并：第一轮CF70发送完整名单；第二轮保留本人的CF72、全部队友CF71及准备状态CF7E，并复用第一轮本人CF71完成的位置初始化，然后解除合并。
- 后续显式刷新、其余队友及房主变化的完整名单推送保持原行为。
- 新续关／新房、离场和连接复用清理旧合并状态，以成员及房间生命周期决定合并资格。
- CF71本地分支直接写坐标：槽位0的初始Y为252，入场目标Y为151；单次本人坐标初始化保持入场位置与座位字段连续性。
- 地址与字段边界归[房间角色、加载、地图和继续条件门控](加载与开战.md#kb-08-023-1)。

- 成员离场采用完整清理路径，正常续关采用结果重载路径。
- 验证覆盖UID4单人三轮工作进程加载、P2P先到／结果重载先到的两种请求顺序、双人普通／超级地宫三轮、CF99成员隔离、第二轮队友／资源／准备状态保留、本人坐标单次初始化、资源恢复、S2C序列环、checksum及request-low。
- 该范围为适配器状态机构造与工作进程集成；客户端联合验收范围归[验证状态](../../../工程/验证状态.md)。

- 槽位0入场位置为`(77,151)`，重复执行本地CF71会将其重写为`(77,252)`。
- 结果页发布时旧战斗控制器可处于state9／退出动画state2；该退出动画的清理会关闭world运行位并将控制器转回state1，而应用页面可仍为战斗页4。
- 连续挑战在结果重载边界复位旧控制器，使新关开场沿独立生命周期运行。

- CF88兼容入口直接发布结果页后，旧战斗控制器的终局状态可能跨地图保留。
- 当前实现把原生reset放在合法CF8C的普通结果重载边界：mode0/1、结果页6、目标state7且旧实例存在时执行，然后调用原重载。
- CF8C维持48字节约定，角色及HP/MP/P沿既有资源恢复链处理。
- 位点、字节、调用约定及安装步骤归客户端二进制补丁文档。
- 验证覆盖3项客户端迁移、160种控制条件组合、5轮原指令隔离及8项工作进程续关检查；发布及客户端验收范围归[验证状态](../../../工程/验证状态.md)。

## 结算页等待与动作授权

结算页等待与动作授权

- 结算的两个控制器分别具有本地timer，action-state5属于鼠标确认路径。
- `--dungeon-state` 关闭两处自动倒计时并恢复鼠标确认；普通关卡继续、第三关超级首领挑战与最终页重试由玩家输入驱动。
- CF88完成原生结果排序后，普通地宫战斗控制器进入已初始化的评分页；观战成员同步使用该入口。
- 进入评分页时将键盘及鼠标的上一帧快照更新为当前输入，确认使用评分页上的新输入变化。
- 适配器按`SettlementAwaitingAction`、合法的存活或失败重试状态、完整12字节CF8B及mode1/2校验推进条件；失败只允许mode1同关重试。
- CF8B携带动作模式，输入来源由客户端控制器处理。

- 连续挑战保留房间与角色资源，切换到下一地宫时同步所有活动成员的完整准备房状态，并建立新的房间加载周期。
- 原生工作进程为队员同步关卡选择和连接局部加载阶段，随后分别完成资料、同伴连接及最终开始确认；续关状态以成员代次隔离，阶段流程见[房间、加载和多人同步](房间身份.md#kb-05-000)。
- 新战斗开始后生命、法力和火力继续按战斗规则更新；准备房与结算界面的主动回城保持独立。
- 超级首领成绩按实际关卡阶段持久化，显示阶段独立处理。

### 跨难度续关

普通地宫的`CF8B/12 mode2`有两个独立目标：普通阶段进入同难度下一副本；`dg2/st1`超级首领阶段的`real0`进入下一逻辑难度的`dg0/st0`。后者不是`dungeon+1`，目标资源必须存在。最高逻辑难度2、失败结算、非法阶段或不存在的目标不能授权升难度；失败重试仍走mode1并保留原元组。Lumineos `hd0/ep100`继续使用自己的下一副本策略，修道僧只允许同关重试，不套用普通跨难度规则。

逻辑难度低／中／高为0／1／2；普通阶段的difficulty选择器为2／0／1，`dg2/st1`超级首领为0／1／2。低到中时源超级首领选择器0与目标普通选择器0相同，中到高同样为1；不能仅比较difficulty WORD的数值判断有没有切难度。合法响应必须同时为`CF8C/48 real0/show0/dungeon0`，并将`WORD+0x2C`置为目标普通选择器。托管`TryResolveNativeDungeonTransition`校验目标副本、阶段和该选择器后才增加逻辑难度、保留续关授权并初始化重载；拒绝后保留结算动作，不放行后续过渡离场。

前一段`dg2/st0 -> dg2/st1`的mode1挑战也必须转换选择器域：普通2／0／1转为超级首领0／1／2，保持逻辑难度不变；同阶段重试不得再转换。原生同时更新连接difficulty、地图身份difficulty及资源槽位，托管验证CF8C的超级首领选择器，不接受把普通编码原样带入stage1。只从直接进入超级首领的夹具测试升难度，不能覆盖这条入口边界。

原生`gs_runtime.inc`先识别超级首领mode2边界，再更新地图与成员元组、重置加载屏障，并使用既有`C587/CF70 -> CFEB/CFEC -> CFD3/CFD5 -> CF7F/CF80`请求链。新槽位按目标选择器重新计算；无CF99时不追加CF6D或CF78，不提前下发CF80。资源冻结、死亡返回及成员代次沿本页既有边界处理。

静态证据：`0x708760`构造opcode CF8B与完整长度12，mode2发送器`0x6EA970`在`0x6EA981`写WORD+0x0A并在`0x6EA99A -> 0x40A821 -> 0x6E90C0`提交；结果输入函数`0x762A30`通过`0x4183F9`调用该发送器。CF8C消费者`0x6FBD28..0x6FBF61`消费BYTE+0x28/+0x29、WORD+0x2C/+0x2E，`0x6FBEDE -> 0x4170D5 -> 0x50A260`写全局difficulty `+0x1E528`；资源episode小于16才写副本选择，原有条件不变。原始IDA输出与宿主失败／修正后帧见[跨难度续关证据](../../../evidence/validation/dungeon-difficulty-transition-20261013/调查.md)。此处描述静态与适配器构造，不表示原客户端连续切难度已验收。

## 超级首领续战与客户端发起的退出

历史ep7/dg2客户端运行样本的退出顺序（其中child1为当时硬编码回收；当前实现已改为数据驱动）：

```text
D013 硬编码 child1 -> D012 final -> CF87/CF88 -> CF15/CF16
CF8B real1/show0/mode1 -> CF8C real1/show0/diff1/dg2
客户端 CF73 -> CF1D -> 适配器 CF1E/200

```
客户端在 CF8C 后发起离开；CF8C 长度48，消费字段 `+0x28/+0x29/+0x2C/+0x2E`，并与当前难度／副本一致。首领 生命周期在离开前完成所有子对象回收与资源 HP 边界结算。

当前构建使用数据驱动的子对象回收。结算构造覆盖 `CF8B → CF8C → C587 → CF70 → CFEB stage1`；后续分支由客户端请求选择。CF8B只携带阶段与动作模式，CF8C难度由已授权源元组和目标选择器域确定，不从CF8B读取不存在的难度字段。

## 结算续关标志与加载分支

- CF99发送调用0x66C190/0x66C6C9后写manager+7。
- setter thunk0x40D24C的已恢复xref为0x66C19E、0x66C6D7和0x70850D：前两者分别紧跟CF99发送并写1，后者由CF6D清0；这支持按实际收到的CF99登记连接门控，不以单纯阵亡代替该写入。
- CF8C在0x6FBE40..0x6FBE61检查该字节：非零进入结果控制器3，零走正常重新加载7。
- CF6D status10经0x6F7973 → 0x4067AD → 0x7084F0设置application+6，并经0x41781E → 0x708530清DWORD+8、经0x40D24C → 0x66E5E0清BYTE+7；但它不是无副作用的清标志包：0x6F7992 → 0x405AE2 → 0x6E9440发送CFD1并改网络控制器+0x7C；0x6F7B67..0x6F7B70还经0x403B70/0x72EFE0 → 0x416793/0x7366D0进入状态8。

- 44字节原生帧覆盖其直接消费的+8/+9/+0xA与+0xC..+0xE。
- CF78 status10在0x6F7EDA切换独立控制器8，清理发生在CF8C之后，不能修正已选中的离场分支；不能据此反推无CF99的正常续关也应补CF6D。

- CFD2回复在0x6F493A..0x6F4941调用0x417B02 → 0x6E94C0发送C587/CF70；CF8C的0x6FBF53..0x6FBF5C独立令结果控制器进入重载7，普通结果循环0x763FF0在0x7646E8..0x764738检查state7与+0x18门，再由0x764707调用同一发送器，随后进入state6。

- 另一结果循环对应调用点0x770100。
- 发送器的application+6门、12字节CF70构造0x708400/0x404165、+8取network-controller+0x7C及0x6E951B发送链保留；因此额外CF6D可以引入两轮真实资料请求，而不是仅客户端调试文本的重复打印。

- CF71本地UID匹配后，0x6F4FFA..0x6F500D无条件写X=-300，普通模式在0x6F504B..0x6F506D写Y=252+100×BYTE+0x56；另一模式为110+100×slot。
- 它不检查本地actor是否已经在移动，远程分支的已有对象门不能用于本人。
- CFDA已登记的入场目标为Y=151+100×slot，故slot0的迟到CF71可以覆盖正在去往151的本人坐标为252。
- 续关状态边界归[房间、加载和多人同步](房间身份.md#kb-05-000)，十个关键代码区通过当前客户端字节校验。

- CF8C完整48字节覆盖实际／显示BYTE+0x28/+0x29、难度WORD+0x2C、副本WORD+0x2E。
- +0x2C经0x6FBE94..0x6FBEE3与application当前难度比较，并通过0x4170D5 → 0x50A260写DWORD+0x1E528（getter 0x411ACC → 0x708550）；它不是房主UID。
- 资源周期小于16时读取+0x2E的既有条件不变。
- CF8B分支已将错误的“room-owner UID at +0x2C”注释纠正为difficulty WORD；构造器按difficulty写该WORD，不能把数值0误读为房主丢失。

- CF6D在0x6F795D读取BYTE+8成功状态；0x6F799D独立读取BYTE+9，经0x6F79AE／0x6F79BE → 0x409BC4 → 0x708C00写application BYTE+4房主标志。
- 下一次CF80的0x6F762B..0x6F766C通过0x402BDA → 0x708C20读取+4，再通过0x408D19 → 0x708C40读取+5：两者均非零时保留续关路径，其余组合进入准备房控制器state3。
- 44字节成功响应以两个独立BYTE分别表达状态和房主身份，房主标志按当前角色保留。
- 适用范围为角色身份和开战分支。

- 连续关卡资源恢复使用已授权CF8B/12与捕获CF8C/48的real/show BYTE+0x28/+0x29。
- 随后CFEB/12的WORD+8/+0xA必须逐项匹配；捕获CFEC必须完整808字节，BYTE+0x2DA/+0x2DB匹配同一real/show。
- NetworkAdapterService.DungeonContinuation在响应原顺序中完成解冻：CFEC前D010仍按结算冻结丢弃，之后D010/36由本地UID和WORD+0x10更新资源再转发；BattleResourceSnapshot.ForEpoch保留HP/MP/P，只重置冻结及HP优先级。
- 此为适配器源码／构造边界，不新增客户端反汇编结论；原客户端下一关可见扣血待验收。

## 续关授权与成员代次

- 多人地宫续关按房间代次、战斗周期和成员会话分别登记；房间完成有效下一阶段授权后，成员沿同一已确认阶段恢复，使用房间已确认的阶段身份。成员离场会清理其房间成员、战斗参与和准备态残留。
