## 拉米诺斯（Lumineos）身份、资源覆盖与L7／L8集成

### 身份与独立账本

- 保持普通D00D，消除重复项，使runtime/deform和BOSS D011/D012/D013独立。
- D00D没有数值伤害/生命值/致命区域。
- 适配器生命值计算需遵循适配器自定义策略，除非有独立的证明。

- 阶段身份使用`hd/episode/dungeon/stage/difficulty`（区域／章节／副本／阶段／难度），`slot=难度*3+阶段索引`。
- CF6C提供完整权威选图元组；快速入房或请求重载也可由有效CF77／CFEB建立对应身份，CF8B推进合法阶段。
- 地图、房间和战斗周期分别重置对应状态。

- 客户端一次只选择一个SMMO列表，生成目录的segment列表示替代资源槽；替代槽语义、选择/解析/遍历调用链由[普通目标、源攻击和选定资源 / 针对传入kind10身份的PON基础攻击](#kb-08-040-2)维护。
- 所选槽缺失时应保留依赖缺口，不能据此推导其他槽的运行语义。
- `st01_H_01` 骨骼依赖正确的 slot 查找。

### 通信与资源映射

- 拉米诺斯区分通信元组与资源元组。
- hd0/episode100/dungeon0..7的普通HP和BOSS查找使用资源episode16..23/dungeon0，第七副本阶段1使用ep22/dg1。
- 房间字段、CF6C/CF77/CF8C、阶段／难度、状态周期、选择器、SMMO选择及数值规则各自保持既定约定。
- CN基线资源含七个战斗关卡，当前选择性资源包另扩展L8；物理入口按页面独立管理；page18/index6/ep22具备加载结果，完整场景验收范围见[房间、加载和多人同步](房间身份.md#kb-05-000)，转换地址见[拉米诺斯战斗资源选择](#kb-08-035)。

### CN基线覆盖

- 拉米诺斯资源按关卡与阶段维护覆盖范围。
- CN基线资源包含ep16..22第一阶段SSTG/SMMO，对应08选择器转换下的入口1..7；未发现入口8..23所需ep23..38的SSTG/SMMO或剧集前缀SM2，五个分发ZIP索引也未提供额外阶段成员。
- 资源中仍有64个后续编号mb-object MMO（每集四个）、16个mb_T效果及一个ep23效果图像；它们属于独立对象及效果资源。
- 上述范围适用于CN基线；当前选择性资源包额外提供ep23。

### CN文本与缺失战场

- CN基线的 L8 文本和打包 UI 资源可直接识别，怪物精灵与战场根缺失；新增韩服样本含对应资源。
- AES 解码的 `GS._D20` 包含2346=`小曲奇/赤豆棒冰/拐杖糖`，2347=`奶油派/嘴唇糖果/蛋卷冰淇淋`，2348=`马斯特洛克`，2397=`打败马斯特洛克的收集者`，2419=`甜蜜危险的诱惑`。
- 构造函数6659D0将显示索引24与文本2419一起写入，并安装两个怪物列表字符串。
- `images/interface.pack` 包含记录291（40x30 D08村庄迷你图瓦片）和1267（26x26等级24/R8徽章）。
- 内容检查覆盖32,410文件、1,325,576,226字节和16个 NANA_PACK 容器；该次CN检查集中没有六种命名糖果、Mastlock 精灵／模型或 L8 战场图层／布局／根。

### 选择性资源包

- L7/L8选择性资源包与L8代码已完成集成及资源事务验证。
- L7“罗兰[Rolland]的秘密研究所”和L8“甜蜜危险的诱惑”各含两阶段、每阶段九个实际SMMO槽及怪物／BOSS／场景资源。
- ep22命名族639文件、25,143,357字节，CN同路径377项相同、225项不同、37项新增；ep23命名族624文件、25,268,068字节，2项相同、4项不同、618项新增。
- L8包含六种糖果怪物，加载图为`dg_intro_hd0_ep24.im3`，战场编号为ep23。
- 客户端玩法采用独立验收状态。

### 转换与依赖图

- 韩服AES解码及MMO300→CN200、PON108→CN106转换保持字段模型一致，密钥及地址由[韩服L7/L8资源字段、转换与布局边界](资源格式与转换.md#kb-08-034)维护。
- ep22／ep23命名族含224份MMO与91份PON；加入共享依赖后为243份MMO、98份PON，共341份。
- 243份MMO的1,378行及事件表通过CN x86记录读取器隔离解析验证。
- 结构检查覆盖4份SSTG、36个引用槽、15份命名族SM2及327份命名族EFF。
- 显式引用图L7为780节点／1,781边，L8为702节点／1,580边，已登记路径完整且唯一。
- 验证范围限定于已解析字段与显式引用；BMO固定记录、CRS几何和程序隐式依赖分别维护解析状态。

### 当前L7整关替换

- L7必须区分原生村庄/UI恢复与整关战斗版本替换。
- 163份L7 MMO/PON中124份字段模型与CN同名资源一致、39份不同；`ep22_bbm_00_00.mmo`及关联EFF在韩服为91行、CN29行，因此按韩服 ep22 怪物引用闭包统一替换，不能只覆写单个BOSS文件。
- 当前资源事务登记662个闭包节点、1605条引用，相较于前一公开资源配方更新263项，其中97个MMO、42个PON完成格式转换，3个SSTG修正逻辑身份（PON与SSTG各含一个兼容别名）；未进入闭包的共享资源继续保留CN。
- 启动兼容所需的stage1 SSTG和PON别名也登记为同一份韩服输出，避免兼容准备回退到旧CN别名。
- 资源身份及事务验证不等于客户端玩法验收，原始冲突及当前边界见[房间角色、加载、地图和继续条件门控](加载与开战.md#kb-08-023-1)，场景范围见[房间、加载和多人同步](房间身份.md#kb-05-000)。

### L8生成及验证

- L8资源与代码使用同一身份约定，验证范围为资源转换及适配器构造。
- 保持wire `hd0/ep100/dg7`与资源`ep23/dg0`分离，两份韩服SSTG逻辑元组分别从`0/1/0/0`、`0/1/1/0`改为`0/100/7/0`、`0/100/7/1`；保留st01实际引用的`dg01_st00`九槽名。
- `scripts/generate_lumineos_combat.py`从已校验的资源副本生成两阶段18个普通目标／BOSS配置，向DCC7增加936个普通资源模板、18个BOSS模板、36个正生命组件与10,440个运行目标模板；原表保留。
- 碰撞目录、PON106首部owner与行攻击、selected-slot地形关联和结算最大分同步生成，HP及攻击不通过硬编码大数或复用旧BOSS向量补缺。
- 生成器在保留的L7两阶段18槽上复读15,858条普通记录及585条BOSS组件，与旧表逐项一致；BMO仅支持本L8已核对的单child固定布局，BMO／CRS其他布局与BOSS实机行为采用独立验证范围。

## 拉米诺斯（Lumineos）战斗资源选择

- 独立入口索引：movement0x5000A0，情况166/167调用0x404A52（6/7）；`0x404A52 ->0xA74450`写入manager+0x5CC的字节，getter `0x403D19 ->0xA743B0`读取相同的字节。
- 结合下面的episode100转换，入口7/索引6选择资源ep22；入口8/索引7选择ep23；同一转换规则将入口23/索引22映射到ep38。
- `0x66EC30`通过常量0xC5F374 `hd%d_ep%02d_dg%02d_st%02d.sstg`格式化射击资源的getter。
- 归因的入口7请求射击hd0，而不是村庄hd4。
- 入口地址与资源选择转换由本节维护；CN基线与选择性L7/L8资源包的覆盖、缺失及验证边界见[身份和资源边界](#kb-06-003-1)。
- 入口索引映射不代表对应关卡资源已经齐全。

- 房间初始化 `sub_72F0F0` 单独保存章节哨兵值，并在 **0x72F239** 与100比较。
- 特殊分支0x72F23E..0x72F265通过0x403D19取得副本字节，在0x72F24C加16，再调用0x40E2AA ->0x72EFC0（0x72EFCD处写入射击管理器+0x1E534），随后向0x408CAB ->0x708D20传入0（资源副本字段+0x1E538）。
- 普通分支0x72F26C..0x72F2BC不替换。
- 这是资源名转换，不是改写房间／传输数据包的依据。

- 资源获取者0x403D2D -> 0x677290 (+0x1E530 hd),0x418499 -> 0x6772B0 (+0x1E534 episode),0x40EE08 -> 0x6772D0 (+0x1E538 dungeon),0x418AF2 -> 0x6772F0 (+0x1E540 stage) 为0x66EC30的SSTG格式化器提供资源。
- 单例Thunk 0x419BBE -> 0x6658E0 返回射击管理器。
- 选定的SMMO闭合（0x66F1A0/0x69D510/0x69D680/0x69FB10）见[普通目标、源攻击和选定资源 / 针对传入kind10身份的PON基础攻击](#kb-08-040-2)。

- 可追溯的raw CF6C/52：完整帧+0x22 hd0，+0x23 episode100，+0x24 dungeon5，+0x25 stage0，WORD+0x26 difficulty0；客户端调试打开`hd0_ep21_dg00_st00.sstg`然后`hd0_ep21_dg00_st00_L_00.smmo`。
- 现有生成的表格包含匹配的ep16至ep22战斗编号大类。
- 这并不能填补上方村庄地图出口/触发器的缺失，也不能证明其他计划中的战斗编号大类不存在于所有可能的存档中。

- 768项x86条件验证覆盖全部BYTE副本值的ep100分支、栈保持及章节99/101的普通分支；资源范围使用ep16..22。当前实现按资源名查找转换，映射及构造验证范围见[身份和资源边界](#kb-06-003-1)。

## 普通目标、源攻击和选定资源 / 针对传入kind10身份的PON基础攻击

- `sub_66F1A0 -> sub_40284C -> sub_69D510` 选择阶段字节+0xB49；文件名是+0x21C+260*槽位。
- `sub_410BD6 -> sub_69D680` 重置/解析该槽位列表；`sub_69FB10` 读取/遍历该槽位仅此一次。
- 生成的段列表示槽位的替代方案；不能累计替代列表进行选择器查找。
- 保留的槽位7运行时打开 st01_H_01，而不是 st01_H_00。
