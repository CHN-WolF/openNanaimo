## 结算页等待与动作授权

- 结算的两个控制器分别具有本地timer，action-state5属于鼠标确认路径。
- `--dungeon-state` 关闭两处自动倒计时并恢复鼠标确认；普通关卡继续、第三关超级BOSS挑战与最终页重试由玩家输入驱动。
- CF88完成原生结果排序后，普通地宫战斗控制器进入已初始化的评分页；观战成员同步使用该入口。
- 进入评分页时将键盘及鼠标的上一帧快照更新为当前输入，确认使用评分页上的新输入变化。
- 适配器按`SettlementAwaitingAction`、合法的存活或失败重试状态、完整12字节CF8B及mode1/2校验推进条件；失败只允许mode1同关重试。
- CF8B携带动作模式，输入来源由客户端控制器处理。

- 连续挑战保留房间与角色资源，切换到下一地宫时同步所有活动成员的完整准备房状态，并建立新的房间加载周期。
- 原生工作进程为队员同步关卡选择和连接局部加载阶段，随后分别完成资料、同伴连接及最终开始确认；续关状态以成员代次隔离，阶段流程见[房间、加载和多人同步](房间身份.md#kb-05-000)。
- 新战斗开始后生命、法力和火力继续按战斗规则更新；准备房与结算界面的主动回城保持独立。
- 超级BOSS成绩按实际关卡阶段持久化，显示阶段独立处理。

## 结算续关标志与加载分支

- CF99发送调用0x66C190/0x66C6C9后写manager+7。
- setter thunk0x40D24C的已恢复xref为0x66C19E、0x66C6D7和0x70850D：前两者分别紧跟CF99发送并写1，后者由CF6D清0；这支持按实际收到的CF99登记连接门控，不以单纯阵亡代替该写入。
- CF8C在0x6FBE40..0x6FBE61检查该字节：非零进入结果控制器3，零走正常重新加载7。
- CF6D status10经0x6F7973 → 0x4067AD → 0x7084F0设置application+6，并经0x41781E → 0x708530清DWORD+8、经0x40D24C → 0x66E5E0清BYTE+7；但它不是无副作用的清标志包：0x6F7992 → 0x405AE2 → 0x6E9440发送CFD1并改网络控制器+0x7C；0x6F7B67..0x6F7B70还经0x403B70/0x72EFE0 → 0x416793/0x7366D0进入状态8。

- 44字节原生帧覆盖其直接消费的+8/+9/+0xA与+0xC..+0xE。
- CF78 status10在0x6F7EDA切换独立控制器8，清理发生在CF8C之后，不能修正已选中的离场分支；不能据此反推无CF99的正常续关也应补CF6D。

- CFD2回复在0x6F493A..0x6F4941调用0x417B02 → 0x6E94C0发送C587/CF70；CF8C的0x6FBF53..0x6FBF5C独立令结果控制器进入重载7，普通结果循环0x763FF0在0x7646E8..0x764738检查state7与+0x18门，再由0x764707调用同一发送器，随后进入state6。

- 另一结果循环对应调用点0x770100。
- 发送器的application+6门、12字节CF70构造0x708400/0x404165、+8取network-controller+0x7C及0x6E951B发送链保留；因此额外CF6D可以引入两轮真实资料请求，而不是仅客户端调试文本的重复打印。

- CF71本地UID匹配后，0x6F4FFA..0x6F500D无条件写X=-300，普通模式在0x6F504B..0x6F506D写Y=252+100×BYTE+0x56；另一模式为110+100×slot。
- 它不检查本地actor是否已经在移动，远程分支的已有对象门不能用于本人。
- CFDA已登记的入场目标为Y=151+100×slot，故slot0的迟到CF71可以覆盖正在去往151的本人坐标为252。
- 续关状态边界归[房间、加载和多人同步](房间身份.md#kb-05-000)，十个关键代码区通过当前客户端字节校验。

- CF8C完整48字节覆盖实际／显示BYTE+0x28/+0x29、难度WORD+0x2C、副本WORD+0x2E。
- +0x2C经0x6FBE94..0x6FBEE3与application当前难度比较，并通过0x4170D5 → 0x50A260写DWORD+0x1E528（getter 0x411ACC → 0x708550）；它不是房主UID。
- 资源 episode 小于16时读取+0x2E的既有条件不变。
- CF8B分支已将错误的“room-owner UID at +0x2C”注释纠正为difficulty WORD；构造器按difficulty写该WORD，不能把数值0误读为房主丢失。

- CF6D在0x6F795D读取BYTE+8成功状态；0x6F799D独立读取BYTE+9，经0x6F79AE／0x6F79BE → 0x409BC4 → 0x708C00写application BYTE+4房主标志。
- 下一次CF80的0x6F762B..0x6F766C通过0x402BDA → 0x708C20读取+4，再通过0x408D19 → 0x708C40读取+5：两者均非零时保留续关路径，其余组合进入准备房控制器state3。
- 44字节成功响应以两个独立BYTE分别表达状态和房主身份，房主标志按当前角色保留。
- 适用范围为角色身份和开战分支。

- 连续关卡资源恢复使用已授权CF8B/12与捕获CF8C/48的real/show BYTE+0x28/+0x29。
- 随后CFEB/12的WORD+8/+0xA必须逐项匹配；捕获CFEC必须完整808字节，BYTE+0x2DA/+0x2DB匹配同一real/show。
- NetworkAdapterService.DungeonContinuation在响应原顺序中完成解冻：CFEC前D010仍按结算冻结丢弃，之后D010/36由本地UID和WORD+0x10更新资源再转发；BattleResourceSnapshot.ForEpoch保留HP/MP/P，只重置冻结及HP优先级。
- 此为适配器源码／构造边界，不新增客户端反汇编结论；原客户端下一关可见扣血待验收。

## 续关授权与成员代次

- 多人地宫续关按房间代次、战斗周期和成员会话分别登记；房间完成有效下一阶段授权后，成员沿同一已确认阶段恢复，使用房间已确认的阶段身份。成员离场会清理其房间成员、战斗参与和准备态残留。
