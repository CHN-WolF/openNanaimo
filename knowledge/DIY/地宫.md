# 地宫 DIY 与资源移植

本页区分两种不同工作：把已有地宫资源转换后接入客户端（L7/L8），以及增加有独立入口、战斗和通关状态的新挑战（修道僧四关）。前者的权威配方见[地宫资源兼容](../工程/地宫资源兼容/索引.md)，后者见[修道僧破关](../业务/地宫/关卡与房间/修道僧破关.md)。

## 范例一：移植已有地宫资源

L7/L8 范例从来源资源构建经审核的增量资源包，将源格式转换为当前客户端读取格式，并把资源身份、村庄入口、战斗目录、小地图门控与启动资格配套起来。它不是“把一份目录拷进客户端”：资源闭包、运行时身份、程序、安装凭据必须匹配。

| 工作项 | 推荐做法 | 当前事实入口 |
|---|---|---|
| 来源与范围 | 记录源布局、受支持章节／阶段、资源用途和被排除对象 | [范围与前置进度](../工程/地宫资源兼容/范围与前置进度.md) |
| 闭包与转换 | 递归收集 SSTG、SMMO、怪物／BOSS、PON、EFF、IM3、地图、音乐和共享依赖；逐格式转换并报告失败 | `scripts/port_lumineos_resources.py`、`scripts/lumineos_codec.py` |
| 运行时身份 | 校验章节、地宫、阶段、难度及两阶段槽；资源身份与战斗目录分别维护 | `manifest/lumineos_resource_port.json`、`manifest/lumineos_combat.json` |
| 客户端集成 | 在精确布局和资源身份通过时启用入口、道路／返回位置和兼容门控 | [道路与资源别名](../工程/地宫资源兼容/道路与资源别名.md)、[小地图补丁](../工程/地宫资源兼容/小地图补丁.md) |
| 发布与恢复 | 先预检资源身份，再提交转换资源及程序变更，保留摘要、备份和事务收据 | [L7/L8 移植指南](../指南/L7-L8资源移植.md)、[事务与恢复](../工程/资源安装/事务与恢复.md) |

### 移植接入顺序

1. 冻结来源客户端／资源版本与目标 CN 基线，不混合未经登记的源包。
2. 生成完整引用闭包和目标清单；为每项记录输入摘要、转换规则、输出身份和间接依赖。
3. 先在临时目录转换，检查逻辑身份和引用闭合；生成资源身份凭据后再准备客户端代码与选择器门控。
4. 将资源包作为可选能力安装。只有完整资源身份通过，才开放对应章节；不完整时应保持原状态或明确拒绝启动。
5. 事务化安装与回滚；在原客户端目录、社交副本和实际启用资源的运行路径分别核验一致性。
6. 分别验收资源解析、战斗目录、导航／返回和客户端可见结果。单项格式或哈希通过不证明关卡可正常游玩。

## 范例二：增加独立挑战

修道僧范例不是单纯移植原有关卡，而是把四套来源关卡映射为项目的新身份，并实现本地入口、创建／准备房、资源选择、战斗、结算、单人资格、持久通关位和返城对白。NPC 的位置、命中和对白见[NPC DIY](NPC.md)。

| 关注点 | 接入要求 | 修道僧范例 |
|---|---|---|
| 关卡身份 | 客户端资源身份与逻辑关卡身份同时明确，并在准备房、选择器、加载器和战斗中一致 | `hd0/ep24..27/dg0/st0` |
| 入口资格 | 绑定村庄／出口页面、人数、难度和目标关卡，不因普通快速进入路径绕过检查 | 四村 NPC 单人入口，复用一致规则 |
| 资源包 | 关卡、目标、BOSS、弹药、碰撞、特效、地图、音乐、UI 和文本闭包逐项登记 | `manifest/monk_challenge_resources.json`、`manifest/monk_challenge_combat.json` |
| 客户端交互 | 创建页、准备房标题／怪物资料、加载、开战、手动结算、重试与回城分别检查消费点 | 四关独立界面与原生生命周期衔接 |
| 进度记账 | 按角色归属保存独立通关位；以战斗代次、结算周期和会话身份防重放、错角色写入 | `CharacterMonkChallenges`、`MonkChallengeCommits` |
| 场景返回 | 冻结开始位置和本人身份，成功结算后仅在原来源场景授予一次后续对白 | 村庄／页面／角色与挑战代次共同校验 |

### 新挑战接入顺序

1. 定义明确且不冲突的资源元组、玩家可见关卡名、难度、阶段和进度索引。
2. 盘点客户端各界面对身份字段的消费点；确认创建页、准备房、加载、战斗和结算不把展示编号误作逻辑身份。
3. 建立战斗资源与UI／本地化资源清单，资源生成与战斗目录使用可重复的脚本；审查共享资源的覆盖与重命名。
4. 将入口授权与快速入场、房间建立和战斗开始共享；失败时拒绝而非回退到不受限制的原生入口。
5. 为结算定义冻结结果、重试周期、幂等提交、角色归属、通关保存与离线恢复边界。
6. 在返城后检查来源位置、角色身份与结果状态；避免过早对白、重复通关提交或向其他角色展示。
7. 把静态指令、隔离构造、托管服务检查和匹配客户端实机验收分别记录；未实机确认的流程标记为未验收。

## 两类工作的共同边界

- 资源移植解决“怎样把来源资源转换、校验并让客户端识别”；自定义挑战还要定义新业务身份、交互和持久状态。
- L7/L8 的道路、章节门控与资源安装合同不能直接套在修道僧的新挑战上；修道僧创建的通关位也不是普通地宫进度。
- 原始地图、程序地址、资源数、性能及验收状态会随版本变化；维护唯一事实页，不在 DIY 专题复制完整表格。
- 按[验证状态](../工程/验证状态.md)报告当前检查范围。资源转换成功、隔离测试通过和客户端完整通关是不同证据等级。
