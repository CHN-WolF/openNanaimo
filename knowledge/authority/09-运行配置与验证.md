## 启动模式与 GUI 契约

- **本地模式**：使用 Network 参数，adapter、资料注册与客户端目标均为 `127.0.0.1`。“进入 Nanaimo”以用户名／角色显示名文本框选定账号，向已运行的回环adapter提交账号注册，再启动独立客户端。新名字克隆当前管理档并同步全部管理页；首次注册原子导入，已有账号按数据库状态续档。档案复制与只读卡片规则由03维护。
- **社交模式**：自动检测或接受用户填写的特定局域网 IPv4，以该地址绑定登录／世界／资料注册监听并向客户端写入同一地址；不绑定 `0.0.0.0`。GUI 显示检测地址并保存最近使用地址。
- **普通适配器启动**：未修改的编辑状态直接复用已保存 INI；有修改时要求先显式保存，不再隐式提交完整库存。启动／停止、逐文件 SHA-256、端口检查与监听归属复核均在后台执行，保持完整运行包校验；停止已有服务不要求编辑状态匹配。
- **社交适配器启动**：社交模式“启动适配器”检查已保存的启动配置存在后，停止本项目已有 adapter／bridge 进程，拒绝复用被其他进程占用的固定端口，再以指定 IPv4 单例启动并验证监听归属。共享服务启动不调用本地角色 `Save-Profile`，不把GUI当前编辑档写入角色／库存表，不受本地纯新手复选框和背包目录校验影响；服务自身仍可初始化数据库及独立工作进程状态；社交账户由各参与入口单独注册。缺少配置时在停止现有服务之前报错。
- **启动诊断**：背包C#工具后端在Windows PowerShell 5.1下完整收集stderr与退出码，恢复调用方错误策略后报告完整异常。目录外卡片按03的只读保留规则处理。host验证覆盖启动解耦、完整异常报告和指定局域网IPv4的三端口绑定。
- **卡片发放目录与活动箱**：GUI发放目录包含560卡号，安装校验逐条核对实际JSON及CSV的494种卡号覆盖。验证包括WinForms发放、保存、重读、删除、旧420条目录拒绝、HP首次终结、领取去重、主库提交、SP专用消耗及完整启动自检。活动箱资格归06，库存字段与事务归03。
- **参与入口**：P1／P2／P3各有用户名框和参与按钮，用户名定位主机数据库账号。新账号进入纯新手创建，已有角色续用原档，注册结果按来源IPv4入队；各槽位使用独立工作目录与运行时缓存。持久化验证覆盖账号重开和离线卡片保留。
- **纯新手档**：控制行位于普通用户名／角色显示名之上；启用后固定 `skip_tutorial=0`、`unlock_all_dungeons=0`，不能跳过教程或开启全部地宫权限；复用普通 profile 启动的 adapter 时，会话级 C355 门控仍强制保持该限制。
- **目录查询**：“装饰家具查表”使用 `inventory_furniture.json` 及资源图标图集，覆盖781条目录记录，其中775条具有可用图标。图标由InteriorIcon资源解码；缺失项保留明确状态及目录信息。


- **后台任务与进度**：普通／社交适配器、客户端启动、档案选择与保存采用单个 detached PowerShell runspace；后台仅取得路径、值及脱离控件的档案快照，UI定时器更新阶段／耗时，完成回调在GUI线程执行。忙碌时禁用管理页、防重复提交，并拒绝关闭尚有任务的窗口；失败恢复界面状态。预览请求以200ms定时器合并，批量控件导入不逐次枚举进程。阶段计时写入`adapter_data/logs/launcher-timings.jsonl`，阶段时长是GUI轮询采样而非精密I/O剖析。

## 发布产物身份

### 统一发布包

当前发布采用net8.0自包含运行包，托管程序集、原生入口、资源目录与兼容配方共同登记于活动清单。源码闭包、运行文件和发布文件分别按精确大小及SHA-256校验；安装与回退采用逐文件事务。验证层级为构造、数据库事务、隔离指令、工作进程及发布合同；客户端任务、娱乐难度和竞技连续对局按匹配版本独立验收，`runtime_acceptance=false`。

当前发布以`manifest/source_closure.json`、`adapter_runtime/adapter_manifest.json`和`manifest/open_release_manifest.json`共同登记源码及产物身份。运行入口为托管适配器与bridge组合；适配器使用11005／11999／12050端口，worker使用51005。金币、积分、卡牌、角色装备与连续挑战按各自功能主题的当前规则执行。

| 身份对象 | 唯一登记入口 | 核对方式 |
|---|---|---|
| 完整runtime文件，包括Adapter、Gameplay、bridge和资源目录 | `adapter_runtime/adapter_manifest.json` 的 `files`（`name`／`size`／`sha256`） | 对照实际文件大小和SHA-256及完整文件身份。 |

| 源码闭包及数量 | `manifest/source_closure.json` 的 `files`、`count` | 对照条目及源码身份，数量随活动清单维护。 |
| 原生正式／testports／bridge输出 | `manifest/source_closure.json` 的 `build_outputs` | 重复构建逐字节比较，并与发布的bridge身份对照。 |

原生三个入口分别执行重复构建字节比较；GUI使用managed入口与bridge组合，正式／testports入口按独立用途维护。当前下载与安装身份统一取活动清单的文件大小及SHA-256。

只读查看登记值及计算磁盘身份（在仓库根目录执行）：

```powershell
$runtime = Get-Content -Raw -Encoding UTF8 adapter_runtime/adapter_manifest.json | ConvertFrom-Json
$runtime.files | Where-Object { $_.name -in @('Nanaimo.Adapter.exe','Nanaimo.Adapter.dll','Nanaimo.Gameplay.dll','nanaimo_gameplay_bridge.exe') } | Format-Table name,size,sha256 -AutoSize
(Get-Content -Raw -Encoding UTF8 manifest/source_closure.json | ConvertFrom-Json).count
Get-FileHash -Algorithm SHA256 adapter_runtime/Nanaimo.Adapter.exe,adapter_runtime/Nanaimo.Gameplay.dll
```

清单、磁盘及源码身份一致后进入发布；发现差异时先核对待发布基线，再构建对应产物并逐文件校验。

## 社交模式槽位客户端启动契约

- `gui_launcher/start_social_client.ps1` 是社交参与者的多开入口；本地模式继续直接启动未改写的 `$Client`，不得调用该 helper。
- GUI 在后台完成共享兼容性检查后，每个参与者仅调用一次多开入口；入口在同一槽位锁内完成准备和最后运行进程保护，再调用`BeforeLaunch`注册用户名，之后启动客户端并等待可见窗口（默认最多8秒）。准备失败不向适配器排入账号；注册后启动失败仍不能当作客户端接收成功。`PrepareOnly`保留为手工／测试准备入口，不是GUI二次调用路径。返回对象包含进程、窗口、工作目录、运行时目录和副本身份。
- 槽位副本与源客户端相邻，使用 `Game.openNanaimo-social-NNN.exe`；缓存根目录默认为静态资源根下 `.openNanaimo-social`，其内部按源 SHA-256 和槽位编号隔离 `work`、`runtime` 及元数据。
- 准备状态使用 `social-client.v5` 与 `social-worktree.v2`；文件、源根、缓存根、工作目录、配置哈希和图像解析器共享读补丁共同校验。可写配置与 `Working` 独立，静态资源采用目录映射；`APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP` 指向槽位目录。图像资源探测保留只读权限并允许并发读取，避免同机多开时将共享读取冲突误判为资源缺失。

- L7/L8资源标识同步分别校验父目录和标识文件：父目录须为真实目录，标识须为普通文件或首次创建目标；目录、重解析点及内容摘要共同参与身份校验。既有20项资源身份、9项宠物身份及多开helper检查覆盖源代次迁移、槽位首次准备及复用；本轮GUI与多开验证的具体范围／限制见“启动模式与GUI契约”。资源隔离专项按可用输入执行；验证范围为路径安全、文件身份和启动准备。
