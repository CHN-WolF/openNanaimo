# 构建与验证

本页介绍源码检查、适配器构建与本地运行环境校验。以下命令均从仓库根目录执行。

**仓库不附带 Python 或 TinyCC，首次下载后没有 `tools/` 是正常情况。** 请先阅读 [下载与安装说明](../README.md#自行安装-python-与-tinycc)；各入口的工具查找方式见 [运行依赖](运行依赖.md#python-与-tinycc-的准备方式)。

## 1. 源码检查与回归测试

### 仅需命令行 Python 的检查

安装 Python 3.11 或兼容版本并使 `python` 可从 PATH 调用后：

```powershell
python --version
python -B scripts/verify_package.py --source-only
```

`--source-only` 核对 `manifest/source_closure.json` 中的文件大小、SHA-256、递归 include 闭包和项目文本。当前 C／include 闭包为89个文件；此命令不需要 TCC、客户端、游戏资源或适配器 EXE，也不会运行客户端。

尚未准备 TCC 时，可以单独运行以下不依赖编译器的测试；它们只是测试集的一部分，不代表完整回归通过：

```powershell
python -B -m unittest discover -s scripts -p "test_verify_package.py"
python -B -m unittest discover -s scripts -p "test_export_patch.py"
```

### 完整测试集的额外前提

`test_native_ui_protocol.py` 当前固定使用 `tools/tcc/tcc.exe`。需要自行将完整兼容工具链放到 `tools/tcc/`，不仅是一个 EXE。它不从 PATH 查找 TCC，也不读取构建脚本的 `-TccPath` 参数。

在完整源码仓库中准备好该工具链后执行：

```powershell
python -B -m unittest discover -s scripts -p "test_*.py"
```

缺少固定路径的 TCC 会导致测试类初始化报错，**不是跳过**。缺少客户端比较输入或创建符号链接的能力，则有相应测试会跳过。仅导出的 `source,knowledge` 层不包含 GUI 运行脚本；其源码完整性检查可执行，但不能直接视作完整测试环境。具体层内容见 [导出工具](文件清单与导出工具.md)。

## 2. 适配器构建

构建脚本支持两种工具位置，任选其一。下载的工具链应保留配套 `include`、`lib` 等文件。

```powershell
# 已自行准备 tools/tcc/tcc.exe 及完整工具链时：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_adapter.ps1 -KeepOutputs

# 工具链放在仓库外时：将示例路径替换为实际下载位置
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_adapter.ps1 -KeepOutputs -TccPath '../toolchains/tcc/tcc.exe'
```

`-TccPath` 只作用于这一次构建调用，不会配置 GUI、完整校验脚本或协议主机测试。构建脚本不会下载编译器；缺少默认位置的工具且未指定有效 `-TccPath` 时，会报告 `TCC missing`。

构建脚本分别编译正式端口与测试端口入口，并对照 `manifest/source_closure.json` 的 `build_outputs` 核对结果。编译器版本、目标架构、头文件或库不同可能导致结果不一致；自行下载的工具不自动视为与记录基线兼容。已观察的工具版本见根 README。

不加 `-KeepOutputs` 时只进行临时重建校验；加上后输出：

- `build/nanaimo_adapter.exe`
- `build/nanaimo_adapter_testports.exe`

部署前退出客户端并停止适配器，备份原有产物，再将需要的构建结果放到 `adapter/` 对应路径。GUI 使用正式端口版本，测试端口版本用于隔离测试。

## 3. 完整运行环境校验

此步骤需要匹配的客户端、资源、GUI 数据、Python 和已构建适配器。仅安装工具不足以运行游戏，依赖列表见 [运行依赖](运行依赖.md)。

客户端字节基线和完整运行文件契约都可以使用 PATH 中的 Python 检查：

```powershell
python -B scripts/verify_client_baseline.py
python -B scripts/verify_package.py
```

`verify_client_baseline.py` 检查完整客户端哈希、7个原生函数窗口、代码填充区及启动／浮点初始化窗口；负向用例包含单字节修改、截断和无有效文件映射的 VA。未加 `--source-only` 的 `verify_package.py` 需要完整运行文件，不是裸源码仓库检查。

如需继续执行包含 GUI 合成配置验证的包装脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify_package.ps1
```

**此 PowerShell 脚本当前固定使用 `tools/python/python.exe`，没有 PATH 回退或解释器路径参数。** 使用它前，须自行在该位置准备可用的完整 Python 运行环境及配套标准库／DLL，而非只复制 `python.exe`。仅安装系统 Python 不满足这个入口。上面的两个 Python 命令不包含包装脚本追加的 GUI 验证，不能当作同等替代结果。

完整环境的文件记录由 `scripts/refresh_manifest.py` 生成到 `manifest/open_release_manifest.json`。刷新清单记录的是文件身份，不会使不匹配的客户端通过独立基线检查。

## 4. 已记录的测试结果

以下为2026-09-19的验证记录，反映各次测试的输入范围，不是每次文档更新都会重跑的测试。它们来自具备相应工具和运行依赖的环境，不表示未准备工具的源码仓库可直接复现全部结果。

| 测试组 | 记录结果与范围 |
|---|---|
| 基础回归 | 70项中65通过、5项因无法创建符号链接跳过 |
| 独立环境复核 | 70项中64通过、6跳过；其中5项是符号链接限制，1项缺少原始客户端比较输入。客户端基线及35字节代码差异另行检查通过 |
| Network／布局回归 | 77项中72通过、5项因符号链接限制跳过 |
| 确定性构建 | 正式／测试端口入口重复编译，复现各自大小与SHA-256 |
| 文件完整性 | 89个源码文件；运行关键文件在不同验证快照中分别为17和16个，适用集合以各自清单为准 |
| GUI 静态与 IO | 合成配置下 ValidateOnly、LaunchModes、InventoryIO、TitleIO、CatalogPreview 及连接器 PreviewOnly 通过；检查10个页面与恢复默认按钮 |
| WinForms 布局 | 1000×870、1120×940窗口以及1／1.25／1.5缩放通过；覆盖同级控件、裁切、16个等级框、2个路线和Z/X槽的滚动访问 |
| C355 构造 | 四项主机测试、三个构造器共54帧；仅Network的+0xDF发生预期变化，两种Standalone构造不变；含旧边界负对照与相邻字节保护 |
| 监听构造与实测 | 12个源码监听调用点：11处wildcard初始化改为loopback，1处原本为loopback；实际9个TCP监听为127.0.0.1:11005、11999、12050、32050–32055 |

C355 与监听构造测试使用封包头／socket 桩，不检查真实 wire checksum。实际监听检查只证明适配器加载及绑定。相关来源标识和功能验证条件见 [知识库09](../knowledge/authority/09-运行配置与验证.md)。
