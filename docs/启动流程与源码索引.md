# GUI 启动链、知识库与源码阅读索引

本文按GUI入口、本地／社交Network启动、资料保存、完整adapter、地宫桥接和客户端连接顺序介绍源码。开发构建使用Python、TinyCC和.NET SDK；发布启动器使用内嵌托管工具，自包含运行包可直接在Windows运行。基础Nanaimo客户端由使用者合法提供，依赖见[运行依赖](运行依赖.md)。

## 路径别名

- `<OPEN_ROOT>`：运行根目录／仓库根目录。
- 完整 adapter 构建结果：`adapter_runtime/`。
- 原生地宫源码入口：`adapter/`，组件：`release/components/`。
- managed 玩法源码：`managed/`，无界面宿主：`managed-host/`。

## 一图看懂

```text
start_nanaimo_launcher.bat
  -> powershell.exe -STA gui_launcher/nanaimo_launcher.ps1
       -> 读取 profile、目录、预览和 adapter manifest
       -> dot-source inventory_admin_gui.ps1
       -> 创建 WinForms 控件
       -> ShowDialog

[保存配置]
  -> Save-Profile
       -> 校验角色、数值、技能、称号和本地库存
       -> 写 nanaimo_launcher_profile.ini/json

[本地模式：仅启动适配器]
  -> 确认编辑状态与已保存配置一致
  -> Test-AdapterBinary
  -> Start-LocalAdapter 127.0.0.1
       -> Nanaimo.Adapter.exe
       -> 内部启动 nanaimo_gameplay_bridge.exe
       -> 等待 11005 / 11999 / 12050

[社交模式：启动适配器]
  -> 自动检测或填写局域网 IPv4
  -> Stop-LocalAdapter（仅本项目进程）
  -> Start-LocalAdapter <LAN IPv4>
  -> 验证固定端口监听归属并显示该 IPv4

[社交模式：P1/P2/P3 参与]
  -> 按用户名注册数据库账户 -> TCP <LAN IPv4>:11999
  -> 注册结果按来源 IPv4 入队
  -> 写 Network ServerIP=<LAN IPv4>
  -> 分别启动 game.exe

[本地模式：进入 Nanaimo]
  -> 解析所选已有档案；纯新手模式写隔离 runtime profile
  -> Test-ClientBinary
  -> Install-LaunchModeConfig 127.0.0.1
  -> 向已运行的 127.0.0.1 adapter 注册账户 -> TCP 11999 -> OK\n
  -> Start-Process game.exe [固定 Network 参数]
  -> 不停止／重启 adapter，不结束任何现有 game.exe
```

## 1. Windows 入口

| 顺序 | 文件／锚点 | 作用 |
|---|---|---|
| 1 | `start_nanaimo_launcher.bat` | 切换到运行根目录，以 `-STA` 启动 GUI。 |
| 2 | `gui_launcher/nanaimo_launcher.ps1` | 读取客户端路径、adapter runtime、profile、日志和目录；只对项目自带 adapter 使用 manifest 哈希。 |
| 3 | `gui_launcher/inventory_admin_gui.ps1` | 本地库存编辑界面。 |
| 4 | `managed-host/LauncherTools.Inventory*.cs` | `Nanaimo.Adapter.exe --tools inventory` 的档案查询、snapshot/apply、增量事务及备份。 |
| 5 | `gui_launcher/client_connect.ps1` | 命令行连接器、资料注册和客户端启动。 |

## 2. 本地与社交 Network 启动

两个 GUI 标签都使用 `network`／`-q` 协议路径，`Install-LaunchModeConfig` 从 `gui_launcher/launch_modes/gamestartoption.network.ini` 生成 `StateOption/gamestartoption.ini`，再把 `ServerIP` 写成当前目标 IPv4。

| GUI 模式 | 地址 | ClientArgs 尾参数 | adapter／注册 |
|---|---|---|---|
| 本地模式 | 固定 `127.0.0.1` | `6:7:1:127.0.0.1:` | adapter、11999注册和客户端均使用回环地址 |
| 社交模式 | 自动检测或手工填写的特定局域网 IPv4 | `6:7:1:<LAN IPv4>:` | 主机以该地址绑定；参与者向同一地址注册并进入 |

客户端路径固定为 `<OPEN_ROOT>/game.exe`。本地与社交模式均使用Network协议及明确IPv4绑定；Stand_Alone构造器用于独立协议研究。

纯新手档的开关和用户名位于普通用户名／角色显示名之上。启用后 GUI 禁用跳过教程与全地宫选项，独立 runtime profile 固定 `skip_tutorial=0`、`unlock_all_dungeons=0`。

## 3. Profile 和本地库存

### GUI 侧

| 锚点 | 作用 |
|---|---|
| `Read-Ini` / `Read-KeyValueFile` | 读取 profile 和状态。 |
| `Encode-NameHex` / `Decode-NameHex` | 名称与 GBK 十六进制身份互转。 |
| `Get-ResourceSelection` | HP/MP、攻击、防御、货币、钥匙和期限字段。 |
| `Get-SkillSelection` | 技能路线、16个等级和 Z/X 槽。 |
| `Write-DungeonGradeState` | 固定称号等级写入。 |
| `Save-Profile` | 完整校验后写 INI/JSON 和库存状态。 |
| `Write-PureNewPlayerRuntimeProfile` | 写入隔离的新手runtime profile，固定教程必做并按真实进度开放地宫，已有账号继续原档案。 |
| `Register-SocialAccount` / `Start-SocialParticipant` | 以用户名注册数据库账户并从指定局域网 IPv4 启动参与客户端。 |

### 库存管理

```text
inventory_admin_gui.ps1
  -> Nanaimo.Adapter.exe --tools inventory
  -> profiles / snapshot；launcher_tools=2 时复用会话常驻工具
  -> 编辑衣物、宠物、游戏道具、家具和卡片
  -> apply；按行差异事务提交，资料与固定称号合并备份
```

普通 profile 通过11999注册导入已运行 adapter；需要直接改写持久 sidecar 或重置进度时仍应先停止 adapter。社交模式的“启动适配器”负责停止本项目已有 adapter／bridge、拒绝占用端口并按指定 IPv4 单例启动；P1／P2／P3 参与按钮只执行资料注册、客户端配置和启动。

## 4. GUI 本地与社交动作

### 保存配置

校验并显式保存profile、称号和库存；服务与客户端启动使用各自独立入口。库存工具的增量事务、按变更备份及离线保护由知识库[工程／启动运行](../knowledge/工程/启动运行.md#kb-09-017-1)维护。

### 仅启动适配器

```text
adapterBtn
  -> 已运行：Stop-LocalAdapter
       -> 写 adapter_data/stop.request
       -> 等待 Nanaimo.Adapter.exe 正常退出
       -> 必要时终止残留桥接进程
  -> 未运行：确认编辑状态与已保存配置一致 -> Start-LocalAdapter
```

### 本地模式：进入 Nanaimo

```text
clientBtn
  -> 固定解析为 Network / 127.0.0.1
  -> Assert-LocalAdapterRunning
  -> 解析所选账号档案，或生成纯新手隔离 profile
  -> Test-ClientBinary
       -> 仅确认 game.exe 文件存在
       -> 不检查脱壳实现的大小／哈希
       -> 不检查本地派生的 pack、SSTG 或 PON
  -> Install-LaunchModeConfig
  -> Ensure-ClientCompatibility
  -> Register-ClientProfile / Register-PureNewPlayer 127.0.0.1:11999
  -> 启动一个新的 game.exe
```

该入口复用已运行且绑定`127.0.0.1`的Network adapter和已保存档案，保持现有客户端及服务生命周期，支持本机多开。准备客户端前检查适配器运行状态，资料注册校验端口可用性。角色数值和库存编辑须先显式保存，适配器按钮负责启动／停止；纯新手账户通过会话级门控按真实进度开放地宫。

`Start-LocalAdapter` 不使用固定睡眠后直接放行，而是在10秒窗口内轮询绑定地址上的 `11005/11999/12050`，三个入口全部可连接且归属新进程才返回。

### 社交模式启动与参与

```text
socialAdapterBtn
  -> Normalize-NetworkIPv4
  -> 校验已保存的ProfileIni，再执行服务切换
  -> Stop-LocalAdapter
  -> Start-LocalAdapter <LAN IPv4>
  -> 写 adapter_ip.txt 并显示地址／PID

P1/P2/P3
  -> Ensure-ClientCompatibility（符合条件时复用会话准备结果）
  -> start_social_client.ps1（每次参与仅调用一次）
       -> 在槽位锁内准备副本、独立网络配置／工作目录及运行保护
       -> 副本改写槽位互斥体及已登记的图像资源共享读取位点
       -> BeforeLaunch：Register-SocialAccount -> TCP 11999
       -> Start-Process 并等待非零窗口句柄
```

adapter 的注册队列按来源 IPv4 隔离；同机 P1／P2／P3 依按钮顺序消费，其他机器使用各自来源队列。用户名是数据库账户身份；新账号进入纯新手建角，已有角色沿用持久化档案。各槽位的客户端副本位于源客户端旁，工作目录、网络选项、运行时缓存和用户目录独立。准备、复用、清理及回滚步骤见《完整适配器与客户端兼容说明》的社交多开副本章节。

## 5. 完整 adapter 源码入口

### 构建入口

```text
scripts/build_complete_adapter.ps1
  -> TCC 编译 adapter/nanaimo_gameplay_bridge.c
  -> .NET 8 SDK publish managed-host（支持 net6.0 / net8.0；当前发布为 net8.0）
  -> 读取 adapter_runtime/资源/数据，或 -ResourceDataRoot 指定的匹配数据
  -> 写 adapter_runtime/adapter_manifest.json
  -> 可选 -SelfTest
```

生成：

```text
adapter_runtime/Nanaimo.Adapter.exe
adapter_runtime/nanaimo_gameplay_bridge.exe
adapter_runtime/adapter_manifest.json
adapter_runtime/资源/数据/...
```

原生独立入口仍可用 `scripts/build_adapter.ps1` 确定性重建：

```text
adapter/nanaimo_adapter.c
adapter/nanaimo_adapter_testports.c
adapter/nanaimo_gameplay_bridge.c
```

`manifest/source_closure.json` 记录当前原生 include、managed 构建输入及已验证原生输出；实际数量与哈希以该活动清单和验证器输出为准。

### managed 玩法层

| 路径 | 作用 |
|---|---|
| `managed/Services/NetworkAdapterService*.cs` | 登录、村庄、任务、商城、社交、交易、竞技、娱乐和地宫路由。 |
| `managed/Services/DatabaseService*.cs` | 角色、库存、任务、关系、拍卖、公寓和地宫差量事务。 |
| `managed/Services/PetProgression.cs` | 宠物等级、阶段、攻击和奖励加成。 |
| `managed/Services/NativeDungeonState.cs` | schema4 地宫状态：payload5704，完整帧5712；精确布局见 level200/internal-layout。 |
| `managed/Services/NativeDungeonClient.cs` | F100/F101/F102/F103 内部桥接。 |
| `managed-host/Program.cs` | 进程生命周期、端口、停止请求和 self-test。 |

### 原生地宫层

`release/teamplay_common.inc` 仍是原生功能拼装点，包含资料、技能、卡片、Boss、目标、掉落、复活、商城、公寓、多人同步和地宫战斗。`NANAIMO_GAMEPLAY_BRIDGE` 构建额外启用 `release/components/game_session/managed_bridge.inc`。

## 6. 端口

| 端口 | 作用 |
|---:|---|
| 11005 | 客户端登录入口。 |
| 11999 | GUI 角色资料注册。 |
| 12050 | 客户端世界入口。 |
| 22051..22054 | 竞技／娱乐入口。 |
| 51005 / 51999 / 52050 | 主地宫桥接实例。 |
| 62050..62055 | 主地宫内部连接。 |
| 53000..53998 | 按队伍隔离的额外地宫实例。 |
| 3534 | 客户端 P2P 发布／防火墙规则。 |

本地模式将公开入口绑定 `127.0.0.1`；社交模式将登录、世界和资料注册入口绑定用户确认的特定局域网 IPv4。固定端口被占用时完整 adapter 直接拒绝启动，不动态改到客户端未知端口。地宫桥接的内部回环端口保持本机内部通信。

## 7. 地宫状态交换

```text
managed character / inventory / tasks
  -> NativeDungeonState.Create
  -> F100 导入 schema4 的5704字节 payload（完整帧5712）
  -> 原生地宫请求／响应
  -> F102 快照
  -> ApplyNativeDungeonDeltaAsync
```

当前关键偏移均相对 payload。下表仅作源码导航，完整字段、版本校验和迁移边界见 [内部布局](level200/internal-layout.md)：

| 偏移 | 内容 |
|---:|---|
| 0..47 | schema判别、角色、等级、+12保留零值、HP/MP与两个u64余额；人物累计经验位于扩展区 |
| 48..95 | 技能点、技能槽、复活次数、快捷栏期限、宠物代码及成长阶段、攻防、姓名长度和性别 |
| 96..159 | GBK姓名、外观、日期、宠物宝石和宠物等级／经验；阶段字段在+72/+76 |
| 160..271 | 16个技能等级、6个快捷栏槽 |
| 272..1951 | 卡片数量 |
| 1952..3995 | 最多255条道具代码／数量 |
| 4000..5023 | 原生实例句柄 |
| 5024..5119 | 地宫称号、最高前沿和60字节通关 mask |
| 5120..5143 | 伴侣UID、schema4、payload长度、CurveVersion3、64位人物累计经验 |
| 5144..5703 | SP、事件及特殊／VIP卡片的独立扩展区 |

角色经验、宠物经验、货币、卡片和道具按差量事务提交，提交ID用于幂等。

连续挑战另有 battle-epoch 资源层：CF71/CF72 提供 effective 最大／当前 HP/MP，D010 提供较新的当前 HP，CF87 冻结结算值。CF72 的复活显示字节与角色账本保持一致；相同PET连续关卡通过原生生命周期保留发射器与P状态。客户端派生覆盖两类结算控制器的自动倒计时，恢复旧版误改的鼠标确认；CF8B承载动作模式，输入来源由客户端控制器处理。失败结算重新挑战建立新的战斗周期，恢复本周期 HP/MP 上限并等待准备房重新加载；玩家选择回城时按 CF73/CF1D 闭合到 CF74/CF1E 和 DeathReturn。

Boss 组件账本位于原生层：组件 HP 按 authored child/ordinal 独立维护，严格并行拓扑中重复的局部0/0按首个仍存活 authored 组件顺序解析。该策略已完成构造回归，客户端显示按当前产物独立验收。

## 11. 验证范围

- 源码清单、确定性原生构建、managed build、完整 adapter self-test、Python 回归和 GUI 自测相互独立。
- GUI 自测分别覆盖本地／社交地址契约、来源 IPv4 注册队列、P1／P2／P3 控件、纯新手强制值和宠物／装扮／家具目录预览；客户端多人显示按相应场景独立验收。
- 社交验证覆盖好友申请确认、双向屏蔽与私聊定向送达、组队准备及续关隔离、死亡观战动作门控、三种戒指权益和参战成员限定、纯新手创建及已有角色重登、独立槽位工作目录与安全清理。构造、隔离执行和客户端场景验收分别登记。
- 适配器构造与客户端显示分别验收，结果绑定当前产物身份。
- 客户端兼容范围由PE结构及目标站点确定；适配器产物由运行清单校验。
