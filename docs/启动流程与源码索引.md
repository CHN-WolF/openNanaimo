# GUI 启动链、知识库与源码阅读索引

本文按启动入口、资料保存、协议适配器和客户端连接的顺序介绍源码。Python 与 TinyCC 不随仓库提供；下载入口见 [安装说明](../README.md#自行安装-python-与-tinycc)，各脚本的查找位置见 [运行依赖](运行依赖.md#python-与-tinycc-的准备方式)。

## 路径别名

- `<OPEN_ROOT>`：仓库根目录。
- 适配器入口位于 `adapter/`，源码组件位于 `release/components/`。

## 一图看懂

```text
start_nanaimo_launcher.bat
  -> powershell.exe -STA gui_launcher/nanaimo_launcher.ps1
       -> 读取清单、目录、预览、现有 profile 和生成状态
       -> dot-source inventory_admin_gui.ps1
            -> 选择本地 tools/python/python.exe；不存在时使用 PATH 中的 python
            -> 所选解释器 -B inventory_admin_backend.py snapshot
       -> 创建 WinForms 控件
       -> ShowDialog

[保存配置]
  -> Save-Profile
       -> 校验角色/数值/技能/标题/投射物；启动模式固定为 Network localhost
       -> inventory_admin_backend.py apply
       -> 写 nanaimo_launcher_profile.ini
       -> 写 nanaimo_launcher_profile.json
       -> 可选写 dungeon_grade_state_v1_<namehex>.dat

[启动本地组件]
  -> Save-Profile
  -> Test-AdapterBinary
  -> Start-Process nanaimo_adapter.exe 11005 0 0 0 <profile.ini>
       -> main()
       -> stable_load_launcher_profile()
       -> progression/inventory bootstrap
       -> multiplayer_start_listeners()
            -> 6 x gs_thread(32050..32055)
            -> profile listener 11999
            -> GS front proxy 12050
       -> login_thread 11005

[保存并进入游戏 / 客户端按钮]
  -> 停止 GUI 识别到的旧本地组件
  -> Save-Profile
  -> Test-ClientBinary
  -> Install-LaunchModeConfig -> StateOption/gamestartoption.ini
  -> 按需重启本地组件并等待 1400 ms
  -> 固定 Network：Register-ClientProfile -> TCP 11999 -> OK\n
  -> 停止同路径的旧 game 进程
  -> Start-Process game.exe [固定 Network (-q) 参数]
  -> 客户端连接 11005 登录入口，随后连接 12050 GS 前端
```

## 1. Windows 入口

| 顺序 | 文件/锚点 | 作用 |
|---|---|---|
| 1 | `<OPEN_ROOT>/start_nanaimo_launcher.bat` | 切换工作目录到包根，使用 `-NoProfile -ExecutionPolicy Bypass -STA` 启动 GUI。 |
| 2 | `gui_launcher/nanaimo_launcher.ps1` | 参数、WinForms 初始化、根目录、客户端/本地组件/profile/log/目录路径和固定哈希。 |
| 3 | `nanaimo_launcher.ps1` | 村庄包、Super-Boss stage、本地资源补丁的启动前校验。 |
| 4 | `nanaimo_launcher.ps1` | 读取 INI、标题/角色/数值默认值、目录数据和 `-ValidateOnly` 分支。 |
| 5 | `nanaimo_launcher.ps1` | 构建 WinForms 页面、控件、预览和启动详情。 |
| 6 | `nanaimo_launcher.ps1` | `ShowDialog()` 进入 GUI 消息循环。 |

## 2. 固定的本地 Network 启动

当前 GUI 不显示连接方式、地址或相关提示，也不提供选择；启动详情保留文件／角色诊断，不展示连接参数。内部实现中：`Get-LaunchModeInfo` 只接受 `network` 与 `127.0.0.1`，`Get-SelectedLaunchModeInfo` 返回这一固定配置。`Install-LaunchModeConfig` 使用 `gui_launcher/launch_modes/gamestartoption.network.ini` 生成本地 `StateOption/gamestartoption.ini`。

| 当前配置 | ClientArgs | 本地适配器 | Profile 注册 |
|---|---|---|---|
| Network (`-q`) / `127.0.0.1` | `-q`, `:1:1:0:3:4:-i`, `5:-r`, `6:7:1:127.0.0.1:` | 进入游戏时保存并重启 | TCP 11999 |

客户端路径为根目录 `game.exe`。`scripts/verify_client_baseline.py` 检查其完整性与关键代码窗口，具体基线见 [运行配置与验证](../knowledge/authority/09-运行配置与验证.md)。

Stand_Alone构造器用于协议研究，不是当前GUI选项。模式之间的协议差异见 [登录村庄与角色](../knowledge/authority/02-登录村庄与角色.md)。

新配置默认用户名、装扮和宠物编号见根 README。已有 profile 保留；“恢复默认”主动载入新默认值，之后需保存。升级后必须关闭并重新打开启动器，旧窗口不会自动重载脚本。

## 4. 三个 GUI 动作的准确链路

### 保存配置

```text
saveBtn
  -> Save-Profile
     -> 拒绝在本地组件仍运行时直接改 inventory
     -> Encode-NameHex
     -> Get-ResourceSelection / Get-SkillSelection
     -> Save-InventoryAdminState
     -> 写 INI / JSON / 可选称号状态
```

### 启动/停止本地组件

```text
adapterBtn
  -> Get-LocalAdapters
  -> 若当前程序已运行：Stop-Process 后返回
  -> 若其他同名前缀程序运行：强制停止
  -> Save-Profile
  -> Test-AdapterBinary
  -> 删除上次 stdout/stderr 文件
  -> Start-Process nanaimo_adapter.exe
       args: 11005 0 0 0 <profile.ini>
       working directory: <OPEN_ROOT>
       hidden window + redirected logs
  -> 固定等待 1400 ms
  -> 仅检查进程是否提前退出
```

### 保存并进入游戏

```text
clientBtn
  -> Get-SelectedLaunchModeInfo
  -> 停止所有 Get-LocalAdapters 命中的进程
  -> Save-Profile
  -> Test-ClientBinary
       -> Village pack hash
       -> Super-Boss stage hash
       -> resource-patch hash
       -> client size/hash
  -> Install-LaunchModeConfig
  -> 固定重启本地组件
  -> Register-ClientProfile 到 127.0.0.1
       -> TCP <适配器地址>:11999
       -> u32 little-endian profile byte length
       -> 原始 INI bytes
       -> 要求适配器返回 ASCII "OK\n"
  -> 停止同路径的 game 旧进程
  -> Start-Process game.exe（固定 Network 参数）
```

## 9. 构建与发布文件

| 文件 | 作用 |
|---|---|
| `scripts/build_adapter.ps1` | 用使用者自行准备的 `tools/tcc/tcc.exe` 或 `-TccPath` 指定的 TCC，按 `source_closure.json` 的 `build_outputs` 重建标准与 testports 程序并校验大小／SHA-256；`-KeepOutputs` 保留到 `build/`，停服后需另行放入 `adapter/`。 |
| `scripts/verify_package.ps1` | 完整本地包结构和合成 profile 的 GUI `-ValidateOnly` 入口；不是 source-only 入口。 |
| `scripts/verify_package.py` | 敏感路径、关键文件和禁止内容校验；`--source-only` 不要求客户端、资源或适配器 EXE。 |
| `scripts/generate_package_index.py` | 生成本地资产索引，排除运行后生成的 profile/state/log；不是导出白名单。 |
| `manifest/open_release_manifest.json` | 运行环境关键文件记录，可由refresh脚本生成。 |
| `manifest/source_closure.json` | 89 文件源码闭包。 |
| `manifest/package_files.tsv` | 由generate_package_index.py生成的本地文件大小和SHA-256索引。 |

`scripts/verify_package.ps1` 仍固定使用自行准备的 `tools/python/python.exe`；协议主机测试仍固定使用 `tools/tcc/tcc.exe`。两者不会自动下载工具，也不继承 GUI 的 Python 回退规则或构建脚本的外部工具参数。仅安装系统 Python、或仅向构建命令传入 `-TccPath`，不足以满足这两个入口。

当前适配器构建契约为 `manifest/source_closure.json` 的 `build_outputs`；完整本地包另由 `manifest/open_release_manifest.json` 校验。运行配置与验证方法见 `knowledge/authority/09-运行配置与验证.md`。

## 11. 验证范围

- 当前代码已完成两次隔离编译并取得一致输出；发布构建脚本再次重编译并核对当前清单哈希。GUI 和包结构以最终校验命令结果为准。历史运行观察只适用于所记录的输入版本。
